## 目标与授权

用户要求启动面板默认加载AI；新增账号管理标签，支持增加和删除账号；全新房间提供kp、player1、player2，初始密码均为用户指定的12345678。新房间默认开放全部AI使用、读取与外发权限，KP助手可读取全部已授权资料。C类EXTENSION_FORBIDDEN及LIVE_SCENARIO_COVERAGE_MISSING改为提供评估与依据、由KP决定采用，并能动态调整C类判断依据。用户允许API调试，并要求扩充需求／提问测试例和统计。

“全部权限”涵盖服务与使用能力及读取／外发开关；自动批准属于决策策略，仍关闭以保留用户明确要求的KP最终裁决。既有房间不重置账号、密码或已有权限；默认初始化只作用于新房间。正式房间、现有账号和会话不用于实验。

## 分工与实现步骤

1. 包侧：启动默认勾选AI，账号标签使用本机宿主管理入口，显示实际账号／角色／状态；创建、改密、删除有结果和原因。新房间首次初始化使用默认账号密码；用户仍能主动设置自己的初始密码。
2. 引擎方：补齐本机账号删除与成员一致性、会话失效及幂等结果；必要时提供C类人工采纳的发布证明接口。现有数据中的历史归属保持可追溯，不把删除账号等同删除游戏记录。
3. AI方：新房间权限初始化、KP读取；区分可评估风险和机器无法执行错误；C类风险与依据形成可版本化评估，KP明确采用／拒绝，批准绑定评估版本与候选摘要。提供动态判断依据的受控配置与UI，不因修改判断依据自动批准或发布。
4. 联测：本机真实隔离房间、面板和浏览器验证；补充真实模型需求／提问、正常和失败修复案例；按格式、语义、预检、人工采用、实际生效分别统计。

## API实验与统计

本轮为2026-11-21新授权任务，独立账本关联前轮已封存199次记录，不覆盖旧账或借新账续跑旧预算。本轮初始硬上限80次外部尝试／650000 tokens，包含重试和未知用量保守预留；单并发，每例最多2次技术修复及2次传输重试。先做确定性回归，再用合成最小资料执行真实API；不记录凭据或上传真实玩家内容。

记录唯一caseId、自然请求、输入摘要、模型、首轮输出、修复次数、调用／tokens／耗时、格式与语义结果、实际执行副作用、阻塞和失败原因。正确拒绝与成功执行分别计数；模拟与真实API、直接探针与完整流程分开，保留首次失败。预算不足明确记录未覆盖项，不把未完成或复跑当成功。

## 实施结果

截至首轮联合验证，包侧已落地默认AI、账号标签和新房间初始化，并完成10组原生面板／真实隔离宿主检查。三个默认账号登录、账号创建／改密／删除、最后KP保护、原会话失效，以及重启保持新密码和手动关闭的权限均通过。首轮依赖引擎冻结v1，修复持久化格式和结果未知处理后以v3再次10/10通过，0次外部API。[记录](../../rulepacks/stumpsville/tests/panel-defaults-results.json)保留所有首次夹具失败与截图。

C类包侧界面5组、既有批次详情9组通过，前者覆盖风险依据与版本、三动作＋可选备注、采纳证明、拒绝与过期重检，属于合成DTO检查。[界面记录](../../rulepacks/stumpsville/tests/c-review-ui-results.json)不能代替实际发布证明。

真实C发布首轮发现房间持久化`models.json`的独立Approval格式未接入新证明字段，实际批准返回`INPUT_INVALID`；v3修复后，两个指定C风险均经实际批准／发布及消费通过：作者允许的角色模板默认hp/maxHp变更因NPC探针未覆盖而明确列为C范围风险，Edge点击采纳后新实例数值为5；短休规则缺少实况场景覆盖时由KP采纳后发布，实际规则消费成功。未把C未知改写为检测通过，也未放宽A/B。批准后改变依据仍以`C_BASIS_STALE`拒绝旧批准。

AI关闭后的依据读取器专项已修复并通过；引擎独立验证160个唯一用例全部通过（54项新增、106项受影响回归，无跳过）。包侧以引擎v3＋AI v2组合完成真实嵌入和网页导出6/6，1440／390px、403恢复、原会话重载、调试导出及模块装配无未捕获错误。

### 真实模型统计与边界

本轮封存43次外部调用／597278已知tokens，无未知用量；不再发起调用。原生产链路为16个唯一案例，15例取得终结输出，1例实质歧义需求在首个工具调用后因保守预算预留被阻断，未完成，不计为成功。

| 口径 | 结果 | 判定边界 |
| --- | --- | --- |
| 首轮完整案例通过 | 7/16，43.75% | 同时计入引擎集成失败、过严判定、模型失败和预算未完成，原记录保留 |
| 完整链路终结输出 | 15/16，93.75% | 1例预算阻断，不计模型成功或正确澄清 |
| 已终结输出格式 | 15/15，100% | 仅表示可解析，不能代替意图或执行 |
| 原语义判定 | 13/15，86.67% | 原记录原样保留 |
| 语义复核 | 14/15，93.33% | 短休参数被实际规则忽略，依据源码与执行修正过严判定；未取证否定回答仍是首轮失败 |
| 正确拒绝 | 2/2 | 与修改执行成功分开 |
| 首轮修改实际生效 | 2/9，22.22% | 6例引擎Approval持久化失败、1例测试判定过严 |
| 修复后原输出重放 | 9/9，100% | 3运行时＋6配置，零额外API、实际生效且幂等；不是重新生成首次成功率 |

对“未查询就回答没有记录”的错误增加有界证据反馈，生产替身回归通过。另用3次真实调用的短反馈实验验证搜索→读取→正确暗号；这属于针对性实验，不计完整生产提示复测。答案仍多附来源文字，不宣称“只回答暗号”的严格输出要求已达标。预算阻断案例、完整提示下修复泛化和严格简短输出仍属后续验证范围。

本轮为固定需求用例，不是随机样本，以上比例不能外推生产总体成功率。AI完整核心回归648/648通过，生命周期／证据反馈／组件专项38/38通过；这些专项可与核心回归重叠，不机械相加。包侧不修改正式房间、账号或服务商配置。
