## 需求与已核查事实

用户要求参考 DeepSeek 官方文档或社区资料，优先引入官方推荐的上下文压缩机制，改善长对话中动态配置需求的完成率；此前已允许 API 调试、统计全部试验结果及与 AI 模块责任者协作。

现有 ISSUE-023 已提供语义摘要、原文归档和受限回读。核查冻结版本 v3 后发现：压缩触发仍以固定字节阈值为主；历史对话固定保留两项；没有先裁剪超长历史工具输出；多次压缩可累积摘要消息；服务商 HTTP 400/422 没有区分明确的上下文溢出。以上是本轮改进对象，不把现有功能描述为尚未实现。

官方 Harness 是 TypeScript 插件体系，依赖其会话存储、计量及模型路由。本项目采用 Python，计划独立适配相关机制，保留现有工具契约和权限校验；不宣称直接安装或完整复刻官方组件。如工程实现引用源码，须同步检查许可证与保留必要声明。

## 实施范围与分工

| 工作 | 实现方 | 约束 |
| --- | --- | --- |
| 模型容量、应用上限与近期对话保留预算 | AI 模块 | 不将估计字节数显示成精确 token；不取消宿主请求上限 |
| 历史工具输出先裁剪、再摘要 | AI 模块 | 不破坏调用/回执配对；受保护结构、当前需求和权限依据保持可用 |
| 单一滚动摘要与原文定位 | AI 模块 | 摘要不可变成授权或执行事实；确认、否定、修正可回读 |
| 明确上下文溢出的有界压缩重试 | AI 模块 | 普通请求错误及输出截断不触发该重试；保持用量记账 |
| 官方机制对照、问题/索引和包侧联合核查 | 配置包会话 | 不代改工程代码或工程能力正文 |
| 新版冻结证据及真实 API 配对试验 | AI 模块，配置包复核 | 独立目录，不修改 ISSUE-023 已封存数据或正式存档 |

## 实施步骤与待核定细节

1. 工程责任者核对官方机制与现有工具循环，确定可安全压缩的历史片段；登记实际修改范围。
2. 实现预算、裁剪、滚动摘要与错误分类，补充必要的确定性回归。
3. 使用同一合成历史分别运行既有 v3 与新版本，覆盖最新参数、撤销、提议与确认区别，以及动态配置候选生成和验证。初始实验规模约 20—30 次调用或 50 万 token；需扩展时记录原因。
4. 统计全部尝试与失败，分别报告压缩成功、业务结果正确、执行/验证通过，保留延迟及调用用量。不以“最终某次成功”替代整体成功率。
5. 冻结源码与证据，联合验证并同步当前文档；验收后归档本问题。

待核定：近期保留预算的具体值、可裁剪的结构化工具结果范围、服务商溢出错误的可靠识别。本轮优先自动机制，手动 `/compact` UI 不作为既定范围。

2026-11-21 责任者确认：滚动摘要限定同一生成任务中的多次工具循环，使用旧检查点与新片段生成一个替代检查点。跨用户轮次仍受既有历史捕获上限约束；只复用完全匹配且重新授权的摘要缓存，不宣称已实现跨任务的完整检查点或无限历史。计量继续保守估算 UTF-8 字节，报告时与实际 token 用量分开。实验初始硬限为 30 次外部尝试、50 万 token。

配对实验的主要判据如下，具体真实请求以工程验收记录为准：

| 场景 | 业务判据 | 不能算通过的情况 |
| --- | --- | --- |
| 助手建议 HP3、用户同意、插入背景、再要求加1 | 关联到原方案并按最终 HP4 生成可校验候选 | 仅复述“按原方案”，或回到3、改成其他数值 |
| 历史方案包含未批准值、用户明确否定／撤销 | 不把旧提议或否定句压缩为已确认要求 | JSON合法但恢复了撤销内容 |
| 同一需求替换目标 | 使用最终目标并保留仍有效参数 | 修改原目标，或不必要地再次确认已明确选择 |
| 大工具结果＋必要修改引用 | 降低输入且保留可用引用，最终候选可通过检查 | 字节减少但破坏工具配对、丢失编辑引用或伪造执行成功 |

摘要调用、业务调用分别统计耗时和用量；同时报告所有尝试和最终成功请求，避免重复重试掩盖失败率。

## 验收条件

- 低压力会话不触发无谓摘要或裁剪；大工具输出可先确定性缩减，重复处理结果稳定。
- 多轮压缩不无限叠加摘要；工具调用与回执保持完整关联；系统契约、当前需求和必要权限依据不丢失。
- 最新数值、否定及撤销不被旧摘要覆盖；助手提议不会变成人工确认；原文与引用可追溯。
- 明确上下文溢出最多一次恢复重试；普通 HTTP 400/422、认证/限流及输出长度截断不能误触发。
- 小窗口、应用请求上限与不可压缩材料有明确可解释的结果；不为了表面成功静默丢弃内容。
- 真实 API 记录基线与新版相同场景的所有调用、摘要次数、用量、耗时和业务正确性；如结果不能证明改善，明确记录限制并继续修正关键问题。
- PL 可见情报边界、KP 审批和技术有效性校验不退化；既有业务与压缩针对性回归通过。

## 当前进展

2026-11-21：官方机制适配首版已冻结，AI针对性回归79/79通过。包侧独立核对219项AI与327项宿主冻结文件哈希，资料权限4项、组件嵌入6项、原子批次5项、来源采纳与发布4项均通过，见[独立验收](../../rulepacks/stumpsville/tests/official-compaction-results.json)。这些采用隔离宿主和模拟模型，不计入真实API成功率。独立审查发现并交回修正一处裁剪后字节诊断计量时点；真实模型配对与扩大回归仍在进行。

真实模型首轮发现业务回归：基线3/3通过，适配v1首例将“原建议HP3、用户同意、再加1”生成并在隔离审批后发布为HP5。模板当前值4被误当成用户接受的原建议；关键短确认已被压入摘要，保留预算被较新的长背景占用。随后调整预算内短需求原文的优先级，保留原次序与建议关联后重新验证。首轮失败继续计入本轮统计，不能由接口测试通过掩盖。

随后v2同样三例实模全部通过；责任者封存本轮23次调用、413419 token，其中基线10次／181889、失败v1为4次／74530、v2为9次／157000。v2一次摘要格式失败后自动修复成功，不算零纠错；不得把最终3/3替代保留首失败的适配总样本3/4。v2包侧来源采纳与发布4项复验通过。

独立检查又发现v2会无条件保留超大末条历史：2048字节保留预算被18011字节背景占用，65字节短确认未保留。v3删除该例外；包侧复核2048预算下保留65字节确认，零预算不强留历史，未选行仍进入原文可回读摘要。v3相比v2仅此辅助函数及两条测试改变；责任者报告最终四文件定向回归100/100通过，三项实模输入不受此差异分支影响，未重复外部调用。最终全量回归与独立证据核验已完成，结果见下节。
