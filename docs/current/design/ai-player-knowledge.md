## 1. 目标与适用范围

用户要求：PL 的 AI 辅助提供信息必须完全基于该玩家已知的信息，不得透露未知信息。本设计将该目标转为可检查的读取、引用和输出约束，重点明确“固定观察版本”和“严格模式提供方故障”两项规则。本设计已于 2026-11-17 按 A0—A3 落地；已验证能力和限制以[工程说明](../engineering/ai-player-knowledge.md)为准。角色级隔离、二进制资料和自由事实生成仍不属于首版。

AI 模块维护本文的消费、引用与输出规则；引擎负责权威记录、策略注册、授权投影和跨入口执行；配置包决定具体玩法中的进入、观察、揭示与分享条件。引擎接口名称、持久化 Schema 和出口矩阵由工程设计统一，不在本文另立一份。模型不能新增知识授权，KP 的实际身份不能提高玩家会话的数据上限。

严格 PL 模式不以“模型没有说出秘密”证明隔离成功：外发 payload 必须无未知数据，最终显示内容也必须有可复验依据。通用模型可能自带原版模组知识，因此首版采用第 7 节的受约束回答；仅添加提示词、引用或另一个模型审查，均不满足这项要求。这里保证系统供给和展示的信息边界，不声称能抹去人或服务商已经接收的内容。

## 2. 什么算本人已知

一次可用于回答的资料，必须同时满足：当前房间／包与会话主体匹配、有宿主认可的披露依据、分面和内容版本确定、当前仍有有效读取授权、允许用于本次 AI 外发。`public`、KP 可见、账号拥有其他角色、模型知道原作，均不能单独替代这些条件。

“已知”按服务器已向该主体完成的披露记录判定，不依赖模型推测，也不要求证明玩家眼睛看过每个字。首版采用账号主体并在 UI 明示；不声称隔离同账号多个角色的知识。需要角色隔离的包必须等对应能力就绪，不能自动合并成账号知识。

| 来源 | 可使用内容 | 不随之获得的权限 |
| --- | --- | --- |
| 进入／观察 | 可信行动完成后，由包规则选出的当时可见分面 | 不开放整个场景、全部线索、NPC 属性或未来变化 |
| KP 定向揭示 | 指定受众、分面和内容版本的披露；全员揭示也需明确的受众规则 | 发布草稿不等于揭示；不能替别人读取私聊原文 |
| 明确的共同知识 | 入房时向本人披露的玩家规则、说明及其他白名单资料 | 不开放整个包清单、主持指南、源码或隐藏示例 |
| 聊天／分享 | 本人获准接收的消息窗口或独立摘录，保留“参与者陈述”类型 | 传闻不自动成为剧情事实；一条线索不开放原场景／原频道 |
| 玩家输入 | 仅作为本人的陈述或待回答问题，可按原话整理 | “我知道地点 X”不生成知识记录；提问中的假设不被系统验证为真 |
| AI 旧回答／摘要 | 仅复用仍可验证的原证据及绑定主体 | 不能把模型曾经说过的内容当作新的事实来源 |

聊天的知识边界需要受众及序列窗口；当前频道成员身份不能自动证明此前全部历史都已向本人披露。未接入这些证据的聊天来源暂不进入严格 PL 上下文。用户本人新提交的内容可被标为陈述，但不能借此引导 AI 从原版知识补完故事。

## 3. 固定观察与持续披露

### 3.1 默认固定观察

场景、人物外观、物件描述、调查线索等采用 `observed_revision`：保存当次允许披露的最小内容快照或等价的不可变引用。名称、标签、图片版本、单位和关系说明也属于内容；不能只冻结正文，随后从当前实体补标签。

1. 由可信进入／观察／揭示结果产生记录，不能按客户端自报的位置或聊天文字记录。
2. 同一事件重试沿用幂等回执；新观察形成新记录，不覆盖旧记录的内容。
3. 原实体、模板或 `published` 更新，不改写旧观察，也不自动让玩家获知更新。
4. 再次进入只取得此次规则实际允许看到的分面；隐藏线索仍需单独发现。返回回答标明“上次观察时”，不能把旧记录当成现场状态。
5. 多次观察可以并存；相同分面有较新观察时默认展示最新的已知观察，明确查询过去时可读仍有授权的旧观察。差异仅在两份都获准读取时计算。
6. 快照遗失、损坏或不受支持时，该记录不可读取；不得以最新内容、模型记忆或缓存中的未经复验文本补齐。

不要求先实现完整世界历史数据库：首版可只保存体积受限的披露分面。支持固定观察是严格 PL 场景资料的发布条件；若引擎首期未支持，则相关资料保持不可用，不以持续读取替代。

### 3.2 live_scope 仅用于明确的持续披露

`live_scope` 表示包规则或 KP 明确将指定分面的后续获准更新持续披露给该主体。它不能从“曾进入过”推导，也不是读取任意最新字段的许可。

| 场景 | 默认处理 |
| --- | --- |
| 本人角色状态、明确持续公开的玩家规则 | 可注册持续披露；每次更新仍按既定受众和字段白名单投影 |
| 当前场景 | 首版不做基于当前位置的 live 订阅；重新进入、包侧可信观察行动或 KP 揭示生成新快照 |
| 已离开的场景、旧线索、秘密 NPC 的内部状态 | 不授予持续读取；保留最后一次有效观察 |
| 新增分面／新增字段／扩大受众 | 属于新授权，不能借原 live_scope 自动生效 |

结束持续披露时，停止获取以后更新。需要保留的最后已披露内容转为固定观察，并使用明确的保留授权；不具备这一能力时不得启用需要保留经历的持续来源。停止更新与撤回历史读取是不同操作，离开场景默认不撤回已经获得的观察。场景内自动持续观察作为后续扩展，首版不以位置订阅暗中持续同步。

例：PL 在庭院看到“空长椅”，离开后 KP 添加守卫。PL AI 仍只能说“上次观察时长椅无人”，不能回答现在有守卫或暗示“有新变化”。再次进入并看见守卫，或 KP 向该玩家揭示后，才能引用新观察。

### 3.3 内容变化与授权变化分别处理

| 事件 | 固定观察 | 持续披露 | 引用／缓存／回答处理 |
| --- | --- | --- | --- |
| 原资料发布新版 | 旧观察内容仍有效 | 只有获准分面按持续披露规则更新 | 更新 live 内容版本及缓存；不全局废弃固定观察 |
| 无关人物移动、未披露秘密变化 | 无影响 | 无关分面无影响 | 不应改变本次已知资料结果或打断只读回答 |
| 一条授权撤回，仍有覆盖同一版本／分面的有效授权 | 仍可读原内容 | 依剩余授权处理 | 重新授权并更新证据，不机械删除全部知识 |
| 所有相关授权撤回／主体控制关系失效 | 不再读取或用于历史 | 停止读取及更新 | 隐藏依赖内容，停止外发、重建摘要；不宣称抹去人的记忆 |
| 仅停止后续观察 | 保留已有观察 | 结束持续来源，按规则保留末次观察 | 不读取新的现场状态 |
| 最新原对象删除，但授权快照仍完整且允许保留 | 可继续读历史观察 | 停止获取当前内容 | 不通过错误提示向玩家透露对象的未知删除状态 |
| 快照不可用／内容摘要不符 | 不可用 | 不用其他版本补齐 | 返回通用不可用提示，KP 可查看详细诊断 |

替代授权必须覆盖原引用所指的同一内容，不能因另有“当前版本”授权就偷偷替换过去的引用。内容修订负责新鲜度，授权修订负责访问资格，两者不能共用一个模糊的 revision。

KP 修正误披露时，显式撤回受影响授权并按需发布新的纠正记录；只编辑当前实体不能假定旧快照已经失效。纠正提示本身也要按受众裁剪，不以“已删去某秘密”暴露秘密内容。

有效固定观察默认不因自动缓存清理而消失；缓存与权威快照分开保存。快照容量达到上限时，新披露应在提交前明确失败，不能先发授权再丢内容。首版不自动淘汰仍被有效知识或会话引用的快照；显式删除／保留策略和容量阈值在引擎 K0 确认，删除前说明受影响引用。

## 4. 引用、二级面板与历史

严格引用指向“该主体获知的某个分面／版本”，不直接指向可任意展开的完整实体。服务端引用绑定至少包含房间及恢复代际、包／策略版本、主体、知识记录、分面、版本模式、内容版本／摘要；另保存本次有效授权与提供方契约的复验证据。以上是语义要求，正式字段名和编码由引擎契约冻结。前端及模型使用不透明句柄，不能传账号参数切换视角；句柄不是离线授权凭证。

- 展示标签来自同一获准快照。点击二级面板仍显示该观察的获准字段与可展示来源，不读取当前实体名称、隐藏字段、完整模板或原始私聊。
- 旧观察面板可以显示“观察记录”，不能因后台存在新版而显示“已过期／已有新版本”来暗示未知变化。只有确有本人可读的新观察时才提供版本切换。
- 搜索、补全、引用解析、面板和历史复用走同一授权接入层。复制其他玩家的句柄不能读取；跨房间／恢复代际不能复用。可见的来源说明也必须先授权。
- 空结果不证明游戏中不存在该对象；未知对象与不存在对象使用相同的用户级反馈，不泄漏名称、字段、总数或他人发现过程。
- 授权变化时客户端清空失效详情和引用缓存；已经显示的内容无法追溯收回。旧回答重新打开时检查依赖，失效部分显示占位，不向 PL 返回包含秘密的原文；KP 审计保留按独立管理权限读取。
- 旧文本引用 `[[entity:…@revision]]` 只有在能够唯一证明主体、分面及实际内容版本时才映射；否则提示重新选择。不得解析为“当前最新版”作为兼容降级。

用户历史中的系统引用与展开资料也必须复验。未经系统引用支持的原话仅是参与者陈述；不会以过去某轮曾出现过为由恢复被撤回资料。切换主体必须使用新会话，首版不提供原地合并历史。

## 5. 严格模式的持久声明与故障规则

### 5.1 声明独立于提供方进程

宿主保存受信的个人知识要求，按包及资源类别／分面注册：是否必须使用个人知识、主体类型、允许版本模式、提供方与契约版本、策略修订及相关出口覆盖情况。声明属于房间／包绑定的持久配置，不能只存在于 adapter 实例或 AI 面板临时开关中。删除适配器、停用 AI、重启、读取备份或加载失败都不会删除要求。

提供方的“已注册、已加载、健康、契约匹配、可复验”是不同条件。身份、授权、来源和出口都核验通过后才能使该资源就绪；插件自行报告 ready 不能替代宿主核验。尚未建立要求记录，不能被解释为“没有限制”。

新设计下 PL 的游戏资料回答统一要求严格模式。旧包的普通游戏入口可以继续沿用旧可见性，但未登记能力／未完成知识接入时，PL AI 不得回退到 public／owner 查询。允许建立待就绪会话、显示固定说明和保留本地输入；不向模型发送未通过检查的游戏资料，也不显示历史缓存答案冒充已知结果。KP 管理员会话保留独立权限，KP 创建的玩家会话仍执行本规则。

取消严格策略、扩大分面或更换主体不是普通设置降级。必须经受信管理流程校验并更新策略修订；失去严格保证时停用相应 PL 资料能力，不能一边改回通用可见性，一边继续标为玩家已知助手。模型不能提出并自动执行绕过此限制的动作。

### 5.2 故障与恢复矩阵

| 条件 | 严格 PL 行为 | 恢复要求 |
| --- | --- | --- |
| 未声明、缺少主体／版本能力 | 相关游戏资料不可用，不调用替代原始读取 | 完成能力注册并核验；不静默改主体或版本模式 |
| 提供方缺失、加载失败、超时或断线 | 停止相关读取、生成及旧缓存答案展示 | 恢复后重新验证当前授权、主体和内容；不直接续用旧结果 |
| 契约／策略不兼容、声明损坏 | 保持严格要求，阻止相关资料 | 受信修复；不得把异常视为未配置 |
| 普通视图、订阅、引用等相关出口尚不能执行策略 | 禁止该出口读取严格资源；该资源不通过完整隔离验收 | 关闭未适配出口或完成统一投影；客户端隐藏无效 |
| 一个可独立隔离的资料源失败 | 仅可继续使用已独立核验的其他来源 | 依赖失效来源的整段回答／摘要不可复用；全局授权服务失效则全部停止 |
| 重启、恢复备份、重新绑定包 | 未核验期间不可用；旧代际句柄及任务失效 | 恢复持久策略后再加载提供方、复验并重新签发本代际引用 |

故障不能返回“该隐藏地点的知识服务失效”等含对象存在信息的提示。玩家仅看到“暂时无法核验可读资料，请稍后重试”；详细原因、提供方名称和内部路径留在 KP／运维诊断。未就绪时禁止通过备用服务商、旧摘要、直接读文件或通用实体查询绕过。更换 AI 模型不改变知识边界。

缓存本身不能证明权限仍有效。只有宿主还能以本地权威记录核验授权，且缓存内容、模式及来源版本完全匹配时，缓存才可作为正常读取实现；它不是外部授权服务断线后的兜底。无法确认有无撤权即停止。

## 6. 上下文、复验和并发边界

只读回答的有效性依据实际依赖的知识、授权和提供方契约；不复用配置发布的全房间 `worldDigest` 作为持续有效条件。配置与运行时写入仍执行原有基线／权限／裁决检查，不能因为只读规则变细而减弱写入校验。

所有外发通道都受此约束，包括首次 payload、工具结果、格式修复重试、手选引用、指南／包契约、会话历史和摘要。PL 指南只含已批准的一般使用说明；包契约采用玩家字段白名单，不能把整个主持契约交给模型后只过滤 sources。

首版不向 PL 透传模型流式原文；先完成结构、证据和授权检查，再交付服务端生成的回答。以后若逐块展示，每块同样需要交付检查，不能先显示秘密再靠最终过滤撤回。

缓存键及证据必须区分主体、房间恢复代际、包／策略、提供方契约、外发策略、分面及内容版本；授权变化触发复验。查询分页针对同一授权结果快照；live 内容变更使该查询游标失效或重新开始，不拼接两个时刻的结果。未披露对象变化不应影响玩家页的条数、文案或有效性。

摘要保留完整依赖集合；失效后整体停止外发，再用仍获准内容重建，不能只删除原始引用。首版可以不提供生成式摘要，不能以缺少摘要存储结构为由直接复用无证据的文本。

外发与展示各有授权检查点：每次向模型提交前取得针对实际 payload 的发送许可；最终回答及详情返回前验证对应证据。撤权提交与发送／交付许可有明确的宿主排序，先撤权则不再批准发送／展示。已先获准并进入传输的请求可能仍被服务商收到；无法承诺撤回在途字节。撤权后尽力取消任务，不再进行后续工具／修复外发，且结果不能通过最终展示检查。网络请求期间不长期持有全房间锁。

客户端按授权变化通知关闭旧详情，重连先刷新资格再恢复内容。浏览器已收到、截图或复制的资料不可撤销。撤回后的请求不得读取旧内容；发送／交付检查点之前已经完成的读取按当时授权审计。

## 7. 严格 PL 回答与选项

首版使用“模型选取已知证据，服务端核验和排版”的回答链。模型返回受限结构：选择哪些授权证据片段、采用哪个已注册的中性标题／说明模板、有哪些允许的下一步操作。正文事实、语义标签、数值和可引用摘录由服务端从通过复验的内容生成；模型自由文本不直接作为游戏信息展示。

| 输出 | 首版规则 |
| --- | --- |
| 事实／规则／观察摘录 | 必须指向本主体已知的精确片段；按原证据标明观察、规则或参与者陈述 |
| 汇总与计算 | 只允许登记的确定性操作和获准输入；结果带依据，不能扩大为全房间结论 |
| 选项／确认按钮 | 由受信动作目录及已知资源构造；模型只选动作和证据句柄，不能自写秘密对象标签 |
| 用户原话整理 | 可以引用本人提交的陈述，明确未被游戏事实证实；不能据此扩大查询权限 |
| 缺资料／不可用 | 使用固定且不确认隐藏对象存在的短提示；缺资料不等于对象不存在 |
| 新剧情事实、自由推理、模组背景补全、故事扩写 | 严格 PL 首版不直接展示；如另设自由创作模式，须独立评审，不得宣称满足本设计 |

个人目录和详情均受同一主体授权。生成可先加载个人目录，再读取相关详情；字面关键词无匹配时可明确回退同一主体的目录，不能升级为世界检索。空匹配与服务／外发／策略阻断须使用不同提示，不能把前者统称为权限不足。

仅给自由文本附上一个有效引用，不代表其中所有断言都有依据。首版不依赖模型自行判断“这句话没有剧透”，也不自动把 PL 请求中猜测的秘密送入全房间检索再返回是／否。模型提出没有授权依据的输出时，按既有格式修复机制要求改为合法结构；达到限制后返回固定失败提示，不展示最后一份原始回答。

证据选择不作为真相、嫌疑或重要性评分。默认按固定的类别／观察时间排版，不让模型依据原作给已知对象加上“真正凶手”“关键线索”等因果标签；需要判断的内容由玩家或 KP 决定。可信模板也必须保持中性，不把一个有效证据拼成它并未支持的断言。

回答尽量使用简短证据卡／短列表；“申请 KP 揭示”只引用用户已提到或本人已知的对象，不能自动列出未知地点供选择。请求本身不赋予知识；获批后以正式披露记录产生新证据，再重新查询。审查者可见秘密时，审查过程本身也不能写入玩家会话。

PL 可主动提交创作／配置需求，严格玩家会话本身仍只能选取本人已知证据，不能生成可执行批次或自由草稿。2026-11-19 的独立申请通路将原需求送到 KP 队列：KP 明确接收后，在 KP 名下另建私有管理员审核会话，按 KP 的授权资料准备方案；该会话和产物不回流 PL。申请状态仅表示是否接收，不代表批准修改。此来源的批次和配置均需另行人工裁决，不适用普通自动批准。批准加载也不自动揭示模板、草稿或剧情；分享结果仍须正常披露。接口与验收见[玩家创作申请](../engineering/ai-session-access.md#玩家创作与配置申请)。

## 8. Stumpsville 接入与发布条件

旧 `locationKnowledge` 只记录“旧包曾认为已知”，没有当时正文，不能转换为伪造的历史观察。保持旧档不变，升级严格模式时由 KP 明确选择向哪些账号、按哪些分面作一次“现在揭示”，记录真实的新时间；未确认的旧条目在严格查询中不可用。不能批量把全部已发布场景当成补录范围。

进入地点创建所见分面；包侧单条发现和定向揭示分别建记录。由当前位置自动推导知识的旧查询逻辑需改为可信动作／初始化披露流程，AI 读取本身不新增观察。已建但缺乏完整证据的旧会话回答不自动转为新模式历史；提示重新查询，保留 KP 审计。

2026-11-17 与“工程bro 1号”确认设计分工：工程首版纳入账号主体、小型分面不可变快照、持久严格策略、统一读取及只读／执行校验分离；live_scope 限于明确持续告知的本人状态／指定公共规则，首版不做场景 proximity 订阅。引擎设计／施工文档由工程责任者维护，本文负责 AI 消费与输出。上述首版边界已实现；任何未实现分面仍须保持关闭。

## 9. 验收与设计待定项

使用隔离双玩家、确定性模型和可检查外发 payload 的测试；真实模型另测越权输出尝试是否被输出门禁挡住，不以真实模型碰巧没有说出秘密为成功。

| 编号 | 必测情况 | 通过标准 |
| --- | --- | --- |
| D01 | 已发布但未进入／未揭示 | 首次上下文、搜索、补全、正文、选项和详情均无未知内容 |
| D02 | 进入后离开，KP 改名／添加 NPC／更新描述 | 只显示原观察；标签、图片和详情也不带新内容，不提示未知更新存在 |
| D03 | 再次进入仅看见部分内容 | 新记录只增加允许分面；旧记录仍可按授权追溯 |
| D04 | 本人状态等 live 更新与结束持续披露 | 只更新白名单；结束后停止新增信息，按保留授权处理末次内容；场景不能注册首版不支持的 live 订阅 |
| D05 | 同一内容有两条授权，依次撤回 | 撤一条仍可复验读取；撤完后引用、历史、摘要及缓存停止供给 |
| D06 | 原实体删除／固定快照损坏 | 保留快照按授权可读；快照损坏不补成当前或模型生成内容 |
| D07 | 复制他人／其他房间／备份前句柄 | 拒绝读取，不暴露实际标签和对象存在性 |
| D08 | 移除提供方并重启；契约不兼容 | 严格声明仍在，不触发 visible 回退，不展示未经复验的旧答案 |
| D09 | /view、订阅、关系、回执、资源／导出旁路 | 按工程出口矩阵全部过滤或关闭；公共占位只含明确获准字段 |
| D10 | 在发送许可前／在途／展示许可前撤权 | 分别阻止新外发、丢弃失效响应；无后续重试泄漏，审计标明边界 |
| D11 | 只改另一玩家秘密或无关实体 | 本人可读结果和只读回答有效性不变；修改执行仍执行写入基线校验 |
| D12 | 账号多角色、KP 代执行、角色类型不支持 | 不冒充角色隔离；不借 KP 或其他角色扩大主体范围 |
| D13 | 模型凭原版知识输出秘密、有效引用旁夹带秘密 | 自由文本不进入显示；无法构造成合法证据块时只显示固定提示 |
| D14 | 玩家猜测秘密／分享一段私聊 | 只作本人陈述或获准摘录，不确认猜测，不开放原对象／私聊 |
| D15 | 旧档、旧回答及没有版本的引用 | 不伪造旧观察，不按最新资料补齐；新揭示时间和受众可审计 |
| D16 | 内容更新但授权不变；批量引用及缓存命中 | live 缓存按内容失效，固定快照不误失效；复验量和延迟有基线 |

A0—A3 的版本／撤回语义、消费端、输出结构、嵌入交互及包试点已分别验收，见[工程验收](../engineering/ai-player-knowledge.md)。D01—D16 继续作为后续变更的回归边界。

工程侧已形成[首版设计基线](../engineering/player-knowledge.md)：小型快照容量／保留、二进制暂不支持、发送资格排序、引用DTO和错误码均有明确约束；K0—K5 的机器契约、实现与验收由工程侧维护。未支持资料类型拒绝读取，不放宽“本人已知”的边界。是否扩展自由推理体验另作产品评审，首版不默认开启。
