基于本仓库 `rulepacks/stumpsville/`（树桩镇，manifest 版本 `0.9.0`）源码核查。下文路径除链接外均相对该包；KP 为主持，PL 为玩家。只概括当前实现，游戏资料中标注“待终校”的内容仍不是已核实的原版规则。

| 类型 / 承载对象 | 触发条件 | 内容 | 接收对象与保留方式 |
| --- | --- | --- | --- |
| 操作提示 `#toast` | 提交、排队、复制、保存或请求出错 | 简短进度、结果或错误 | 当前操作页面；3秒后淡出，新提示替换旧提示 |
| 检定小窗 `.dice-popup` | 新终态事件含检定、豁免或骰子明细，且动画开启 | 已提交骰点、目标、成败；不在前端重掷 | 事件 `account` 对应账号（含KP自己的事件）；约0.8秒动画，结果显示3秒后淡出 |
| 结果/影响 `.effects-popup` | PL 收到新的非 `pending/processing` 事件，或本人授权角色快照发生未被事件覆盖的变化 | 结果、叙述、HP/属性/钱币/物品等前后值；拒绝/未完成结果也可显示 | 本人PL；即使无数值变化仍显示新事件结果；逐条排队，3秒后淡出 |
| 新线索（同一影响窗） | 新结果携带线索，或 KP 定向揭示后个人地点快照新增线索 | 标题、正文、查看线索入口 | 获得知识的PL；与同次行动结果合并，按地点+线索ID去重 |
| 未完成原因 | 条件校验或裁决执行失败 | `reason`、`nextStep`、`actionId` | 操作者及相关申请者；表单错误区、日志/裁决详情保留，不只依赖短提示 |
| 行动日志 / 未读徽标 | 提交、自动完成、KP回复、本人资源变化 | 状态、原因、结果、变化、时间、回执及复核入口 | PL仅本人，KP可看各账号事件；服务端每账号最多200条，界面投影最多200条 |
| KP 待办徽标 / 队列卡 | 建角提交、人工裁决申请、宿主流程等待/异常、AI待办 | 数量、时间、来源、内容概要和动作；详情浮窗保留全文 | KP；待办处理后更新，保留相应历史/回执 |
| 聊天消息 / 未读徽标 | 有权访问的频道收到他人未撤回消息 | 发言者、时间、文本/结果卡、未读数 | 场景：当前位置玩家及KP；队伍：已有角色玩家及KP；全局/私聊依宿主成员权限 |
| 房间/探索通知 | 开场、回合、自动裁决开关、暂停/恢复、地点发布 | 公共状态摘要 | 调用者及已有角色的账号；发布通知不附带未授权地点正文 |
| 连接/恢复提示 | 连接异常，或提交后未确认结果 | 连接状态、未确认命令、恢复入口 | 当前页面；保留原命令ID，恢复时查回执，避免重复执行 |

首次进入账号/存档范围时，骰子和影响窗以当前历史建立基线，不重播旧消息。影响窗等待骰子窗及模态表单结束；后续轮询和排队消息不延长当前提示的3秒寿命。减少动画时省略/缩短动画。源码：[dice.js](../../../../rulepacks/stumpsville/ui/dice.js)、[effects.js](../../../../rulepacks/stumpsville/ui/effects.js)、[action_errors.py](../../../../rulepacks/stumpsville/tools/action_errors.py)。

事件由 [package.py](../../../../rulepacks/stumpsville/tools/package.py) 的 `record_feedback` 分发：调用者、角色数据变化的拥有者、申请者分别收到自己的投影。核心字段为 `id/account/operation/title/status/mode/result/changes/time/requestId/receiptId`；不能把 KP 原始结果复制给所有玩家。聊天权限由 [chat.py](../../../../rulepacks/stumpsville/tools/chat.py) 与宿主共同检查。

裁决操作见[界面与层级](stumpsville-interface.md)：结构化请求可直接执行，自由请求可选择受限动作，回复区默认折叠；AI信息待办通过定向揭示表单执行。玩家创作申请由 KP 接收后进入私有审核会话，PL 仅见接收／拒绝状态；生成的修改另行批准，原申请不重复占据待办。通知本身不触发游戏写入。
