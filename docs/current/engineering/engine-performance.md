## 执行与静态装载

`worker_process.execute_request` 在进程内共享两个槽位的受限 Python worker 池，按需创建。每次任务仍构造全新的 LuaRuntime、Execution、规则定义和随机问答通道；请求携带完整规则源码，因此新版本不会读到旧闭包。Windows Job、512 MiB 进程限制、32 MiB Lua 限制、8 MiB IPC 限制和期限继续生效。成功进程达到 64 次或 90 秒即退休；超时、协议错误、业务执行错误和内存故障均销毁进程。首次调用、故障替换及退休替换仍有冷启动开销，没有后台预热保证。程序退出清理空闲池。

返回的内部诊断新增 `workerAcquireMs`、`workerReused` 和 `workerTimings`，分别区分槽位/创建、导入、Lua 装载、执行和任务处理。`workerMs` 保持原含义。随机结果仍在交回 Lua 前由宿主持久记录；T1/T2、同 ID 回执及 pending 恢复不变。

`registry.stage` 只缓存成功的静态产物，键覆盖完整 sources/data 和静态校验/worker 策略版本，返回独立副本，最多 16 项／8 MiB 产物字节。不缓存当前世界、来源证明、权限、C 依据或发布批准；配置引用、世界图、CAS 和发布指纹继续执行。更换代码后须重启服务；规则/数据热发布本身改变内容键。

未采用跨任务 Lua VM 或编译闭包复用：本机分段样例的冷导入约 496 ms，Lua 装载约 0.8–0.9 ms，保留逐任务解释器的隔离成本较小。

## 知识投影缓存契约

宿主缓存键绑定房间 generation、账号、提供者注册版本和所有政策的来源令牌，最多 128 个键，返回深拷贝。所有房间提交（包括撤权、改角色、所有者变化和激活规则）清空旧代缓存。

受信 Python 提供者可实现无参数 `projection_revision()`：返回 1–4096 字符的非空字符串，任何外部内容、可读资格或 guard 变化必须使它改变；每次调用必须检查当前来源。宿主在命中前及构造前后取令牌。缺少方法、返回 None、来源异常或构造失败时不缓存，不沿用旧结果。宿主内置 HostStateProvider 绑定自身字段配置；其子类必须显式重新选择接入，避免继承后意外缓存外部来源。

文件提供者应检查文件身份、mtime_ns、大小及自身内容版本，原子替换、删除、损坏也必须失效；不能只返回房间 generation 或不更新的文件名。该端口不替代 provider 的 `read_live`、`check_guard` 或每次命令的授权复验。

## 提交、备份与 HTTP

固定消息封套和操作 Schema 的 validator 在加载模块时建立。普通文本消息的纯结构缓存键包含全部字段及精确 Python 类型，包含 text/revision，绝不只使用 messageId。富卡片继续走 JSON 原生类型检查与规范字节键。每次完整房间提交仍验证跨记录约束和全图。

`Host.metrics.commitPhases` 分开记录完整模型校验与存储耗时；`FileDataStore.last_commit_metrics` 记录序列化、配额扫描、写入、fsync、发布及拷贝/目录同步。指标不进入持久封套，不改变存档版本、摘要链或故障恢复。通用可变快照 API 尚未引入不可变子树或写集提交；不能依靠调用者声称“字段未变”跳过全图。

`Assets.prepare_backup` 在房间锁内捕获一致代、身份绑定和可选完整逻辑 AI 快照，并固定资源摘要；`write_backup` 在锁外落盘，最终 manifest 写完才成功。固定记录由同一 Host 的 Assets 实例共享，回收跳过这些资源，失败释放固定记录。在线 HTTP 备份仍等待实际完成，格式和恢复分叉不变。AI 分段物理存储须由 AI 侧转换为完整逻辑快照传入，不自动复制对象目录。

新增 `GET /api/v1/ai/rulings?compact=true&queue=active|archived|all&before=...&limit=30&sessionId=...`，转给 `Rulings.page(..., delivered=True)`；`GET /api/v1/ai/rulings/{id}` 转给 `detail(..., delivered=True)`。列表默认 limit=30、最大100；不接受重复、未知或非法参数。无查询参数保留旧 list。权限由当前认证及 AI 服务继续检查，紧凑页不等于执行授权。SDK 为 `aiRulings(options?)`、`aiRuling(id)`，ID 经 URL 编码，详情返回单个 ruling。

`GET /api/v1/view?extras=auto|player|keeper` 在同一认证锁边界和一份房间快照内附加 `viewExtras`；无参数保持原响应。`auto` 按实际角色选择，`keeper` 要求 KP。公共字段是 `mode` 和字符串 `knowledgeStatus`；keeper 额外返回 `knowledgeGrants`（现有披露分页对象，limit=50）与 `members: {items: [...]}`；player 只返回本人 `notifications`（现有分页对象，after=0、limit=50）。这些页的游标、可见范围和上限沿用独立接口，额外翻页仍走原接口。KP 的 PL 窗口可显式选择 player；这只控制附加区，基础 view 仍按实际登录身份授权。附加区不进入基础视图缓存，撤权和通知确认立即生效。身份昵称取同一宿主锁内的当前身份快照，不将密码、会话或管理披露加入 player 附加区。

## 本机证据与边界

完整后端 302 个不同用例通过；与冻结 AI v1 的分页/详情及授权联测 22 项通过（其中15项与后端路由回归重叠）；网络统计另有4组模拟契约检查。均使用隔离合成存档，无真实模型调用或正式房间写入。

随后聚合读取及相关回归57项通过，其中8个新增用例；与原后端集合合并为310个不同后端用例。该阶段采用冻结AI v2，见 `extras-v5.xml`。30样本/场景的同版宿主独立读取→合并读取 p95：1/4/8并发 KP 为12.15→4.99、55.56→22.35、97.60→49.52ms；PL为9.22→4.33、41.48→15.76、73.76→34.56ms。每次所需HTTP请求从KP四次/PL三次降至一次，仍是回环TCP测量，不等同包页面或公网完成时延。

回环 1/4/8 并发读取另做三轮交替对照，各270请求，全部成功。p95 分别为 3.72→4.10、16.76→16.26、33.56→32.20 ms。单并发尾部增加约0.38 ms（10.2%），没有满足“所有路径均不超过10%回退”的严格目标；中位数并未同步恶化，不能据此断言稳定回退或保证无回退。测试期间同机仍有协作进程，结果不是跨硬件 SLO。

JSON decode 替代 deepcopy 只做测量：一万条历史样本 p95 为82.81 ms，对照 deepcopy为71.32 ms，且通用存储的 Python 类型/拷贝契约会改变，因此未采纳。没有未经验证地引入写集或日志式房间存储。当前验收不包含实际 LAN、WAN、TURN、断电、SCTP 重传或全进程树峰值内存；保存的内存数字仅为宿主进程采样。启动测量限于引擎新房间初始化，包资源导出/多组件就绪并行由各模块负责，不把静态 stage 缓存等同于整套冷启动完成。
