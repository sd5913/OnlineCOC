## 1. 定位与文档分工

本地化指多语言与地区显示支持。本方案是一套完全独立的配置包开发模块／工具，独立维护、运行、测试和发布，不属于 OnlineCOC 核心，也不属于任何具体配置包。配置包或其他开发者按需使用其文件规范、编辑工具、资源产物和可选解析库。

2026-11-12，依据用户确认形成以下需求基线。本轮将详细文件格式、API、目录和恢复机制整理到[工程设计](localization-engineering-design.md)，将工作包、依赖和可执行退出条件整理到[施工计划](localization-construction-plan.md)。本文保留目标、范围、已确认决定及产品要求，不重复维护工程契约。

2026-11-12 已开始 L10N-0，实现独立窗口、CLI 帮助、共享消息格式化与最小打包；该阶段 3/4 验收条件通过，原生目录最终确认未完成，L10N-1～6 未开始。当前实现以[工具工程入口](../current/engineering/localization.md)为准；本文其余产品要求仍为待实现范围。

## 2. 已确认决定

| 事项 | 决定 |
| --- | --- |
| 独立归属 | 提供给配置包开发使用的独立模块／工具；不归 OnlineCOC 核心或某个具体包 |
| 默认语言 | 英文为源语言、中文为目标；首版默认 en→zh-CN，项目可显式设置其他语言 |
| 数据与协作 | 可读文件是唯一协作数据源；人、GUI、CLI、脚本和 Agent 使用同一文件契约 |
| 人类开发者工具 | 必须配备可视化管理界面及工具，支持增删查改、预览、审校与发布 |
| 平台接入 | 具体协作平台及实现后置；当前准备稳定身份、格式版本、摘要、审校元数据和交换机制 |
| 缺译处理 | 允许翻译不完整的资源发布；返回 fallback 或指定 errorText，缺译不使使用方运行中断 |

这些决定替代早稿的中文源语言、必需语言完整性发布门槛，以及把主机接口扩展与房间备份纳入本地化实施阶段的安排。工具不为实现自身而修改核心协议、启动游戏服务或改写运行存档。

## 3. 范围与职责

| 对象 | 归属与职责 |
| --- | --- |
| 独立工具 | 自有源码、依赖、schema、GUI、CLI、校验、构建、可选解析库、测试与发行 |
| 本地化项目 | 作者持有的可读资料，可独立存放；一个工具管理多个项目，不把资源写进安装目录 |
| 使用方 | 按需加载资源、绑定自己的显示字段、提供语言与参数、处理授权和部署 |
| OnlineCOC 核心 | 维持自身业务职责，不要求理解本工具的项目格式、资源清单或 TextRef |
| 外部协作平台 | 后续通过适配器交换文件，不能取代项目文件成为唯一权威来源 |

首版范围包括文本 CRUD、引用查询、翻译状态、格式与参数校验、导入导出、冲突处理、预览、不可变资源发布及离线解析。房间身份与权限、规则计算、聊天同步、游戏历史、存档备份和配置包下载均由使用方负责。

工具以独立通用样例验收，不依赖树桩镇或其他真实包。后续某包接入属于该包自己的任务，不能将其需求隐含转成对本模块或核心的强耦合。

## 4. 产品工作流与可视化要求

基本流程：新建本地化项目 → 创建英文原文与语境 → 添加中文译文 → 预览及审校 → 检查文件与引用 → 发布资源 → 使用方加载。保存草稿、审校和发布是三个不同操作，界面必须区分状态。

| 操作 | 人类开发者应得到的体验 |
| --- | --- |
| 新增 | 向导创建项目；词条表建议稳定 key，填写原文、语境和参数，目标语言从未翻译开始 |
| 查询 | 搜原文、译文、key、语境；按语言、命名空间、状态、标签、引用和问题过滤，定位受影响源文件 |
| 修改 | 双语表格和长文编辑器、参数插入、复数分支表单、即时预览；原文变更标记译文需复核并保留旧译文 |
| 删除 | 区分删除单语言译文、停用词条和永久清理；先显示引用影响，支持撤销，不删除旧发布产物 |
| 重命名 | 展示词条、译文、元数据与引用差异；不支持的动态引用显式列出，可保留同语义兼容别名 |
| 管理 | 语言与回退设置、术语提示、翻译完成度、批量操作、文件差异、导入冲突和版本导出 |

GUI 是人类开发者的正式入口，文件不是 GUI 的内部私有格式。应提供打开文件、复制 key/TextRef、查看实际变更和外部修改提醒。多文件保存失败必须可恢复，不静默覆盖其他人的新内容。

具体页面、操作输入、文件影响、键盘行为和错误状态由[工程设计](localization-engineering-design.md)规定。

## 5. 本地化与资源边界

- 游戏 ID、字段名、规则枚举和数值保持稳定，显示文本单独引用。玩家自定名字、聊天和临场笔记默认保留原文，不自动抽入词库。
- 缺译默认先尝试后备语言和源文，再使用指定 fallback/errorText，最终有内置文字兜底；也可配置目标缺失后直接显示 errorText。具体顺序及返回状态在工程契约中定义。
- 工具只做资源的 public/restricted 分类输出，不负责判定玩家身份或剧情解锁。受限内容必须由使用方先授权后提供，不能为了本地化把整个秘密词库交给玩家。
- 项目、资源版本与缓存相互隔离。发布不代表部署到房间，保存草稿不会自动替换运行内容。使用方若需历史显示，自行保留所用资源版本。
- 独立工具关闭后，已发布资源仍能使用。可只用文件，不强制引入解析库；解析库也不自动连接游戏后端。

## 6. 工程方向与阶段入口

工程采用 TypeScript 共享逻辑、Electron 桌面 GUI、独立 CLI 与 JSON 文件；L10N-0 已冻结 intl-messageformat＋ICU parser 的共享解析实现及精确依赖版本，实际范围见[现行架构](../../tools/localization/docs/architecture.md)。文件编辑、容量与完整发行仍需后续阶段实施和验收。

源码已独立维护在 tools/localization/，当前已有 L10N-0 骨架。工具源码、作者项目和发行产物分别管理，均不得依赖 OnlineCOC 环境。目录暂存于本仓库不改变其独立归属，后续迁出时应保持相同文件与接入契约。

[施工计划](localization-construction-plan.md)按 L10N-0～L10N-6 推进：独立骨架 → 文件契约 → 事务与 CLI → GUI 增删查改 → 引用与文件协作 → 资源构建与解析 → 独立发行总验收。每阶段都有前置依赖、失败测试和可检查的证据要求。

## 7. 验收原则与后续事项

最终需要证明：没有 OnlineCOC、具体配置包或系统开发环境时，作者能通过 GUI 创建并管理项目；人与 Agent 可直接基于同一文件协作；缺译发布后仍可显示；中断与冲突不造成静默丢失；已标记受限的资源不进入公开产物；关闭编辑器不影响产物消费。

数据、GUI、故障恢复、性能及独立发行的逐项条件只在[施工与验收计划](localization-construction-plan.md)维护，未执行不得标为通过。

精确依赖、Playwright 真实窗口驱动与最小打包已在 L10N-0 试验中确定；原生目录最终确认、文件替换与恢复实现、实际容量和完整发行仍待验收。第三方平台、其他操作系统、网络盘、自动更新和游戏集成另行规划。已确认的独立归属、英文到中文、可视化工具、文件协作及缺译不中断原则不再列为待确认问题。
