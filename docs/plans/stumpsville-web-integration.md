## 1. 目标与首期范围

让玩家凭房间代号加入，查看配置包、规则和人员，再打开独立游戏页完成树桩镇玩法；资源从房主按需获取。复用 network-web 的平台账号、快捷重入和黑名单，不为配置包另建大厅。

首期已采用：**房主本机运行宿主与 KP 管理台，远程 PL 使用网页；保留平台账号与游戏账号两次登录。** 原有本机、局域网和 AI 入口继续可选，同一宿主先只启用一种远程准入入口。不含浏览器独立托管房间、远程 KP 管理、账号合并或 AI 配置生成/发布。

2026-11-13用户先授权S0–S3接口施工，随后明确“确认，进行更新”，追加云端部署及隔离公网验收授权。S0–S2已落地为Stumpsville 0.8.0、network-web 0.2.0、network-p2p 0.2.2；云端于13日23:50升级，14日完成8组双浏览器强制TURN验收，未改真实团档。S3本地/公网技术闭环已通过，真人独立家庭/移动网仍须单独留证。当前事实以[包网页说明](../../rulepacks/stumpsville/docs/current/web.md)和[工程契约](../current/engineering/network-web.md)为准，以下保留实施目标与待验条件。

## 3. 调整内容

### 3.1 包侧接口与身份

工程侧先按 ISSUE-006 定义包服务能力：显式登记房主回环服务、包 ID/版本、方法与路径、允许的参数、大小和超时。保留核心宿主连接；禁止任意 URL 代理和通过通用 commands 转发包侧请求。

| 现有包侧接口 | 首期网页处理建议 |
| --- | --- |
| `GET package/state` | 返回当前游戏账号的授权投影；白名单校验 locale/page 等参数，不开放任意 KP 预览 |
| `POST package/action` | 保留原动作权限、命令 ID、版本与幂等规则；PL 只能执行自己获授权的动作 |
| `POST package/chat/history` | 校验场景、队伍和私聊成员关系，保持与核心聊天的边界 |
| `package/scene-executor`、`package/bundle`、`package/integrations` | 首期继续只供本机受权管理流程使用 |
| `setup/*`、`host-control/*`、任意文件路径 | 不向远程玩家开放 |
| `api/v1/ai/*` | 原始路由仍拒绝；2026-11-14通过 `POST package/ai` 的固定路径/操作白名单接入个人咨询 |

每个连接必须隔离游戏 Cookie/CSRF，由可信桥建立与包服务一致的登录上下文；不得复用房主的 KP 会话。平台房主身份不自动等于游戏 KP，页面 `?view=player` 也不改变真实账号权限。踢出、封禁、退出和游戏账号切换应同时撤销旧桥会话与访问资格。

首期沿用现有包侧状态/聊天轮询，增加断线提示和有界重试。动作重发沿用同一命令 ID；超时先查结果或恢复原请求，不能重新生成 ID 导致重复扣除。

### 3.2 玩家页面与本机记录

- 保留现有一屏场景桌面、角色工具、行动日志和聊天；分离 KP 控件与本机初始化入口。游戏登录使用可信壳，网页模式不再跳转 `/sessions/...` 或运行 setup。
- 普通 API 通过传输适配调用，图片和语言包通过资源桥加载；把 ESM/SDK 依赖打包，处理 CSS 与图片地址。沿用禁止直接联网、禁止同源权限的沙箱。
- 为字体、语言、桌面偏好及待恢复动作提供受限存储适配；版本2桥已落地，仅允许声明的包键，按平台账号、游戏账号、房间、包ID和资源版本隔离，不暴露账密或会话。动作恢复记录校验规则修订，过期时停止重发。
- AI 按能力显示：已接入本机KP和网页PL咨询，不以隐藏按钮代替服务端权限校验。

### 3.3 资源与配置包声明

保留原 `manifest.json`、Lua、配置和存档结构，新增独立网页发行描述及构建产物。沿用现行 webVersion/资源组契约；如服务能力或桥版本需要新字段，先在工程侧定义兼容版本，不直接把额外字段塞入严格校验的描述文件。

| 内容 | 加载与授权方式 |
| --- | --- |
| 房间信息 | 房主发布不含剧透的包名、版本、规则摘要；加入房间后可见，不提前下载游戏文件 |
| 启动组 | 最小玩家 HTML/脚本/样式、必要通用词条与占位资源；点击进入游戏才下载 |
| 图片、规则参考、其他语言 UI | 按实际打开的功能加载独立组；先满足成员权限，再校验版本与摘要 |
| 场景真相、个人线索、笔记、私聊和受限译文 | 主机依据当前游戏账号生成授权结果；不把完整正文/词库打入启动组再由前端隐藏 |
| KP 原稿、完整包、存档、密钥与参考原图 | 不进入玩家发行清单 |

需要按角色发放的静态组，必须先定义可信的“平台账号—当前游戏身份”关联及撤权流程；首期可先不提供这类组，受限内容通过包侧投影返回。已经交付给玩家的内容无法追溯收回，撤权控制后续获取与请求。网页资源版本在同一房间内不可变；更新发行包需关闭旧房间并发布新房间代号，存档是否继续由房主显式选择。

### 3.4 启动与部署

在包侧启动器增加可选网页模式，借用本次宿主并发布独立网页房间状态，沿用一次性房主认领流程。检查桥版本、发行包和权限配置；不满足时明确提示缺少条件。停止网页分享应保留借用的游戏宿主，关闭整个启动器仍按原有生命周期清理。

腾讯云继续部署网页/账号/房间元数据、目录信令和 TURN；树桩镇包服务、规则、存档、AI 配置与素材留在房主电脑。若公共协议有改动，再更新云端联网代码；本规划不要求新增游戏服务器、数据库或 CDN。无域名阶段沿用测试 CA，正式对外开放的域名与可信证书验收仍见[大厅后续计划](browser-room-portal.md)。

## 4. 实施顺序与路径

以下为实施范围及完成条件；实际阶段结果见表后，不把尚未执行的公网用例计为通过。

| 阶段 | 主要范围 | 完成条件 |
| --- | --- | --- |
| S0 契约确认 | `engineering/network-p2p`、`network-web`；ISSUE-006 | 确定包服务身份、接口/参数白名单、存储桥与版本兼容；权限负例可测试 |
| S1 工程桥接 | 上述模块及必要 SDK 适配 | 两个真实游戏账号经 WebRTC 访问各自包侧投影/动作/聊天；越权、撤权和幂等通过 |
| S2 包侧适配 | `rulepacks/stumpsville/ui/`、`tools/launch.py`、`tools/integrations.py`、`tools/build_web.py`、`web/bridge.js`、`start-web.cmd` | 可选启动、最小玩家页、按需资源、隔离偏好和动作恢复可用；不改旧存档格式 |
| S3 完整联测 | 包侧 `tests/`、模块验收和使用文档 | 两名实际玩家完成下表流程，本机/LAN 回归通过，更新当前文档和实际目录清单 |
| S4 可选 AI | `ui/ai.js`、受限咨询桥及 AI 专项测试 | 网页 PL 自有会话、KP 转交与回复权限通过；配置生成/发布仍按独立 AI 计划推进 |

S0完成版本/身份/白名单/存储契约；S1服务桥通过真实双账号与权限负例；S2完成发行、启动、UI和恢复。S3本地7组网页专项（18预设）、15组业务、10组LAN、6组一屏、5组AI/旧P2P和5项网页启动器通过；工程网页29项通过、2项工程云端用例在该批次跳过。后续新增6组启动诊断、云端部署及8组真实公网强制TURN全流程通过，包含全部18预设。游戏数据均在独立目录，云端仅增加隔离测试账号及关闭的测试房间记录，证据见[测试索引](../../rulepacks/stumpsville/tests/README.md)。S3剩余真人独立家庭/移动网验收；2026-11-14完成S4个人咨询桥，本地真实双WebRTC玩家、KP启用/转交、模拟回复、账号隔离与未知回执恢复已通过5组专项（含KP地图和不加载AI兼容）；未重新进行公网AI或付费模型验收。

## 5. 验收条件

| 范围 | 必须验证 |
| --- | --- |
| 入场 | 代号首次加入、房间信息、跨次快捷重入；信息页没有游戏连接/资源，独立游戏页可用 |
| 账号 | 平台最低 6 位密码与本机可选记住账密保持原行为；游戏凭据按账号/房间隔离，包 UI 不可读取 |
| 完整玩法 | 两名 PL 建角、移动、18 个预设行动、资源变化、线索、队伍/场景/私聊；KP 本机裁定与同步结果一致 |
| 权限与内容 | 两个游戏账号的投影分离，KP 正文/完整包/管理 API 拒绝；受限译文无泄漏，未授权资源组不可猜取 |
| 断线与恢复 | 强制 TURN、重连、超时重发、重复点击、封禁/解封、旧票据、账号切换、缓存版本冲突均有结果；不重复结算 |
| 执行与退出 | KP 管理台关闭时明确暂停自动行动，重开后幂等恢复；停止分享不关闭借用宿主 |
| 兼容与运维 | 原本机/LAN、不开联网、不启用 AI、现有存档继续可用；云端不保存游戏包/存档；独立家庭/移动网实测单独留证 |

## 6. 剩余事项与授权边界

“两次登录、本机 KP、单一远程入口、先完整玩法后网页 AI”已按授权实现。云端已更新，原缺桥接口404已消除；强制TURN、双浏览器及恢复验收通过，真人独立家庭/移动网仍待验证。旧失败启动器需关闭后重新启动网页入口。远程 KP、统一身份/席位、宿主后台自动执行器、运行中资源热更新另期处理，不作为本期现有能力。
