## 首轮排查的目标、范围与结论

用户要求进一步深查各操作流程，允许减少非必要安全检查与校验、引入运行缓存。本轮交付排查与可执行的优化清单；下表记录排查时的候选方案。包侧随后实施的范围与复测见文末。背包丢弃另已实现并验证，见包当前文档。

本轮基于本地源码阅读和独立真实宿主采样，覆盖状态、聊天、手记、规则行动、人工裁决、回合、掉落与领取；四页面脚本另外覆盖 AI 接受、模型工具循环、审批和依赖变化。启动、备份、配置发布、联网中转的新增建议为代码审查结论，本轮未做相应压力测试。所有运行数据写入包的 `tests/output/`，未读取或修改正式房间存档，未调用外部模型。

当前小房间的主要可观察成本是 Lua 独立进程执行，以及包动作的多次全量同步持久化。包状态读取另有固定的串行 HTTP 扇出和共享锁竞争。实际普通聊天接口已较快，但跨页可见延迟还受轮询间隔影响。不能从“本机访问”推断无进程、磁盘或锁开销。

## 已有优化与剩余开销

以下都已在当前源码确认，不应再次当作“新增方案”计入收益：

- 包代理和 Client 已复用无共享 Cookie 的连接池；普通聊天已走独立路径，不等待游戏行动 busy 或完整状态刷新。
- 浏览器已有同查询合并、旧身份响应丢弃、BroadcastChannel 唤醒；包内新的无变更数值写入会跳过宿主提交。
- 宿主已有 ChatState 单条消息及 AiControl 审批 Schema 校验缓存、预构建模型校验器；因此不能把每次完整 JSON Schema 递归都算作现状。
- 宿主 `Host.project` 有按 generation/account 的视图缓存，但配置知识策略时不会填充缓存；树桩镇正常启用知识策略，需要处理外部包来源版本后才可扩大适用范围。
- AI repository 有请求内 read_scope、历史依赖图复用和任务分页；官方压缩机制也已适配。它们没有消除存储快照复制、全量 verify、所有裁决遍历或网络模型耗时。

## 可以减掉或合并哪些检查

1. **同一请求、同一不可变输入的重复检查**：已认证上下文、静态 Schema 编译、工件语法及基础引用结构允许复用。执行前重新读取多个 `/view` 如果只为获得相同命令头，可一次获取并将版本冲突交给最终提交判断。
2. **只为解释原因的重复预检**：包 `explain_preconditions` 与 Lua 检查部分重叠。先将宿主稳定的错误码映射为友好文案；实测比较保留/减少包预检。减少预检不能消除最终规则执行约束，也不能丢失可定位的失败原因。
3. **不相关对象的重复校验**：普通聊天无需重新验证无变更的完整规则工件；手记无需查询场次或个人play记录。通过明确读写集合选择校验范围。
4. **前端重复表单/队列全量复核**：输入时轻量提示，发送时一次校验；不可执行状态变化依版本推送。KP 已做出的决策不重复要求填写同一项。
5. **保留在最终边界的检查**：账号和资料可见性、物品/资源守恒、房间/规则版本、槽位和参数有效性、命令幂等、事务结果以及发布工件身份。这些检查可减少重复次数，但不应通过删除它们造成越权、坏档或复制物品。

## 实施步骤与验收标准

1. 固定同一源码、隔离存档、机器负载和样本集；记录每条操作的用户感知时间、HTTP、锁等待、规则worker、校验、序列化与fsync分段。扩大到100/1000/10000条历史及1/4/8页面，每组至少30有效样本，冷启动与热运行分开。
2. 先做包保存合并和worker原型，各自独立A/B；随后知识投影/缓存，最后更深的存储与增量校验。任何阶段不能把模型等待隐藏在“发送成功”统计里。
3. 初步目标（待实测确认，非当前承诺）：热状态p95低于100ms；本机4页普通聊天另一页完整可见p95低于500ms；简单Lua行动HTTP p95低于400ms。相比同环境基线，目标项p95至少降低20%，其他主要流程p95不回退超过10%，再决定合并。
4. 配合旧权限/知识/原子批次保护测试；新增强杀、回复丢失、并发领取、缓存失效、同账号多页以及撤权测试。分别报告吞吐、p50/p95、峰值内存、文件体积和失败率，不只报平均值。
5. 工程实现由引擎/AI责任者维护；包侧维护编排、界面、缓存和联合验证。分项施工前重新登记占用和具体改动路径。当前待确认的是各原型的真实收益、内存上限和更大历史规模下的尾延迟，而非是否允许开展排查。

## 2026-11-22 包侧实施与复测

手记将正文与回执一次持久化。包内结构化检定或背包申请在同一把锁内完成排队和反馈，一次保存。规则操作把新建作业、执行前角色数据合并到首次提交宿主前的命令信封检查点。恢复仍先查原命令回执。执行所需的第一份命令头可复用该请求的宿主视图。纯手记不再查询场次知识。

PL 的完整宿主视图已带有已授权引用的摘要。包侧用该摘要省去重复搜索，分页时仍走完整查询。正文缓存最多保留八个账号，每份原始 JSON 上限 256 KiB。每次请求重新取得授权视图，房间、run、权威代次、账号授权代次、知识范围及 viewRevision 都匹配时才可命中。KP 预览不能使用其他人的缓存。包侧知识提供方按打开文件的身份、大小和修改时间复用一次解析结果，保留场景数据所需字段。中文本地化跳过没有属性缩写的原文匹配。PL 页面也直接使用个人观察生成场景资料。

### 最终集成版本

引擎 v2、AI v3 和配置包在独立测试房间按顺序运行。每项 30 次，下表比较第一轮包优化后与最终版本的 p95（毫秒）。四读者组使用四个并发请求。普通检定与批准检定均包含持久化回执。各轮 p50、最大值、内部请求与保存次数见[逐项结果](../../rulepacks/stumpsville/tests/operation-optimization-results.json)。

| 操作 | 上轮 | 最终 |
| --- | ---: | ---: |
| PL 完整状态 | 32.83 | 13.88 |
| KP 完整状态 | 51.64 | 18.94 |
| 四读者混合状态 | 130.47 | 76.50 |
| 普通检定 | 828.45 | 237.01 |
| 申请并批准执行检定 | 1057.44 | 547.62 |
| 推进回合 | 798.92 | 533.05 |
| 历史累积后 PL 状态 | 70.38 | 30.81 |
| 宿主私聊发送 | 84.49 | 68.25 |
| 手记 | 25.70 | 27.09 |

四个真实页面发送 20 条聊天消息，20 条均出现在接收方。浏览器表单提交至接收方出现正文的 p50 / p95 为 291 / 371 毫秒。另一个包含输入操作和页面调度的接收计时 p95 为 1.99 秒。测试覆盖裁决等待期间继续聊天、丢回执后按原编号恢复、草稿保留及频道隔离。未调用外部模型，模型生成耗时不在本次数字内。

包侧万条作业交替保存各 30 次，全量 / 分段 p95 为 70.07 / 6.02 毫秒。一百条时分别为 2.88 / 3.33 毫秒。AI 侧万条裁决、每页 30 条，已打开宿主、清空读取缓存和裁决索引后，首次打开活动 / 归档并持久化该页交付证明耗时 320 / 369 毫秒；后续读取 p95 为 15 / 17 毫秒。宿主启动时的磁盘审计耗时另计。专用交付凭证可单独更新；通用 AI 写事务仍检查完整状态，万条下三次更新一组的既有测量 p95 约 6.53 秒。详见[AI 首次读取记录](../../engineering/acceptance/ai-operation-performance/delivery-cold-v3.json)。

同一房间依次打开 1 / 4 / 8 个真实 Edge 页面，各页面按正常方式轮询。在每种负载下串行读取 PL 完整包状态 30 次，p50 分别为 16.57 / 16.52 / 13.15 毫秒，p95 为 77.79 / 28.69 / 47.82 毫秒，均低于 100 毫秒。该组固定顺序、共用已运行的房间，不能据此认为页面越多读取越快。

最终 AI v3 配合引擎 v2 的完整回归共 753 项，全部通过，无跳过，耗时 375 秒。包侧四页面端到端 7 组及掉落、重放与恢复 7 组均通过。串行组达到热状态、简单规则行动及本机聊天提交至对方可见的初步目标；其他回归同时运行时，四页检定和聊天尾延迟仍会超过目标。引擎单并发读取对照的 p95 增加 0.38 毫秒，略超相对回退 10% 的门槛。各轮负载与失败复测分别保存在[引擎报告](../current/engineering/engine-performance.md)及[AI 性能报告](../../engineering/acceptance/ai-operation-performance/README.md)。
