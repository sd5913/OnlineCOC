## 现象与证据

玩家询问已知场景时，回答曾显示 `actions/choices/process` 嵌套 JSON。定位到 AI 的 `known_answers.render` 直接序列化结构化证据；引用详情在深层嵌套时也曾回退为 JSON。这两项 AI 显示问题已在 2026-11-19 修复，不要求引擎代修。

通用数据仍缺少可供消费端直接使用的字段语义展示约定。知识策略已有 `facetSchemas` 的 Schema、模式和 `labelField`，提供方可以自行组织正文；本问题不是要求另建权限系统。需评估能否复用 Schema 注解，或在现有知识读取结果中提供受约束的展示描述，避免每个前端分别维护模组字段字典。

代码证据：[知识服务](../../../engineering/backend/src/onlinecoc/knowledge/service.py)、[知识契约](../../../engineering/contracts/knowledge.json)、[包提供方](../../../rulepacks/stumpsville/tools/knowledge_provider.py)。AI 当前通用格式化器只认常用字段，不知道每个配置包的单位、枚举和业务含义；不能从当前世界查询来给旧观察补名称。

## 目标与责任

| 责任方 | 建议职责 |
| --- | --- |
| 引擎 | 评估最小展示契约，验证类型／大小／版本，与来源证明、撤权及恢复作用域绑定；统一各读取入口 |
| 配置包 | 决定什么已向某人披露；提供名称、单位、枚举、分组、顺序和引用的业务语义；主持机制与玩家内容分开 |
| AI／UI | 渲染已授权内容、固定观察提示及引用；未知类型安全降级，不能推断缺失事实或自行扩大读取范围 |

候选展示信息包括字段标题、显示顺序、数值单位、枚举含义、观察时间，以及**同次授权观察内**的引用名称。只使用声明式且有界的纯数据；不接收 HTML、脚本、可执行模板、网络地址解析器或模型指令。展示契约不能成为授权凭据。

## 边界与待确认问题

1. 先评估现有 Schema 的 `title/description` 等注解是否足够；若新增可选 DTO 字段，明确 HTTP、SDK、AI 和版本兼容。此文不指定已经存在的新 API。
2. 静态字段标题与会泄露事实的对象名称须区分。旧观察不得套用新版包字典解析隐藏地点、未发现人物或后续状态；显示元信息须绑定原观察／策略版本，或有明确不改变事实的兼容规则。
3. PL 的缺失字段表示“本份已知资料未提供”，不代表世界中不存在。保留 observation/live 区分；撤权、重启、存档恢复后旧句柄不能绕过检查。
4. KP 管理信息和 PL 已知投影采用不同授权来源；同一玩家级会话不能因查看者为 KP 就自动补全世界事实。
5. 若现有提供方返回可读结构已经足够，引擎可以只补契约指导而不扩展协议。包侧安全投影不等待此通用增强。

## 实施与验收

1. 引擎责任者确认复用现有 Schema 或增加可选展示元信息的方案，明确大小上限、签名／摘要覆盖和兼容策略。
2. 用 Stumpsville 场景与另一包的证词分面验证，不把 `hp/location` 等字段硬编码进核心。
3. 验收 KP、两名 PL、KP 打开玩家会话、原观察与后续世界改变、撤权、恢复作用域以及不认识展示类型的旧客户端。
4. 恶意标签、嵌套对象、超长内容不能执行 HTML／脚本或诱发额外读取；原记录内容／摘要不被展示层改写。未授权内容不得进入响应或模型输入。
