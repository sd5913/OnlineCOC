## 目标与授权

用户要求真正的上下文压缩、合理增大应用窗口，提升动态新增和修改配置的多轮完成能力。CONSULTATION_ONLY不再仅因资料来源而拒绝KP候选，应提供风险与依据，由KP决定是否执行。PL主要约束未知情报泄露，KP主要通过技术预检和自动纠错保证可执行性。已允许真实API实验，并要求本轮完成后提交GitHub、更新主分支。

## 已核实问题

旧应用初始96KiB／累计256KiB，最近4轮完整历史与32条／12KiB原文摘录均有界，未实现语义压缩。资料查询见到非宿主sourceId即设置consultationOnly，历史还能继承该标签；配置裁决据此blocked并关闭canDecide。包作者指南和错误文案仍包含仅供咨询、不能发布的硬限制。

远端origin为GitHub sd5913/OnlineCOC，默认主分支main；初查main为5c4ff68，当前spathering为d879cef。工作区包含之前已授权开发但尚未提交的依赖性改动。本轮交付须审核并纳入必要工程、包、文档与可复现证据，排除运行存档、凭据和临时产物；禁止强推覆盖他人提交。

## 分工与实施

- AI责任方：上下文预算、自动压缩与可追溯摘要，来源风险评估及KP执行路径、自动纠错、PL隔离、当前接口文档、独立真实API账本。
- 引擎责任方：核查宿主中的策略门禁与真正技术边界，必要时补齐可执行接口和隔离回归。
- 包责任方：作者指南、裁决风险展示和明确接受、实际树桩镇联合场景、界面与导出回归、文档索引和Git交付。

摘要保留原需求、确认参数、决策、未决事项和来源定位；原始记录不丢失。摘要不能成为新的权限、当前事实或批准证明，修改时仍读取当前目标。压缩失败应有有界恢复或明确降级，不重复无限消耗模型。预算须区分输入字节、估算token、输出、工具回合及超时；既有配置和房间也须有明确生效路径。

来源风险不能使支持的KP候选无条件失去执行机会；也不能把宿主无法写入的独立存储或未知字段伪装为已支持。真正需要决策的差异集中询问，唯一可查参数、格式和Schema错误自动纠正。

## 验收与实验口径

1. 多轮动态增加物品、NPC、地图／规则修改；跨压缩仍保留明确参数，实际三检、审批、落地值与原意一致。
2. 独立资料可作为设计参考，KP能看到评估并审批受支持修改；PL不可读取未知资料或借压缩越权。
3. 故意无效字段、引用和工具参数由同任务快速检查纠正；不可修复时保留具体原因与定位，生成阶段无业务副作用。
4. 真实API独立记录尝试数、token、首次可用率、自动修复后完成率、实际执行率、压缩触发及前后体积、耗时；初始失败和修复复验分别保留。先行控制40调用／600000tokens，因长上下文摘要的格式/来源失败及必要复验，内部控制上限追加到60调用／1000000tokens；按实际需要使用，不与以前账本混算。用户授权未指定此上限。
5. 包侧用冻结工程、隔离房间和真实浏览器检查风险接受、时间和过程展示、恢复及网页模块导出；不修改正式存档。
6. 最终检查文档／目录／凭据和构建产物，提交可复现更新；读取远端最新状态后正常快进或合并主分支，核对远端HEAD。
