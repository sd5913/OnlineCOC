## 目标与范围

用可操作原型评估房间文件夹、会话选择与设置的关系，减少在管理弹窗和对话之间往返。原型独立于正式组件，不调用 AI、不修改游戏数据。正式 API 已有置顶、标题、归档与历史设置；本原型的新布局、归档撤销和摘要卡是待评估交互。

打开 [session-prototype.html](../../engineering/ai/web/manager/session-prototype.html)，或本机 AI 管理器侧栏“会话管理原型”。刷新恢复示例数据。桌面使用“房间 → 会话列表 → 会话详情”三栏；窄屏使用列表／详情两页，保留明确返回入口。本轮只展开树桩镇一个示例房间。

## 可体验流程

| 操作 | 原型反馈与设计意图 |
| --- | --- |
| 切换 KP／PL | KP 可见全房间，PL 仅见自己的会话；角色切换清除旧选择 |
| 搜索／筛选 | 标题搜索；进行中、待裁决、已归档；KP 可选仅本人 |
| 选择会话 | 右侧显示创建者、固定等级、可读范围和最近进展；不自动跳进聊天 |
| 新建 | 自动绑定当前身份，PL 不能选择管理员等级 |
| 修改标题／历史轮数 | 明确点击保存，避免轮询覆盖正在编辑的内容 |
| 归档／恢复 | 操作立即反馈；归档后短时可撤销，也可到已归档列表恢复 |
| 删除 | 二次确认，并说明游戏修改不回滚、裁决与用量审计仍保留 |
| 继续／查看对话 | 演示返回原会话的入口；正式接线需要保留草稿、滚动位置与生成任务 |

播放器可读范围在详情中直接展示，不要求用户阅读技术权限字段。管理员浏览别人会话不等于可冒充该玩家发消息。

## 待讨论

1. 三栏工作台是否比当前弹窗管理更易用；小型嵌入场景是否继续用抽屉。
2. 是否需要置顶，置顶属于个人偏好还是全房间设置。
3. “待裁决”按会话关联的未处理批次过滤，还是还应包含普通待转交需求。
4. 归档后保留详情以方便撤销，还是自动选下一条；删除继续强确认。
5. 最近进展优先采用真实最后一条摘要或任务状态，不额外调用模型制造摘要成本。

## 实施步骤与验收

原型与桌面／窄屏截图已完成。下一步按试玩反馈调整，再将确认交互接入 `mountSessionManager` 和管理器；复用现有会话命令，不新增客户端权限裁定。若把现有会话级置顶改为个人偏好，需单独确定新存储范围。

正式接线验收：归档后不会被旧轮询响应恢复；切换筛选不丢未保存编辑；删除期间避免重复提交；断线明确可恢复；PL 不见其他会话；窄屏键盘操作和焦点可回到列表；继续聊天保留原草稿与生成任务。当前原型只验证本地交互，不代表新布局的这些服务端集成条件已验收。
