## 目标与范围

验证基础错误由模型自动修正、真实决策交给用户、修改整批进入 KP 裁决，以及 Stumpsville 的模板和规则扩展。2026-11-16 用户授权真实 API 测试。所有实验使用生成的隔离房间；不修改正式存档，不保存密钥。默认修正次数为首次输出之外的 5 次；超时、取消和权限变化仍可提前终止。

## 用例与判定

| ID | 实验输入／操作 | 通过标准 |
| --- | --- | --- |
| R1 | 先用完资料查询轮数，再连续给 5 次基础格式错误，第 6 份输出合法 | 查询轮数不挤占修正次数；合法结果仅保存一次，无游戏写入 |
| R2 | 首次输出及 5 次重试均不合法 | 共 6 次输出后 MODEL_OUTPUT_INVALID；保留具体错误代码／结构路径，不无限调用 |
| R3 | 首次 Lua 语法错误，修正为合法配置 | 同一提案升级修订，通过 A/B/C 后才待裁决；错误版本不能发布 |
| R4 | NPC 的友好／敌对立场未决，明确要求询问 | needs_input，显示问题及 2—6 个选项，不创建修改、不自行选择 |
| R5 | 确定方案后生成实例批次，连续发送两次“批准” | 首次执行、第二次返回原结果；只产生一个实体，无新增模型调用 |
| R6 | 新增 NPC 模板及 action/calculation，进行一次配置裁决 | A/B/C 通过；一次批准加载整批；模板可实例化，规则可执行／预览，重启保留 |
| R7 | PL 审批、错误 digest、取消、越界默认值、来源撤权 | 拒绝或停止；不泄露已撤回资料，不产生未授权写入 |
| R8 | 单独开启运行时／配置自动批准 | 开关分别生效；配置仍经过 A/B/C 并记录策略风险接受，已有实例值不迁移 |
| R9 | 真实 API + 首次响应注入坏 JSON | 使用真实模型修正；注入次数和真实调用分开统计，不把注入计为服务商故障 |
| R10 | 真实 Stumpsville 多轮设计、确认和配置生成 | 记录问题、回复、选项、三检、最终裁决和用量；人工检查是否冗余或重复确认 |

## 执行方式

离线测试运行 `engineering/ai/tests/test_rulings.py`，与权限、管理器 UI、宿主发布测试联合验收。包侧用 `rulepacks/stumpsville/tests/verify_ai_extensions.py` 验证真实公开 HTTP；网页接线由 `verify_map_ai.py` 复验。

真实实验显式执行 `rulepacks/stumpsville/tests/verify_ai_rulings_live.py --live`。测试代理仅转发到已配置的 DeepSeek 官方端点；第一条响应可注入错误，后续使用真实 API。实验限制真实调用总数 24，超过则停止；每次记录耗时、已确认 Token、错误分类和输出，结果存入独立测试产物。费用以服务商账单为准，不把 Token 估算当作费用。

## 结果与待确认

2026-11-16 已完成隔离实验。真实服务使用当前配置的 deepseek-flash；测试代理只注入首次坏 JSON，后续均调用真实 API。所有正式存档和持久服务配置在实验过程中保持不变。

| 运行 | 实际结果 | 真实调用／确认 Token | 证据 |
| --- | --- | --- | --- |
| 首轮 | R9、R4、R5 通过；R6 连续结构错误耗尽修正，失败如实保留。反馈只有根路径，未保存错误候选，不能确认其唯一字段原因 | 13／162,441 | [首轮](../../rulepacks/stumpsville/tests/ai-rulings-live-results.json) |
| 模板复测 | R6 通过；一次注入响应错误、两次 RULE_INVALID 后在同一提案修正，三检及裁决加载成功 | 7／95,606 | [复测](../../rulepacks/stumpsville/tests/ai-rulings-live-retest-results.json) |
| 最后一轮 | 四项核心用例通过；R9 的 MODEL_JSON_INVALID 修正成功，R4 等待选择，R5 两次批准均 completed 且只产生一个实例，R6 三检／加载成功 | 10／111,484 | [最终样本](../../rulepacks/stumpsville/tests/ai-rulings-live-final-results.json) |

总计 **30 次真实调用、369,531 确认 Token**；三次本地故障注入不计服务商调用。没有再次申请正式房间数据或修改正式存档。最后一轮从提交到模型／校验结果约为 6.20、11.26、12.31、20.20 秒；这些是本机样本，不是性能保证。真实费用未查询服务商账单。

修复反馈现在包含约束说明，机器 Schema 明确 sources/data 文件名必须为不含目录的 basename，包指南提供可运行 Lua 示例。有效 HTTP 响应即使正文 JSON 错误也保留确认用量，由编排器统一修正，避免把已发生消耗丢进无法确认的预留。

人工质量核对：最后一轮的一句话请求已按一句话回答；配置正文仍会保留部分开发字段。R4 已返回结构化选项且未创建修改，但正文仍重复友好／敌对选项，并出现“选定风格与位置后”的多余措辞。**表达质量未完全通过**；后续改进项保留在[接入后续计划](stumpsville-ai-integration.md)，不能把自动流程通过写成任意回答都准确简洁。

离线／浏览器按测试 ID 去重 177 项通过，包侧 6＋11 组通过。回归清单、复测关系及最终源码摘要见 [统一验收结果](../../engineering/acceptance/ai-runtime/rulings-results.json)。自动通过不等于长期游戏性保证；真实回复的可读性需要审阅样本。权限、回执丢失和重启故障使用确定性离线实验；不以一次真实模型成功取代这些测试。
