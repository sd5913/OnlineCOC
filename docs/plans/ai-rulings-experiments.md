## 目标与范围

验证基础错误由模型自动修正、真实决策交给用户、修改整批进入 KP 裁决，以及 Stumpsville 的模板和规则扩展。2026-11-16 用户授权真实 API 测试。所有实验使用生成的隔离房间；不修改正式存档，不保存密钥。默认修正次数为首次输出之外的 5 次；超时、取消和权限变化仍可提前终止。

## 用例与判定

| ID | 实验输入／操作 | 通过标准 |
| --- | --- | --- |
| R1 | 先用完资料查询轮数，再连续给 5 次基础格式错误，第 6 份输出合法 | 查询轮数不挤占修正次数；合法结果仅保存一次，无游戏写入 |
| R2 | 首次输出及 5 次重试均不合法 | 共 6 次输出后 MODEL_OUTPUT_INVALID；保留具体错误代码／结构路径，不无限调用 |
| R3 | 首次 Lua 语法错误，修正为合法配置 | 同一提案升级修订，通过 A/B/C 后才待裁决；错误版本不能发布 |
| R4 | NPC 的友好／敌对立场未决，明确要求询问 | needs_input，显示问题及 2—6 个选项，不创建修改、不自行选择 |
| R5 | 确定方案后生成实例批次，连续发送两次“批准” | 首次执行、第二次返回原结果；只产生一个实体，无新增模型调用 |
| R6 | 新增 NPC 模板及 action/calculation，进行一次配置裁决 | A/B/C 通过；一次批准加载整批；模板可实例化，规则可执行／预览，重启保留 |
| R7 | PL 审批、错误 digest、取消、越界默认值、来源撤权 | 拒绝或停止；不泄露已撤回资料，不产生未授权写入 |
| R8 | 单独开启运行时／配置自动批准 | 开关分别生效；配置仍经过 A/B/C 并记录策略风险接受，已有实例值不迁移 |
| R9 | 真实 API + 首次响应注入坏 JSON | 使用真实模型修正；注入次数和真实调用分开统计，不把注入计为服务商故障 |
| R10 | 真实 Stumpsville 多轮设计、确认和配置生成 | 记录问题、回复、选项、三检、最终裁决和用量；人工检查是否冗余或重复确认 |

## 执行方式

离线测试运行 `engineering/ai/tests/test_rulings.py`，与权限、管理器 UI、宿主发布测试联合验收。包侧用 `rulepacks/stumpsville/tests/verify_ai_extensions.py` 验证真实公开 HTTP；网页接线由 `verify_map_ai.py` 复验。

真实实验显式执行 `rulepacks/stumpsville/tests/verify_ai_rulings_live.py --live`。测试代理仅转发到已配置的 DeepSeek 官方端点；第一条响应可注入错误，后续使用真实 API。实验限制真实调用总数 24，超过则停止；每次记录耗时、已确认 Token、错误分类和输出，结果存入独立测试产物。费用以服务商账单为准，不把 Token 估算当作费用。

## 本轮矩阵与计数方式

2026-11-20 扩展验证同房间重启、顶部调试窗口和配置增删改。已授权在隔离房间调用 DeepSeek；每次真实实验先限定调用次数，凭据沿用本机配置且不进入报告。

| 范围 | 通过条件 |
| --- | --- |
| 重启与权限 | 同目录重启后可读旧对话并继续；撤权、变更来源和旧待执行提案仍按边界拒绝 |
| 调试窗口 | 顶部单入口、整会话/单请求范围、默认不导出正文；关闭或换会话后丢弃迟到结果 |
| NPC、物品、武器和容器 | 新增、替换、可删除项通过三检与批准；发布后实际创建/发放/使用，依赖中的删除须拒绝 |
| 地图与场景 | 增改后可读取并执行移动；稳定 ID、引用关系不破坏 |
| 扩展与核心规则 | 明确高危批准，实际执行或预览；无依据删除、悬空引用、超出包支持范围须给出反馈 |
| 失败恢复 | 明确拒绝不锁死后续请求；超时/断线的未知结果先查原回执，禁止盲目重放 |

首轮与复测分别统计，保留全部失败。配置成功必须走完“模型输出 → A/B/C → KP 批准 → 实际加载 → 玩法消费”；仅生成候选不计端到端成功。预期拒绝单列，不能混入配置创建成功率。统计分开列出场景数、模型请求数、真实调用数、修正次数与 Token，避免重试或重复回归扩大分母。

失败记录至少包括用例 ID、失败阶段、错误码/字段路径、是否产生写入、用户反馈、处理措施、复验关联和最终状态。测试夹具/传输故障与模型或产品故障分别标注。确定性权限、重启、并发和回执边界用离线测试复验；真实 API 样本用于验证实际生成链路，不能代替边界测试或保证任意措辞均成功。
