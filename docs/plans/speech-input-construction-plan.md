## 1. 交付目标与实施状态

交付独立的“浏览器录音 → 阿里云识别 → 编辑文字 → 独立 AI 文本入口”模块，用于玩家行动/KP 需求，以及 KP/开发者的规则和内容编写。范围与协议唯一依据[工程设计](speech-input-design.md)，本计划不维护第二套默认参数。

**用户当前只要求设计和计划，下面所有 SI 工作包均未开始。** 本次不创建工程目录、不安装依赖、不申请密钥、不录音、不调用收费服务，也不修改运行时配置。其他任务对 AI 模块的施工不代表本模块某个阶段已通过。

交付状态必须区分：

| 状态 | 能证明的内容 | 不能据此宣称 |
| --- | --- | --- |
| 语音模块隔离通过 | 真麦克风或协议夹具可得到正确文字，取消、限额和错误可控 | 真实 AI 接收或业务执行已通过 |
| AI 文本接收通过 | 编辑后的文字通过真实 AI 接口持久接收、去重、查询 | 行动执行、KP 转交或配置发布必然成功 |
| 场景 A/B 端到端通过 | 对应场景真实接收、业务权限、结果回执和审批闭环通过 | 尚未接通的作者工具、手机、离线或 LAN 环境可用 |

## 2. 施工依赖、责任与文件范围

默认单一施工者顺序推进；角色表用于职责交接，不要求并行 Agent。每一阶段开始前按 hierarchy 登记实际读写范围，测试输出同样登记。出现其他任务占用先协调或等待；不以本计划预先取得未来改动权。

| 角色 | 责任 |
| --- | --- |
| 语音模块开发者 | 核心会话、协议、供应商适配、音频处理和控件 |
| 宿主/网络维护者 | 身份与目标授权、启动组合、网关、TLS、限额及回归 |
| AI 模块开发者 | 文本 Request 映射、幂等回执、动作/需求/作者侧能力声明 |
| KP/开发者试点用户 | 术语及规则样本、参考转写、真实 A/B 操作与错误修正体验 |

范围缩写仅用于任务表，不表示路径已存在：

- `SP`：`engineering/speech-input/`，包含包、web 控件、contracts、tests。
- `HOST`：`engineering/backend/src/onlinecoc/`。
- `LAN`：`engineering/network-lan/`。
- `SDK`：`engineering/client-sdk/`；`UI`：`engineering/test-console/`。
- `AT`：`engineering/acceptance/speech-input/`，生成物放 `AT/output/` 并忽略入库。

依赖顺序：SI-0 → SI-1 → SI-2 → SI-3 → SI-4/SI-5 → SI-6。SI-4 与 SI-5 可分别收集证据，但本计划不授权并行施工。SI-1/2 使用假供应商和文本接收替身，可在 AI 未完成时独立验证；SI-5 的真实接收依赖对应 AI 文本接口，不能用替身替代最终门槛。

## 3. 工作包与退出条件

### SI-0：冻结契约、语料与验收口径

- [ ] **语音＋AI＋宿主**：以工程设计第 6 节已核对的 AI-0 Request 为起点复核最新契约，冻结 manual 来源、sourceId/sourceRevision、intent、服务端身份与字段分工。补齐公共 args/回执 Schema、目标修订校验和按 clientRequestId 恢复原 taskId 的协议；分别列出动作和作者入口的 AI 方任务，不重复创建 AI 领域契约或在语音包补业务权限。
- [ ] **语音**：创建 `SP/contracts/speech.json` 及正反例，覆盖 profile、Create、SessionView、WS 控制、事件、VoiceDraft、AiTextPort；固定未知字段拒绝、字符计数、音频字节序和版本策略。
- [ ] **KP/开发者＋语音**：准备至少 100 段经参与者允许使用的音频，建议 80 段安静、20 段噪声/口音/中英混用，至少 4 名说话人；场景 A/B 均覆盖，包含 1—120 秒边界、术语、数字、否定、空白和长停顿。保存人工参考文字、关键实体及条件标注。
- [ ] **语音＋试点用户**：冻结 CER 规范化方法、术语召回、数字/否定条件判定、延迟起止点及设备/网络；确认设计中的目标阈值。样本分为调参和验收集，验收集不用于反复调热词。
- [ ] **部署者**：确认阿里云北京业务空间、模型可用性、并发、试测预算、凭据保管和外发说明。此时可先做配置检查，真实音频调用留到 SI-3；不承诺免费额度必然存在。

**退出条件**：字段映射及缺口可审阅，T01/T02 的契约夹具准备完整；预算、样本、阈值和目标环境明确。缺少动作或作者入口可以继续独立模块施工，但必须记录 SI-5 的阻断项。

### SI-1：独立服务与假供应商

- [ ] **语音**：创建独立包和 `models.py`、`service.py`、`session.py`、`providers/base.py`；无 Host/AI/FastAPI 业务导入，以注入端口提供身份和配置。
- [ ] **语音**：实现 created/connecting/streaming/draining/终态、顺序帧、尾帧、stop/cancel 竞争、会话 TTL 与事件快照；每会话串行转换。
- [ ] **语音**：实现背压、时长/文字/并发限制、预算原子预留与持久日聚合账本；重启遗留预留保守计入，不因异常清零。
- [ ] **语音**：提供可脚本控制的 fake provider：延迟 ready、句内替换、重复 final、冲突 final、尾部丢失、401/429、异常断线和费用未知。
- [ ] **语音**：实现清理、日志脱敏和只读诊断；fake 能力只在测试组合中可见。

**退出条件**：T03—T10、T15—T19 的模块级部分通过；没有真实供应商、AI 或麦克风也能证明状态与边界正确。

### SI-2：录音控件与草稿编辑

- [ ] **前端/语音**：实现 `SP/web/speech-input.js` 与 PCM Worklet，读取实际采样率并重采样；200 ms 帧、尾帧排空、bufferedAmount 上限与有限队列。
- [ ] **前端/语音**：实现权限等待、就绪提示、开始/停止/取消、时长和预览；授权迟到、设备拔出、页面切换与退出时释放 tracks/AudioContext。
- [ ] **前端/语音**：通过独立输入组件接入普通编辑器，按编辑器 revision 保护原稿；记录 inputId 插入状态，保证候选只追加一次。
- [ ] **前端/语音**：提供契约测试页与假文本端口，验证键盘和语音走同一个 submit 路径，默认不自动发送。

**退出条件**：T11—T14、T20 的浏览器部分通过；在 Windows Chrome/Edge 实际授予和拒绝麦克风权限，模拟点击不能替代真实授权/设备验收。

### SI-3：首选供应商真实接入与质量评测

- [ ] **语音**：实现 `providers/aliyun.py`，按已核对文档完成任务启动、PCM 转发、finish 和结果映射；持久记录 profileRevision 与请求模型 ID。
- [ ] **语音**：验证 sentence_id、sentence_end、heartbeat 及累计 usage 的处理；连接失败与录音中断分别计量，不逐句累加累计费用。
- [ ] **部署者＋语音**：在明确配置的测试账号和预算内进行真实短句、长句、取消、静音和并发试测。证据保存脱敏请求 ID、参数及结果，原音频和人工参考按样本授权保存。
- [ ] **语音＋试点用户**：执行固定验收集，输出逐条转写差异、术语/关键条件错误、CER 和延迟分布。若首选不达标，按同样口径测试豆包并更新选型理由；不静默切换，也不以单句演示代替对照。
- [ ] **语音**：核对实际费用报告与本地预算账本；记录未知计费、最小计费单位和静音影响，更新发布说明。

**退出条件**：T07—T10 的真实事件联调及 T21/T22 通过，目标质量/延迟达标；无凭据或无真实录音时仅保留“模拟通过”，不能进入正式供应商验收结论。

### SI-4：宿主、SDK 与 LAN 集成

- [ ] **宿主**：新增 `HOST/speech_api.py`、启动组合和 capabilities；核心包只获得必要身份/授权快照，网络等待不占房间写锁。
- [ ] **宿主/SDK**：实现设计第 5 节 HTTP 与 WS，Cookie/CSRF/Origin、认证会话绑定、目标修订复核、一次流连接及 GET 结果恢复；扩展 SDK 独立 SpeechTransport。
- [ ] **网络**：在 LAN 精确放行语音路由与 `/speech-ui/`，只在语音路径允许协议规定的二进制帧；保留原房间通道与其他路由限制。
- [ ] **网络/部署者**：实现可选 TLS、externalOrigin 与正确 Host 校验；在受信证书环境用两台客户端验收麦克风与 WSS。无证书环境记录为未验收，不通过浏览器不安全开关规避。
- [ ] **宿主**：更新实际使用的运行依赖、锁文件、安装清单与许可；没有新增依赖时不制造形式化变更。执行关闭语音模块下的既有启动、登录、聊天与快照回归。

**退出条件**：T15/T16/T19/T23—T25 通过。本机与 LAN 分开列结果；需要 LAN 玩家使用的交付不能只以 localhost 结果通过。

### SI-5：AI 文本桥接与两个场景

- [ ] **AI＋前端**：按 SI-0 映射实现 describe/submit/lookup/cancel 桥接；同一目标、同一文字在键盘和语音来源下执行相同权限与请求创建流程，不向 AI Schema 添加未定义字段。
- [ ] **AI＋宿主**：实现或验证持久接收去重及回执查询；网络回包丢失后能恢复同 taskId，修改载荷同 ID 被拒绝。UI 的“已接收”与业务“已执行/已发布”分别显示。
- [ ] **AI＋KP**：真实验证场景 A：允许的动作、无权限动作、向 KP 提交需求。若当前 AI 只支持提案，则先完成需求转交，动作分项保持未完成并由 AI 模块补能力。
- [ ] **AI＋KP/开发者**：真实验证场景 B：运行房间的规则/内容提案与审批，以及独立作者工作区的草稿编写；作者侧入口缺失时不能用 KP 身份假装覆盖开发者场景。
- [ ] **语音/AI**：录音取消与 AI 任务取消分开测试；语音失败不会撤销或重发已经提交的 AI 请求，发布后取消不会回滚真实游戏状态。

**退出条件**：T26—T29 通过，场景 A 行动、A 需求、B 房间配置、B 作者编写分别有真实回执或明确阻断项。替身验证仅证明输入端口，不能将四项合并写为全场景完成。

### SI-6：试点、发行与文档同步

- [ ] **试点用户**：按第 5 节进行完整人工脚本，至少含一次数字或术语修正、一次取消、一次结果待确认和一次权限拒绝。
- [ ] **工程**：完成 Windows 安装/启动、禁用语音、服务退出清理、预算恢复、多账号与 LAN 回归；确认发行物不含密钥、原始私人录音或测试 fake 配置。
- [ ] **文档维护者**：同步实际目录、运行方式、服务商配置、支持的浏览器/语言、限额及错误；仅将验证通过的能力移入当前工程文档，保留剩余分项与替代关系。
- [ ] **工程**：整理第 6 节证据，核对所有必需用例，通过后按协作规则释放施工登记。

**退出条件**：T01—T29 的必需部分和目标部署场景通过；不完整交付明确标为阶段成果。仅输入层可用不能结束 A/B 完整体验验收。

## 4. 验收矩阵

测试须使用隔离房间、独立数据目录和授权样本。故障注入避免产生真实游戏副作用；真实供应商测试与离线模拟分开报告。

| ID | 场景/输入 | 必须观察的结果 |
| --- | --- | --- |
| T01 | 缺字段、未知字段、非法 enum/版本/字符数、超大 JSON | 契约拒绝，不开上游、不产生 AI 请求 |
| T02 | AI-0 Request 与两类目标的桥接正反例 | manual 来源、sourceId/修订、intent、authorityEpoch、身份及服务端生成字段正确；accepted 不混作领域状态，公共 args/回执与能力缺口明确；语音包不依赖 AI 内部类 |
| T03 | 同 clientRequestId 重发、不同载荷复用 | 返回同 session 或冲突，只预留一次预算；第二条音频连接被拒绝 |
| T04 | 音频序号缺失/重复、头长错误、sampleCount 不符、stop lastSeq 错误 | 明确协议错误；不静默丢帧或拼接损坏音频 |
| T05 | stop/cancel 竞争、重复 stop、结束后追加音频 | 一个终态、一次上游 finish 或 close；迟到事件不自动插入 |
| T06 | 上游未 ready、ready 超时、3 秒停滞 | 准备期不采集上传；超时结束且麦克风/连接资源释放 |
| T07 | 多句临时替换、心跳、重复相同 final | 按 segmentId 更新，无叠字、漏句或心跳文字 |
| T08 | 冲突 final、未完成片段、缺少 task-finished | 报协议/不完整/超时错误，残缺候选不能自动提交 |
| T09 | 正常停止后尾帧、标点、数字、否定词 | 尾帧排空后 finish，等待最终完整文字；不擅自润色 |
| T10 | usage 多次累计、失败缺 usage、并发预留、跨日和重启 | 不重复累加、不超预算、不因重启清零；未知费用保守记账 |
| T11 | 已知 44.1/48 kHz 信号、跨块、长录音和短尾帧 | 输出采样率/时长/频率正确，无累计漂移或边界失真；记录容差与算法 |
| T12 | 真麦克风授权/拒绝/未回应后取消/授权迟到 | 正确状态；取消后的新 tracks 立即停止，无幽灵录音 |
| T13 | 原稿非空、录制时键盘编辑、重复完成事件 | 原稿不覆盖；无修订冲突时只追加一次，有冲突时等待显式插入 |
| T14 | 切换目标、退出登录、设备拔出、页面离开 | 采集资源清理，旧结果不串入新会话，键盘文字保留 |
| T15 | 伪造用户/角色/目标、跨账号 sessionId、CSRF/Origin 不合法 | 拒绝；错误不泄漏其他目标存在性，不能凭“我是 KP”升权 |
| T16 | 活跃流撤权、认证过期、读取结果前撤权 | 轮询发现后关闭上游；GET/发送实时复核，不继续使用旧权限 |
| T17 | 120 秒、超长音频、文字上限、第五路并发 | 到达正常时限执行 stop；越界拒绝，不截断后标成功 |
| T18 | 慢网络、供应商阻塞、客户端 buffer 累积 | 有界背压失败，不丢帧续录、无内存无限增长 |
| T19 | streaming 断连、draining 回包丢失、终态 TTL、重启 | 前者失败；后者通过 GET 恢复结果；过期明确提示；不自动重放 |
| T20 | fake provider/文本替身隔离运行与发行配置 | 可单独验证输入模块；发行环境不能选择 fake |
| T21 | 固定真实语料与标注 | 分组 CER、术语/关键条件正确率可复算；达到锁定阈值或明确失败 |
| T22 | 实际网络的录音停止、首字与最终结果时间；费用对账 | 时延口径一致，p50/p95 有样本数；账单与本地累计用量可解释 |
| T23 | 两客户端 LAN HTTPS/WSS、证书不可信、HTTP 页面 | 受信环境真实采集通过；不受信或 HTTP 时明确不可用，不关闭安全检查 |
| T24 | LAN 未知路径、普通 WS 二进制、超大帧及静态 Worklet | 只开放设计白名单；房间原通道限制保留，Worklet 同源加载正确 |
| T25 | 服务关闭/崩溃/主机退出、日志和发行物检查 | 普通游戏及文本输入可用；无残留录音；日志不含音频、文字、凭据 |
| T26 | 同文键盘/语音输入、编辑后的文字、切换目标 | 相同接收权限和语义；实际收到的是最终编辑全文；目标不串用 |
| T27 | AI 接收后丢回包、重复发送、同 ID 改文字、取消 | lookup 恢复同 taskId，接收一次；冲突拒绝；结果不明时不新建 ID 重发 |
| T28 | 玩家允许/拒绝动作与向 KP 提交需求 | 主机回执符合权限，需求能被 KP 处理；无重复动作或越权 |
| T29 | KP 配置提案与开发者作者草稿 | 生成/校验/审核/保存各走真实入口；KP 发布有明确批准，作者不借 KP 权限 |

## 5. 完整体验脚本

1. 玩家在当前房间 AI 输入框录制一条咨询，停止后改正角色名，发送；核对 AI 实际收到编辑后的文字。
2. 玩家录制一条可执行动作并按 AI 确认流程执行；检查主机回执。再请求一条无权限动作，确认被拒绝。
3. 玩家说“请向 KP 提交制作某道具的需求”，修正数量后发送；KP 查看并处理这条需求。
4. KP 录制包含次数、消耗及否定条件的规则调整，编辑后发送；AI 生成提案，A/B/C 检查、KP 审核、发布仍按原流程进行。
5. 开发者在真实作者工作区录制地点或规则配置需求；确认草稿仅进入该工作区，未向运行房间发布。
6. 重复录音并在中途取消、切换目标或拔出麦克风，检查没有旧结果插入；键盘输入仍可使用。
7. 注入一次 AI 已接收但响应丢失，恢复同一请求结果；证明没有重复执行或重复配置提案。
8. 在第二台 LAN 设备验证同样输入，并关闭语音服务；检查普通游戏和 AI 文本输入仍可工作。

没有真实动作入口或作者工作区时，第 2/5 步应保留未验收状态及责任方；不能用输入框截图或模拟响应替代。

## 6. 证据、交付与发布条件

最小证据集包括：版本与环境清单、脱敏 profile、schema 正反例结果、T01—T29 机器/人工记录、每条样本的参考/输出/差异与授权来源、设备和网络条件、分阶段延迟与用量、真实 AI/主机回执、部署限制及未通过项。

音频样本是否可入库按其授权决定；私人样本默认放外部受控目录，仅登记匿名样本 ID/摘要和获取方式。正式凭据、真实房间秘密和未经允许的录音不入证据。隔离测试生成文件的实际路径在阶段开始前登记。

文档验收至少核对：状态未夸大、来源日期、链接、实际目录、配置示例、键盘回退、ASR 与 AI 的独立预算、HTTPS 条件，以及动作/需求/房间配置/作者编写四项结果。所有必需项通过后才更新对应当前工程能力说明。
