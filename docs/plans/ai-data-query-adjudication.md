## 已完成范围

2026-11-15 按用户授权核对引擎并实施：Room v3 上的四类只读查询工具、HTTP/开发者接口、按需上下文、版本化来源及宿主复验、三种嵌入视图的聊天/事件/裁决语义引用、树桩镇可信只读适配与新行动消息来源记录。实际协议、配额、验证结果和边界统一维护在[当前实现](../current/engineering/ai-data-query.md)，不再在计划中复制。

引擎近期更新为后端 0.2.0、只接受 Room v3，未落地通用请求/决定集合。本轮因此采用标准读取适配先行，不增加第二份裁决事实库，也不改变存档格式。决定采用 confirmed＋outcome（包括 deny），与执行状态分开，替代初稿中易混淆的 decisionStatus=rejected 表达。

## 剩余范围与顺序

| 后续工作 | 前提与验收条件 |
| --- | --- |
| 通用请求与决定持久化 | 按 interaction-records 的 I0— I2 冻结类型注册、来源权限和 Room 新版本；并发决定、改判、恢复与幂等通过后再替换包侧读取映射 |
| 包侧资料参与配置发布 | 建立可在最终提交时验证的跨存储一致性机制；当前 consultationOnly 必须保持；文件变化、进程中断、撤权与恢复负例全部通过后才解除 |
| 大历史检索与性能 | 以固定规模数据测量延迟；当前类型过滤后内存检索，后续按实际瓶颈引入可重建索引和受权缓存；不得返回旧权限下的内容 |
| 历史资料补关联 | 仅按真实业务 ID 导入；无来源保持缺失。语义匹配若引入，只产生待 KP 确认候选，不改写原始历史 |
| 业务界面资料选择 | 现有短指令可附多条资料，底层可指定聊天窗口；按包需求补场景菜单、范围选择和明确的外发预览，不自动监听全部聊天 |
| 真实模型与公网复验 | 用显式选择的测试资料核对实际工具往返与用量；包侧网页服务桥已接线不代表本轮已完成真实公网/跨设备验收 |

## 待确认与退出条件

通用持久记录的数据保留策略、多方决定与执行补偿仍沿用引擎方案的待确认项。首版不以向量库、全自动关联或跨房间查询为前提。

完成后续每项时先验收，再把有效说明写入当前文档；本计划全部完成后归档。当前读取接口可以独立使用，AI 离线不影响既有游戏操作。
