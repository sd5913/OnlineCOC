## 1. 配置入口与规模

| 入口 | 当前内容 |
| --- | --- |
| [manifest.json](../../manifest.json) | 包 ID `stumpsville`，版本 `0.10.0`；登记 2 个数据文件、22 个 Lua 文件，页面入口 `ui/index.html` |
| [game.json](../../config/game.json) | 14 个地点、28 类物品、6 张预设角色、12 个 NPC 模板、6 条遭遇占位、3 条规则速查 |
| [scene-actions.json](../../config/scene-actions.json) | 40 个场景行动、85 种固定做法、18 条玩家知识定义；含玩家措辞及发现条件 |
| [configurations.json](../../config/configurations.json) | 7 类实体配置：角色、场次、世界、地点、NPC、建角骰盘、私密场景状态 |
| [package.py](../../tools/package.py) | 初始化地点公开范围、通路状态、NPC 实例与随机表；维护房间中的活动配置 |

物品以 `game.items` 的 **1 起始序号**被库存引用，地点以 `index` 引用；这些编号具有存档含义，不应随意重排。行动完整条件与结算以[场景预设行动](scene-actions.md)为准，本页仅作内容摘要。

## 3. 角色与 NPC

| 预设角色 | STR／DEX／WIL | HP | 钱币 |
| --- | --- | --- | --- |
| 木栗 `mul`（探路） | 10／12／9 | 4 | 3p |
| 豆叶 `dou`（交涉） | 9／10／12 | 5 | 2p |

木栗、豆叶均为自制测试角色，初始携带针剑、火把、口粮、绳索，分别放在槽位 1、2、5、6。也支持随机建角：三属性各掷 3d6 取最高两骰之和，HP／钱币各 d6，可交换两属性；背景装备与低属性补偿由 KP 核定。

新增预设为榛钉（修理工具组）、苔枝（绷带与安神草）、风尾（绳索与攀爬钩）和芦舟（绳索与搅拌桨），各自另带针剑、火把和口粮。

12 个 NPC 模板中，新房间初始化两只蜘蛛、守卫蛇和五位原创角色。栗婶在庭院、灰穗在大厅、铆须在旧工坊、露哨在信号台、苇伯在渡口。

| 模板 | 所在地 | 当前数值／状态 |
| --- | --- | --- |
| 蜘蛛一、蜘蛛二 | 06 | 各 STR 8／DEX 15／WIL 10、HP 6、护甲 1；采用通用蜘蛛数值，冒险专属条目待终校 |
| 守卫蛇 | 09 | STR 12／DEX 10／WIL 10、HP 12、护甲 2、咬击 d8；复用同一实例 |

## 4. 物品与规则默认值

| 物品序号 | 内容与关键配置 |
| --- | --- |
| 1–5 | 针剑（d6）、火把、口粮、绳索、轻甲；均 3 格用量。轻甲占 2 槽、有效装备减伤 1，其他各 1 槽 |
| 6–9 | 整轮奶酪（100p／1 槽）、金叶鼠像（600p／4 槽）、铜锅盘（10p／1 槽）、蛇笛（1 槽）；用量字段为 0 |
| 10–11 | 搅拌桨（2 槽）、滤布（1 槽），均 3 格用量 |
| 12–14 | 受伤、疲惫、惊惧三种状态卡，各占 1 槽 |
| 15–16 | 法术石板（1 槽／3 格用量）、电提灯（1 槽／6 格用量） |

17–28 依序为黄铜齿轮、密封蜡、修理工具组、干净绷带、灯油瓶、信号旗布、供粮账本、鼠帮通行牌、防水行囊、攀爬钩、支撑木楔和安神草。

基础物品栏为双爪 2 格、身体 2 格、背包 6 格，另有 11–20 超载区；状态卡也占空间。豁免使用 d20≤属性，优势取两骰低值、劣势取高值；光源每 6 个探索轮消耗 1 格用量。更多伤害、休息、掉落和权限规则见[实现说明](implementation.md#规则与权限)。

7 类配置均基于 `actor`：`sv.character`、`sv.session`、`sv.world`、`sv.location`、`sv.npc`、`sv.draft`、`sv.scene`。空白角色模板为三属性 10、HP 4、等级 1，初始在地点 1，未审核、未准备；选定预设后会覆盖对应数值。场次默认 `phase=0`、`round=0`、`autoResolve=1`；场景状态单独记录机关、许可、门与有限库存。

## 5. 自动化与未填内容

- **自动范围**：40 个预设及其固定分支已接入规则结算；默认开启自动裁决，需已登录的 KP 管理页面在线驱动。自由行动、建角审批和主动请求仍交 KP 处理。
- **随机表**：6 条冒险遭遇、20 条战利品均为主持待填占位。d6 遭遇检查已区分遭遇／征兆／无遭遇，另有 2d6 反应和士气规则；能掷骰不代表原版表文已补全。大厅“战利品三次”、洞内宝箱“两次”目前是主持资料提示，不属于这 18 个预设的自动领取。
- **内容边界**：十地点资料、部分道具占槽、Jack／Ernie 数值、蛇笛细节和出口线索仍待原版终校；固定做法及成功／失败分支包含本包适配。法术具体效果、成长、完整战斗／追逐仍由 KP 裁定，详见[来源与许可](sources.md)。
- **开局目标**：[玩家指南](player-guide.md)推荐“探路取物”：两条新发现、带回一件新物品、全员回到入口。它由 KP 核对完成。暴雨主线另按两名村民已获救及修复／外援／撤离的世界记录提供候选结局，KP 在房间总览清点队员并确认，也可记录损失后撤退。


## 6. 房间内增改配置与依赖

| 意图 | 应修改的目标 | 核对的真实依赖 |
| --- | --- | --- |
| 新物品、武器、占槽容器 | 在 `config/game.json` 的 `items` 末尾追加唯一 ID | 保留既有序号，检查占槽、用量与受支持字段。普通容器按物品占槽；增加独立容量机制还需要相应规则。定义本身不产生库存。 |
| 新地点、出口、库存、线索 | `config/game.json` 的 `locations`，以及确实涉及的相邻出口 | 地点编号连续，出口指向存在的其他地点，库存引用有效物品序号。发布后包侧同步地点及通路，新地点的公开与定向揭示另行处理。 |
| NPC 实体配置、默认数值 | 宿主配置集合中相应的 `configurationId`，包中对应 `config/configurations.json` | 读取当前类型、修订与默认值。NPC 位置范围从作者地图生成。运行时检查治疗等规则时，存量实例未触及的旧字段问题会记入 C 类依据；新模板和实际写入字段仍核对范围。扩展模板按字段、试跑与指标检查；已有实例保留自身数值，在用模板不能删除。创建或修改某一只 NPC 走运行时操作。 |
| 预设角色、书面 NPC 资料、遭遇或规则速查 | `config/game.json` 对应的数据集合 | 变更资料与执行 Lua 各有独立入口。初始化用的预设和运行中实例需要分别查看。 |
| 场景做法、提示、可见线索 | 完整作者版 `config/scene-actions.json` 中对应的行动、选项或知识定义 | 更新条件与措辞时保留玩家可见边界。已有结算机制可复用；引入新机制才需修改对应 Lua。已安装的紧凑执行表示携带作者文案摘要，其他数据变更原样继承。 |
| 新规则或调整结算 | 对应的 `rules/*.lua`，新增文件使用独立文件名 | 校验完整候选的规则 ID、输入、权限、执行及覆盖。引用新数据时才一并提交所需定义。 |
| 发放装备、改某位角色的属性、通知玩家 | 运行时指令批次 | 读取活动定义、实际角色与槽位；通知与源动作关联，依执行回执交付。 |

KP 的单文件导入以打开导入窗口时的活动修订为基线。导入后先暂存，可预览再激活。宿主在锁内合并变更文件并检查整份候选，单条宿主增量命令上限为 64 KiB。AI 提案也可只提交有改动的文件或数据路径；A 类核对结构、编号和引用，B 类按包声明运行场景和指标，C 类提供存量影响与覆盖依据。配置裁决详情中的「拟修改路径与内容」默认折叠，路径对应房间规则工件，发布只作用于该房间。

场景行动有两种表示。作者版包含玩家文案与发现条件，宿主执行版可仅保留 `presentationDigest` 与结算用 `actions`。旧校验只接受作者版，导致整包合并校验在新增物品时也报告该文件缺少 `version`。修改物品时保留活动场景文件即可；要改场景文案或结算选项，提交完整作者版，确保能恢复对应展示。
