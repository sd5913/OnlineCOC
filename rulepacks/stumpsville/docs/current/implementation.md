## 格式与组成

manifest 版本为 **0.10.0**，依赖后端 **0.3.0 / Room v4**，包存档支持完整格式 2 和带行动分段的格式 3。启动核对必需字段和已引用分段的摘要；旧档处理见[使用与恢复](usage.md)。

| 层 | 实现入口 | 职责 |
| --- | --- | --- |
| 启动管理 | `tools/panel.py`、`accounts.py`、`slots.py`、`processes.py` | Tk 启动／账号标签、默认AI与独立房间槽位、本机账号CLI、仅托管本次子进程树 |
| 包服务 | `tools/launch.py`、`package.py`、`client.py` | FastAPI 同源服务，使用公共 CLI／HTTP，组合可恢复工作流 |
| 规则 | `rules/`，manifest 登记22个 Lua文件 | 宿主事务内检查权限、投骰、数值与有限库存结算 |
| 数据 | `config/configurations.json`、`game.json`、`scene-actions.json` | 7类配置、28种物品、14地点、6张预设、40个场景行动及玩家措辞 |
| 知识 | `knowledge_provider.py`、`knowledge_client.py`、`scene_knowledge.py` | 固定观察、持续告知、个人菜单与来源守卫 |
| 界面 | `ui/` | 原生 HTML/CSS/JS，玩家三栏、KP独立页面、聊天／AI与反馈 |
| 联机与AI | `integrations.py`、`build_web.py`、`ai_*`、`publication_sync.py` | 模块编排、网页白名单、作者声明、审核来源及发布同步 |

工程目录由工程责任者维护。包代码不直接编辑宿主内部存档；标准启动不安装依赖、部署云端或修改服务商配置。

## 页面与工作流

KP 默认进入 `#/gm/room`，房间、地图、裁决、控制台、地点、资料、场次和 AI 设置独立导航。房间页汇总状态、回合、玩家、准备与待办；一键开场用原 `Job` 流程串接初始化、知识订阅、恢复与开场，不替玩家准备、不重建旧固定观察。

PL 使用 `#/play/scene`：角色／背包、地图／行动、聊天／AI三栏；1050px及以下切换栏目。线索与日志位于可拖动折叠浮窗。KP 可打开同账号的 `?view=player` 独立页面，该页面只取本人玩家投影，不充当自动执行端，也不是另一个账号的模拟登录。完整导航见[界面](interface.md)。

统一裁决队列包含建角、人工行动与复核、宿主等待／异常、AI申请及修改，使用共用卡片；消息与裁决在左栏标签切换，历史移入顶部入口的子窗口。详情支持实际执行或回复；自由／互动／复核只允许针对申请人的 check/damage/rest/grant，已完成请求不重复执行。提交后关闭详情并通知结果；失败保留原请求与可读原因，未知结果保留原回执恢复入口。高危可选备注与浏览器通知的边界见[界面说明](interface.md#反馈语义与边界)。

聊天的全局／私聊使用宿主接口，场景／队伍频道由包服务再次校验角色及当前位置；各频道草稿独立，撤权、退出或切换身份时清理。轮询独立更新聊天、连接与待办，编辑表单期间避免重绘丢失输入。

普通聊天发送使用独立的进行中状态和原请求恢复记录，不占游戏行动的浏览器busy，不等待完整包状态刷新；发送期间新输入的草稿保留。`GET package/chat/state`只组合当前授权频道，前台每1秒、后台每5秒探测，同机页面可通过不携带正文的BroadcastChannel提前唤醒。全局／私聊历史直接交给宿主校验，不在网络往返期间占包写锁；场景／队伍历史只在裁剪本地记录时持锁。完整游戏投影仍按原节奏刷新，迟到的完整投影不会覆盖更新的聊天频道结果。

## 规则与权限

角色、场次、世界、地点、NPC、建角骰盘和私密场景状态分别对应 `sv.character/session/world/location/npc/draft/scene`。随机值和受保护数值由宿主规则生成。

- 建角：属性3d6取高两骰，HP与钱币d6，可交换两属性；六张预设为自制。背景表和低属性补偿由KP核定。
- 检定：d20≤属性，优势取低、劣势取高；超载或受伤对相应检定施加劣势；未准备、未开场或失能不能行动。
- 丢弃：背包物品详情可丢弃实物到执行时所在场景，保留剩余用量与光源计时，自动熄灯；状态卡不允许用丢弃代替恢复。`sv.inventory.core` 在宿主事务中移除库存并返回掉落数据；包 `Job` 按原行动/申请ID保存 `groundItems`，响应丢失需恢复原行动以补齐投影。丢弃记录与地点库存分别保存，玩家界面合并展示；同场景PL可见，KP通过 `ground.take` / `sv.ground.take` 领取给同场景角色。领取锁定原行动，失败释放占用，未知结果保留原回执恢复，防重复领取。这是可恢复的跨存储流程，不是单次跨库事务；调用者须走包行动入口，直接调用Lua规则不负责包投影。
- 库存：1／2／4格物品、轻甲组合、状态卡、钱币占槽及11–20超载区；光源每六探索轮扣用量，换槽／重燃保留进度。
- 伤害与休息：减甲→HP→属性→重伤豁免；重伤失能与状态卡。STR为0不能通过休息复活；照料、耗时、食水和死亡时限由KP推进。
- 场景：40个固定行动处理暴雨主线、机关、有限领取、检定、门与个人发现。自动任务由已登录KP管理页面每0.5秒驱动；离线时等待，重开后恢复。普通检定、物品及可通行移动按自动开关执行。
- 人工：建角审批、主动申请、预设外行动、法术与特殊战斗等由KP处理。复核不自动重掷或撤销既有结果。

具体行动与结果以[场景行动](scene-actions.md)为唯一正文。地图与菜单取本人观察快照，全球发布不自动披露；PL不取得完整物品库、主持世界、动态联系人或共享回顾。知识提供方独立于AI，缺失／故障时拒绝，见[个人知识](player-knowledge.md)。

## 反馈与资料

`dice.js`只展示授权事件中的真实骰点，`effects.js`合并本人结果、线索与属性变化；先检定再反馈，反馈停留3秒、280ms淡出，减少动画仍保留阅读时间。初次载入建立基线，不重播旧事件；换账号、房间或角色清空队列。宿主直接修改本人角色时仅根据授权快照提示变化，不伪造原因或包事件。

`action_errors.py`仅对与标准源码相同的激活规则做无副作用前置解释；自定义规则不套用旧假设。明确业务失败以HTTP 200的 `status=rejected`结果返回，客户端检查业务状态；失败不等同于所有资源未变。未知连接结果与明确拒绝分开处理。

KP资料页按活动配置类型、数据键与规则源分类，缓存按账号、房间和规则修订隔离。UI共527项中英词条，受限内容424项；先权限筛选再翻译副本，用户文字不自动翻译。完整覆盖和未翻译范围见[本地化](localization.md)。

## 持久化与恢复

`runtime/slots/<槽位ID>/host/`保存宿主权威规则、实体、关系、随机回执、账号、聊天及知识；`package.json` 保存包侧地点草稿、发布资料、发现、请求、事件、手记和活动工作流。格式 3 另在同级 `package.jobs/` 保存完成行动和回执的不可变分段。AI伴随材料、联网导出和日志也按槽位隔离。

包使用单实例文件锁、RLock、fsync和原子替换。`Job.command`先保存精确命令信封再发出；恢复先查原commandId，已提交不重掷、不重复领物。原命令unknown且规则未变时才更新运行代际重发原ID。多步工作流不承诺跨存储原子提交；宿主已发布但包同步失败时保留“已提交待同步”。

浏览器动作缓存包含存档路径摘要、登录入口和账号；根地址生成独立登录槽位，刷新保留同页登录，复制完整地址共享该槽位。心跳与访问诊断只在内存保存，不记录密码、令牌或正文。备份须配对宿主和包文件，流程见[使用](usage.md#备份与恢复)。

AI配置发布由宿主A/B/C与KP审批控制，包侧跟随活动工件三方同步；物品与地点编号不可删除或重排，新地点默认私密、新通路关闭，冲突不覆盖KP草稿。具体权限见[AI权限](ai-permissions.md)。

## 验收与剩余边界

[验收索引](../../tests/README.md)区分包内替身、真实本机宿主、浏览器、真实模型和公网证据，不能把组数累加为完整覆盖。原版专属遭遇、Jack／Ernie数值、背景自动分配、法术／成长自动化、完整拖拽库存、额外插画及真人跨网络压力仍未完成。十地点与18预设是本包适配，来源限制见[来源与许可](sources.md)。

阶段发展、故障注入和旧验收记录见[历史](../history/2026-11-20-development-records.md)。

手记与普通结构化检定/背包申请将包内修改和回执一并保存。自动结算先持久化命令信封再派发，首次命令可复用同一行动的视图。PL 状态读取复用当前授权视图的引用摘要，仅在同账号及房间、权限、知识版本均匹配时复用已读正文。各项缓存上限与实测见[操作性能排查](../../../../docs/plans/operation-performance-audit.md)。


包作业达到 128 条时首次检查归档条件，后续每新增 64 条再检查。已完成作业按 64 条组成不可变文件，仍等待主持结算的场景原请求保留在活动存档。旧回执按账号和原顺序分段，活动事件引用的回执在主文件保留读取入口。先同步分段，再原子替换引用它的主文件。启动时逐段核对 SHA-256、回执次序并恢复原行动编号。完整备份合并为独立格式 2 快照。

本地页面以当前授权、语言和角色生成五个状态分区。完整状态接口仍供旧客户端使用。浏览器保留上次分区版本，只更新变更部分；聊天长轮询由服务端发消息后唤醒，并重新检查本人可见频道。空闲轮询、不同账号、不同浏览器各自检查权限，后台页或领读页消失后仍可同步。同槽位、同身份、同视图的前台页面仅广播刷新信号。包内聊天的未读、修订和历史分页索引在内存维护，重启从存档重建。

## 暴雨包的规则发布

0.10.0 在包存档的规则修订中保存完整的行动描述。经宿主发布的行动数据包含执行字段和完整文案摘要。个人知识提供方只有在执行字段和摘要匹配时才采用对应的玩家措辞。包侧允许已登录 KP 导入最多 512 KiB 的配置请求，宿主仍按 64 KiB 上限检查实际命令。游戏目标、物品与任务入口见[内容配置概览](content-configuration.md)。
