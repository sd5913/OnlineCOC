## 快捷取证

| 位置 | 操作与内容 |
| --- | --- |
| AI 对话顶部 | “引用与调试”按钮打开子窗口，可选择整个会话或其中一条请求，复制定位、导出状态、查询链、错误、用量和模型标识 |
| AI 每条回复的过程卡 | 生成中自动展开，按时间显示准备资料、模型请求、工具调用、输出及依赖校验；完成后可展开回看，批准后的命令回执也写入该任务 |
| 待办与修改裁决 | 对应记录的“引用与调试”提供定位与授权调试导出 |
| 包侧裁决详情 | “调试”：复制房间范围、来源类别、ID 与修订；导出当前裁决快照 |
| 裁决页左栏消息队列 | 执行结果的“详情与定位”显示拒绝／失败原因，复制裁决、请求或命令定位；AI结果可重新打开原裁决 |

导出默认不含正文；需要复现对话时勾选包含当前可见内容。KP／PL 权限仍由服务端检查，PL 不能导出他人对话或 KP 私有审核。导出为本地 JSON，不写入游戏状态或命令回执，也不附带服务密钥。局域网不能自动复制时可选择文本后手动复制。

窄屏 KP 裁决页先切到“AI 对话”。切换会话、暂停面板或身份变化会关闭旧调试窗口，重新打开后读取当前授权记录。

结果未知与明确失败分别提示。503／断线后使用原命令回执恢复，不以新ID重发；消息中的定位可用于核对原记录。此类结果通知按房间范围与账号保存在当前浏览器，最多100条，不替代服务端历史。AI拒绝备注保留在本地通知；当前公开拒绝接口没有独立备注字段，不能据此声称服务端保存了该备注。

裁决详情和结果通知使用序号列表显示每条指令的预检查与执行状态，参数可折叠查看。包直接消费服务端 `preflight`／`execution`，不会根据摘要推测成功；缺失检查显示未提供，随机结果显示需运行判定。失败项保留安全原因、规则及命令定位。旧 `partial` 的首项明确拒绝显示0提交、1失败、其余未执行，并说明旧记录没有整批撤销证明；未知回执不归类为成功或确定失败。通知只缓存展示摘要，原裁决仍是核对来源。规则回执中明确的blocked、failure或passed=false另显示条件阻塞／有效检定失败，不把事务提交等同于玩家目标达成，也不将正常判定显示为回滚。

当前新批次采用事务执行：同一宿主支持范围内整批暂存，任一技术或规则前置错误时不提交业务修改；正常骰子未通过保留游戏后果。纯AI会话／草稿记忆批次在AI存储内提交，单条记忆确认／撤销另走宿主权威回执；跨存储组合、等待流程和成员创建等不支持的范围会在执行前阻止。旧批次沿用原回执，不能当作已经原子撤销。具体范围见[宿主事务接口](../../../../docs/current/engineering/atomic-batches.md)。

生成时的格式、工具参数和可确定的引用错误会把具体字段／Schema／规则原因送回同一任务，最多2次技术修复；不要求用户修正JSON或替换唯一槽位引用。目标、成本或效果不明确仍需澄清，权限不足不自动扩大授权，已经批准的包不静默改写。高危配置仍走独立审核。隔离[完整联测](../../tests/batch-workflow-results.json)验证错槽位自动修复、批准前无副作用、整批提交与通知幂等；模拟模型结果不计真实API成功率。

## 上下文与减少往返

应用的上下文预算与模型窗口分别控制。原始资料捕获上限为2MiB；模型请求的框架上限为768KiB并预留2KiB封装余量，实际还按所选模型窗口扣除输出和安全余量，未知模型采用较小限额。当前DeepSeek配置通常在256KiB触发语义压缩；阈值会随较小模型预算降低。设置中的最近0—4轮之外，管理员还可携带较早用户需求（最多100条／384KiB）和经权限复核的旧助手方案（最多100条／192KiB）；超出部分明确记录省略，关闭历史会同时关闭这些携带。

压缩会调用模型整理目标、已确认参数、未决问题、当前计划和工具结果，每项必须引用可核验的原文片段。当前要求、策略和候选契约保持精确；较新更正优先。摘要只辅助生成，不能代替当前游戏事实、权限、审批或执行结果。原文按内容摘要去重并gzip保存于独立归档，当前授权生成任务可用room_read_compressed回读；相同会话／主体／模型及原文可复用摘要。跨轮旧方案仍逐次核验查看权，PL保持本人已知资料边界，不参与KP语义压缩。

过程卡显示“压缩上下文并保留可追溯原文”。调试诊断包含每轮前后字节、原文记录数、摘要定位、修复次数和状态，不默认输出原文。一次摘要有一次自动格式／来源修复机会；任务压缩最多8轮。超限、无法缩小或引用校验失败保留原文和具体错误，不无限重试。模型调用及用量包括压缩开销；这与磁盘历史存档的无损压缩是两套机制。完整边界见[AI上下文](../../../../docs/current/engineering/ai-session-access.md#上下文连续性与预算)和[服务管理器](../../../../docs/current/engineering/ai-manager.md)。

摘要中的确认参数以核验过的用户逐字原话为准。模型改写引句不能增加数值或把否定变成确认；无法逐字支持的内容标记为原记录定位，并要求回读核对，不能据此认定用户已同意。压缩归档使用独立临时文件和有界并发恢复，避免多个页面同时生成时争用同一缓存文件。

明确的配置修改会按当前权限预读相关模板（最多5项／8KiB）及可用操作名称索引，减少只为确认可查字段而追加一轮工具调用。用户已经明确选过的同组选择若被再次提出，会在原技术修复额度内纠正；目标、效果或成本仍存在真实歧义时继续提问。不得凭历史摘录补造当前事实、绕过审批或静默扩大修改范围。

上下文保留、资料预读和重复选择纠正分别处理信息丢失、工具往返和冗余确认，不能保证模型所有回答都正确。真实模型成功率须同时检查方案含义、能力描述及实际校验／执行，不能仅按回复JSON合法或含有选择按钮判定成功。

## 转 AI 与来源

建角、玩家行动、宿主等待／异常、历史记录及 AI 队列均有“转 AI 处理”。这会打开独立 KP 审核会话：KP 发出处理指令，玩家原话与原裁决放在来源卡中，可回看原裁决／对话。原申请人不等于当前 KP；来源快照也不等于当前游戏事实。

已处理的包申请可回看只读详情；AI 原裁决／请求也按当前权限重新读取，不依赖旧快照执行。转交只准备方案，不批准原裁决。生成的修改仍须人工审核，PL 不会收到 KP 私有分析。重复转交同一来源与要求复用审核任务；包根据真实 request/event 与 flow/wait 关联提供 correlationKey，不靠相似文字或同一玩家猜测事件。建角草稿没有跨修订关联键，重新提交的角色不自动当作旧业务。响应丢失时恢复原回执；原记录被移除时说明来源不可用，不伪造关联。

继续处理已有问题可在通用对话选择“继续此请求”，以明确的 replyToRequestId 关联后继；普通新消息不自动合并。新候选通过校验后才替代同事件旧待审项，历史保留 supersedes/supersededBy 供查看。无可靠关联的中间项由KP手动归档；归档并不删除业务记录或批准修改。已执行、执行中、部分完成与结果未知不能因来源改变而重跑。

会话访问权仍有效时，已向该主体发布的原需求、回答和申请人继续展示；引用资料失权不替换整段消息，只让相应入口灰显不可打开。旧记录须有可信会话受众与最终正文证明才能迁移，缺失回复时间显示未记录；不补造从未生成的回答。旧回答只作为历史意图，执行前重新读取当前目标与事实。生成中、失败、取消以及真实执行结果保持各自状态，不被过期提示覆盖。包侧卡片与详情消费 `sourceState/sourceNotice/historicalReadOnly`，原机器原因保留在 `sourceError`。

新任务在发送时冻结本轮资料与工具读取视图。生成期间的普通聊天不改变该输入；相关资料变化后，返回保留原回答和候选，并在“资料变化”提示中列出涉及的对象。KP可选择“按最新资料重新生成”，该按钮先恢复原需求到输入框，发送后才再次调用模型。批准时仍检查当前权限、目标版本和事务条件，资料变化提示并不允许强制执行旧候选。账号撤权、会话删除、关闭资料外发或取消任务仍会阻止继续生成；进程重启导致未完成的内存快照丢失时，任务明确标记中断，不把新资料拼入原任务。

过程卡展示可公开的阶段、工具名、操作摘要、时间、耗时和结果；具体候选指令及回执仍在已有批次／配置裁决详情中查看。它不展示模型隐藏推理或服务密钥，PL看到的内容继续受本人授权限制。旧候选保留原有基线校验，不能通过更新程序自动取得新的执行授权。

本机代理的错误带 `code/httpStatus/operation/requestId/traceId`，必要时含原命令和内部上游操作定位。槽位 `request-errors.log` 只保存安全定位及异常类型，不记录密码、Cookie或正文。超时、拒连、非JSON HTTP错误、本地资源错误分别提示；GET查询失败不再泛称恢复原行动。正式写入结果未知仍按原ID核对回执，不因诊断增强而自动重交。

本机响应的`Server-Timing: package;dur=…`记录包请求总处理毫秒数，便于和浏览器等待、宿主和模型调用计时区分。代理及包组合请求复用连接池，池不保存Cookie；每次请求独立传递会话和CSRF，不缓存角色授权。暂时状态查询失败保留当前AI窗口；401或403仍清除上一身份的展示。聊天历史与裁决列表会合并重叠读取，后台页面的完整状态刷新间隔为10秒，自动执行器仍独立每500毫秒探测，跨浏览器结算不等待完整状态刷新。

普通聊天室有独立发送状态、轻量频道刷新和“核对原消息”入口；裁决处理中仍可发送聊天。丢失成功响应后沿用原包请求ID核对，未确认前阻止另发消息，避免重复发送。聊天401/403立即清除频道视图，其他刷新失败等待下次授权读取；真实权限与目标版本检查继续保留。收发耗时和隐私／恢复测试见[聊天对照](../../tests/chat-delivery-optimized-results.json)，四页小样本不作为所有设备或公网延迟保证。

资料桥只复用角色引用中的账号绑定显示标签；包文件的标识、大小或修改时间变化即重读，原子替换和删除也会失效。资料正文与权限仍逐次按当前授权读取，不使用标签结果决定访问权。

KP宽范围的包配置资料只枚举`GAME_FACT_ROOTS`中的游戏事实，例如地点、通路、机关状态、角色名册、已发布资料和规则修订。聊天容器、作业、回执、事件总表及包总版本不再伪装为`config`依据；独立`chat/event/ruling`入口保留。普通聊天发送、编辑、撤回和已读不会改变这份配置投影；明确引用的消息被改动仍使该消息证据失效，真实地点等游戏事实变化仍须重验。

撤权、删除、跨恢复作用域仍限制正文。旧 `sourceRefs` 和有对象引用的读取可重新核对；少数旧搜索记录只留摘要、未留对象标识，结果变化后无法证明历史权限，显示 `HISTORY_PROVENANCE_INCOMPLETE` 及中文说明，需要重新描述需求并查询当前资料。不能把这类记录自动当作仍有权读取的普通版本变化。

游戏术语文件的 `runtimeReferences` 声明用于生成输入中的有限数字引用投影。当前声明把树桩镇角色的20个itemN／usesN字段映射为槽位、物品定义编号／名称和剩余用量。AI模块通用展开后，已读取实体的工具项可带 `referenceProjections`；仅管理员会话且允许KP资料外发时提供，不遍历未读取角色，不向PL增加资料。定义来自发送时快照中的活动工件，实体与定义节点都进入依赖校验。投影用于解释引用，不能替代正式执行检查、创建权限或决定目标；界面业务卡仍消费原授权引用。

## 引用展示的责任边界

| 实现方 | 当前职责 |
| --- | --- |
| AI 通用组件 | 读取并复核授权引用、处理刷新／迟到响应／失效、维护弹窗和技术详情；提供同步 `renderReference(item, {audience, readOnly:true})` 扩展，返回 DOM 或空值 |
| Stumpsville 配置包 | `ui/reference-view.js` 只消费这份DTO；角色属性与物品说明复用常规页面显示函数，场景展示该观察内描述、通路和线索；不向当前世界另查资料补齐旧记录 |
| 引擎 | 负责原有数据权限、来源证明及知识记录；本次不在核心硬编码游戏字段，也未新增跨包展示元信息协议 |

该回调是随包发布的可信代码，不接受资料或模型输出中的脚本。名称和说明按安全文本显示，未知结构交还通用展示。此边界与仍待评估的[通用展示元信息](../../../../docs/plans/Issues/issue-012-authorized-data-presentation.md)分开。

严格PL的紧凑正文由通用 `known_answers` 格式化器生成，旧版展开格式也由模块转为引用入口；只改包作者指南不能改变这条路径。正文不复制整个场景或行动树，相关资料用名称、短说明和按钮提供，点击仍读取该份授权引用。包不读取隐藏材料来补齐答案。

## 问题排查

- C阶段的`EXTENSION_FORBIDDEN`／`LIVE_SCENARIO_COVERAGE_MISSING`现在提供可采纳的风险评估，不单独把方案判死。先查看详情中的风险、位置、证据与覆盖限制，再决定“采纳评估并发布”或拒绝。机器输出`unknown`仍保留，不能理解为已证明安全。同名A/B错误仍须修复。
- `C_BASIS_STALE`表示评估后判断依据发生变化。点击“重新检查”生成当前依据的评估，再由KP决定；不能重用旧摘要。仅重新检测不会调用模型或发布配置。动态依据入口位于AI设置，支持指标阈值、补充场景和说明，原作者场景继续保留。
- `STALE_AUTHORITY` 表示执行权限版本已失效，房间进程重启会更换该版本；旧候选即使A/B/C三检均通过，仍可能在批准阶段被拒绝。若唯一回执是 `ai-ruling:<提案>:<修订>:approve` 的明确拒绝且没有发布记录，不能将其解释为配置已发布或备注不足。内容指纹不包含权限版本和提案修订号，因此重新检查后的指纹可以保持不变。
- 对上述明确失败的高危配置，详情提供“重新检查”：核对原差异涉及的当前配置，创建新修订并重跑三检；队列恢复待确认后，再由KP接受。相关配置已变动时拒绝沿用旧整文件，改为转AI基于当前资料准备方案。重检不调用模型、不自动发布。[当前引擎](../../../../docs/current/engineering/ai-rulings.md)同时按修订与指纹关联裁决，原拒绝回执保留；更新后须重启房间加载新代码。仍运行旧引擎时会明确提示队列未恢复，不能把三检通过当作恢复成功。包侧[5组隔离复验](../../tests/stale-approval-results.json)覆盖重检、再次人工发布、冲突保护和失败定位，保留首次失败证据。
- “全房间读取／允许修改”与“资料外发”是两层设置。KP 外发关闭会省略 KP 正文和作者指南；公共操作 Schema 仍可查询。要启用全部游戏资料，在 AI 设置点击“选择全部游戏资料（保存后生效）”并保存；这不会自动开启调用或自动审批。
- `sv.character.itemN` 是物品编号，定义来自当前活动 `game.json.items`，不能用 `demo.weapon` 或模板默认值代替。新增定义是高危候选；批准定义后发放或消耗物品须另行处理。
- 追加物品可通过绑定当前版本的配置读取与显式 `dataEdits` 构造完整候选，未修改字段由服务端保留；旧版本、重复 id 和增量／整文件混用会被拒绝，仍须高危审核。
- 服务配置显示请求模型、版本核实备注及来源／日期；每次响应保留服务商返回的模型原值。版本备注是核实记录，不保证服务商将别名永久固定。更新后重启房间并刷新／重新导出网页资源。

参数错误会在原额度内返回明确反馈供模型修正；权限与来源失效仍须重新核对。KP引用独立资料时现在显示参考资料评估；读取当前可执行目标并通过技术检查后，可由KP明确采纳。`CONSULTATION_REVIEW_REQUIRED`表示缺少或不匹配的来源确认，需要查看当前评估再裁决；`CONSULTATION_ONLY`仍可能出现在严格PL写入尝试或旧版本拒绝记录，不能通过伪造确认绕过。`STORAGE_UNAVAILABLE`／`STORE_FULL` 时先核对回执和存储状态，不能删除历史中间代或重复发放。失败与首次／复验计数见[统一修复报告](../../../../engineering/acceptance/ai-runtime/repair-20261120.md)。
