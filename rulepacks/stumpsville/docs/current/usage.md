## 启动与入场

网页联机使用 [start-web.cmd](../../start-web.cmd)，完整玩家场景已完成本地及公网强制TURN联测，云端已更新；旧的失败启动窗口需关闭后重新双击启动，操作见[网页联机](web.md)。可选 AI/旧 P2P 使用 [start-integrated.cmd](../../start-integrated.cmd)，提供 AI 咨询和旧 P2P 基础宿主接入，见[模块接入](integrations.md)。

前提是现有 `engineering/.venv/` 可运行 FastAPI、uvicorn、httpx、websockets 和宿主依赖。包启动不安装或修改工程环境。

1. 双击 [start-panel.cmd](../../start-panel.cmd) 或 `start.cmd` 打开Python面板；本机默认 `127.0.0.1:8899`。选择本机／局域网／网页方式、端口和是否加载AI；局域网另选网卡。原各双击入口预选对应模式，打开面板本身不创建或发布房间。
2. 全新运行目录在面板设置8–128位初始密码并确认，点击“启动房间”。宿主建立 `kp`、`player1`、`player2` 三个测试账号，初始共用此密码；成功后打开主持登录页。已有存档不再询问初始密码，也不会重置账号。
3. 同设备、同浏览器可同时打开多个根地址页面，每个页面自动取得独立登录入口；也可在登录页或“偏好”中点“新开独立登录页”。分别登录 `kp`、`player1`、`player2` 即可共存，不需要无痕窗口。刷新保留该页会话，复制相同完整地址则共享该入口。固定的 `/sessions/kp/`、`/sessions/player1/`、`/sessions/player2/` 仍可使用。
4. 玩家从大厅创建预设或随机草稿。KP 在“控制台”审核；随机角色背景及起始装备须按 SRD 核定。玩家打开背包检查后标记准备，KP 在控制台开场。

面板可通过标题栏或“最小化”按钮缩到任务栏，房间继续运行；“停止房间”停止服务但保留面板。点窗口关闭按钮会先停止分享、宿主和适配器，再退出。正常关闭保留存档；Windows进程托管在面板意外退出时也会结束本次子进程，异常断网后的云端显示仍可能等待租约到期。关闭浏览器网页不会关闭面板或房间，自动裁决仍需KP网页在线。存档位于本包 `runtime/`，测试使用 `tests/output/`，互不混用；不要同时打开两个使用同一存档的启动器。

双击入口直接使用 `pythonw.exe` 显示面板，不保持命令行窗口。需要命令行运行时仍可使用 `start.ps1`，Ctrl+C结束；其中文脚本保留UTF-8 BOM，以兼容Windows PowerShell 5.1。

面板入口兼容 `-Port`、`-Bind`、`-DataDir`、`-NoBrowser` 和 `-AI` / `-P2P` / `-Web`，也支持Python式 `--port`、`--data-dir`、`--mode local|lan|web|p2p`。`-Web` 与 `-P2P` 互斥，网页管理服务只绑定回环。`-DataDir` 指定独立存档目录，`-NoBrowser` 禁止启动成功后自动打开浏览器；都不会代替面板中的“启动房间”。命令行 `start.ps1` 保留原参数和自动启动行为。例如打开一个独立目录的面板：

```powershell
rulepacks/stumpsville/start.cmd -Port 8900 -DataDir "D:\Studies\Art Programming\OnlineCOC\rulepacks\stumpsville\runtime-other" -NoBrowser
```

网页游玩双击 [start-web.cmd](../../start-web.cmd)，现默认加载AI；只用本机AI双击 [start-ai.cmd](../../start-ai.cmd)。服务配置或密钥尚未就绪时，用 [start-ai-manager.cmd](../../start-ai-manager.cmd) 打开管理器配置并启用服务，然后在KP“裁决→AI 助手内的 KP 审核与设置→服务与外发范围”允许调用并保存。网页玩家只能提交自己的咨询，PL请求由KP点击“转交AI”才调用模型；KP在新版对话中点击发送会直接转交本人请求；外发范围保持明确选择，详见[模块接入](integrations.md)。

## 首次走查

若开启外发后AI仍声称roomFacts为空，请先关闭启动窗口并重新启动房间，再新建AI会话。查询指南随启动时的AI快照加载，刷新网页不会更新它；“KP 审核与设置”会提示旧指南。当前按需模式的空初始上下文不表示房间无实体，实际资料需工具查询。更新后的引擎已在隔离真实服务复验中完成实体/配置分页查询并返回回答；这不代表读完全部资料或所有解释均准确。可先问某个场景的NPC，或按角色、规则、事件分开提问，并在“资料查询”中核对实际工具执行；未读内容及地图/剧情推断仍需KP审核。排错与验证范围见[AI接入说明](integrations.md#ai-查询空列表排查2026-11-15)。

### KP管理台与本人PL视窗

所有登录后的包页面可点击顶栏右侧箭头收起菜单，再点“展开顶栏”恢复。折叠偏好按登录入口和账号保存，切页、刷新后保持；切换不会清空AI或聊天草稿。裁决页无额外标题横栏，消息/裁决队列、原生AI与常驻聊天填满剩余高度。

0.5.0起，KP登录后默认进入管理台。房间管理、裁决、地图、控制台、地点、资料、场次使用独立路由，保留房间信息、队伍管理、裁决、聊天入口、备份等全部原有管理功能。顶部“打开PL视窗”新开同一登录槽位的独立页面，地址带 `?view=player`；此页仅取得KP本人玩家投影，复用玩家的建角、大厅、场景、背包、线索和记录界面，没有管理导航或主持真相。

KP可在PL页创建自己的小鼠，再回管理台审核自己的草稿，随后在PL页准备和实际游玩。PL页顶部“打开管理台”可回到独立管理页面；两页共用同一账号会话，其中一页退出登录也会使另一页的同账号会话失效。自动场景执行需保持管理台登录在线，单独打开KP的PL页不充当自动执行端。普通玩家仍使用自己的独立登录页。

### 常驻聊天与私聊窗口

0.6.0玩家场景右栏常驻聊天，顶部切换全局／所在场景／队伍／私聊，显示各类未读数。同类有多个会话时显示会话列表；单会话省去重复选择区。没有私聊时显示联系人提示，不借用全局输入框。底部不再提供聊天入口。KP独立裁决页右栏常驻同一聊天工具；左侧未读消息队列可直接选中频道。

- **全局**：所有当前房间成员可见，沿用宿主公共频道。
- **所在场景**：按本人角色当前位置显示；发送和查询历史均在服务端重新检查位置。移动后不能继续读写原场景频道，原窗口缓存及草稿会清除；返回该地点时可查看其历史。KP管理台可查看当前角色所在各场景。
- **队伍**：已拥有角色的成员及KP可见，当前冒险全体角色为同一队伍。需要额外分组时，KP可在管理台创建宿主分组频道。
- **私聊**：“建立私聊”选择成员，可同时打开多个独立窗口；窗口标题显示对方角色名／账号，支持拖动、折叠、关闭。关闭窗口不删除消息，从会话列表可重新打开。KP不能读取自己未参与的私聊。

输入区支持Ctrl+Enter发送；草稿按频道分别保留在当前页内存中，切换、折叠、关闭窗口或切换语言不会混入其他会话，刷新／登出／连接异常会清空。支持较早记录、标为已读、本人消息编辑／撤回。消息按纯文本显示。场景和队伍聊天写入包侧存档，每频道最多10000条、单条4000字；全局、分组和私聊仍使用宿主聊天存档。两个存档均包含在原有配对备份内。

### 语言

网页顶部可选简体中文／English，当前标签页刷新保留。477项UI词条及424项受限内容词条已接入，涵盖玩家主要流程、十地点公开描述、18个预设、系统检定与状态变化；玩家输入保持原样，KP部分旧编辑提示和原生启动器仍为中文，详见[本地化接入](localization.md)。

自动裁决默认开启，可在主持控制台关闭。保持至少一个KP页面登录在线，即可自动执行预设，无需逐项批准；页面关闭或休眠会显示等待自动结算，重开后继续。新建存档已包含完整场景规则；页面不补装旧规则。

玩家探索时停留在固定一屏的场景桌面。场景／大厅／回顾移到顶栏；其下方“角色状态／背包装备／线索手记”打开三个可折叠浮窗，点击工具按钮可置顶或关闭。左栏为地图、可用行动及现场事实；中栏为行动日志；右栏为常驻聊天。历史记录只在所属栏内滚动，整页无需上下浏览。宽度不超过1050像素时，用顶部栏目按钮在场景／日志／聊天间切换。面板偏好按账号和独立登录入口保存。导航与功能组成见[场景桌面与主持控制台](interface.md)。

玩家从01入口开始：“观察地面”会发现机关和02；“检查奶酪”可选择安全检查、敏捷豁免解除或直接拿取。到02后检查把手，再用绳索固定开门或冒险直接开门，实际开放03。庭院辨认梯子后继续探索04–10。每个预设的检定与结果见[18个场景行动](scene-actions.md)。未公开、锁住或不相邻的地点不能自动进入。公开描述和主持真相分栏保存；“发布预览”只发布已保存描述及勾选的线索。

玩家可点属性检定、物品详情使用/换槽/点亮，转交则进入主持请求队列。主持“推进回合”每次仅推进一次；六轮消耗已点亮的光源一格。04铜锅盘和07鼠帮人数只生成一次，生成后保留结果。地点库存领取在接收角色实际位于该地点时执行。

需要主持判断时，预设行动、检定、移动、使用/换槽弹窗可选择“主动请求 KP 裁决”；场景的“请求 KP 裁决”可描述具体事件，已有回执也可点“请求复核”。KP 在“裁决→裁决队列”查看上下文、批准或拒绝并填写回复。复核已完成行动不会重复掷骰或扣减资源。关闭自动裁决后，新预设行动、检定、物品操作和移动默认等待主持；已有申请不会在重新开启时自动批准。

中栏“行动日志”统一显示提交、等待、检定、结算、资源前后值和主持说明，不再重复显示最近行动和记录浮窗。最新行动默认展开，旧条目折叠，可手动展开并筛选全部／待处理／检定。等待批准或执行的任务不提前投骰、扣资源；实际结果包含原始骰、阈值、叙述、机关／库存和本人资源变化，新线索进入线索面板。可对条目申请复核，适用回执可分享文字摘要。轮询保留日志滚动、手动展开状态、聊天草稿和未保存手记。旧存档回执保留，但无法补建当时未记录的资源前后值。

“控制台”分别提供遭遇检查、冒险表抽取、反应、士气和伤害。未终校表项在“资料→编辑随机表”填写。通用蜘蛛/蛇已预建；其他NPC可按原版输入数值新建，不能把默认小鼠数值当专属数值。

连接中断后保留原行动，使用顶部“恢复原行动”。不要为同一次掷骰或领取换一个新请求。规则版本冲突时刷新并检查来源；主机已明确拒绝才重新发起修正后的行动。

## 局域网

可直接双击 [start-lan.cmd](../../start-lan.cmd)，不需要输入命令。该入口使用现有Python环境中的Tkinter，并直接启动树桩镇游戏服务；不需要另开通用LAN网关。0.4.2增加“检查连接 / 启动问题”，启动失败或朋友连接超时时也可使用。

1. 若原 `start.cmd` 仍在运行，先关闭它；两个入口共用默认 `runtime/` 存档，不能同时占用。
2. 双击 `start-lan.cmd`。窗口自动识别已连接网卡的私有IPv4，优先选择上次使用的地址，否则选择有默认网关的网卡；可下拉切换并点击“刷新网卡”。没有可用地址时不会启动，连接Wi-Fi或网线后再刷新。
3. 确认玩家连接端口，默认8899，可直接修改。首次使用时在窗口填写两遍8–128位初始密码，再点“启动房间”。账号准备在本机完成，已有账号不会被重置。
4. 启动成功后窗口显示可复制的玩家地址，并自动打开主持登录页。点“复制玩家地址”，将地址发给同一局域网的玩家；玩家在浏览器分别登录自己的账号。
5. 保持启动窗口打开，自动裁决还需至少一个已登录KP网页在线。“停止房间”或关闭启动窗口会停止本窗口启动的服务及宿主，保留存档；再次启动继续原房间。

其他玩家只需要浏览器，不必安装Python或本项目。分享窗口中的完整 `http://IP:端口/` 地址，保留 `http://` 和端口；默认提供 `player1`、`player2` 两个玩家账号，每人使用一个。增加玩家时由主机通过已有本机账号工具创建账号，不要让多人共用同一玩家身份。

运行期间锁定网卡和端口，需停止后再修改。端口被占用、IP失效、重复占用同一存档会显示错误，失败时不会显示可分享地址。`runtime/lan-settings.json` 只保存上次成功使用的IP和端口，不保存密码。此GUI也接受可选的 `--data-dir` 与 `--no-browser` 参数，供独立存档和验收使用；日常双击不需要参数。

原命令行方式仍可用：先在本机完成准备，再关闭启动器，以明确的私有IPv4重新启动，例如：

```powershell
powershell -File rulepacks/stumpsville/start.ps1 -Port 8899 -Bind 192.168.1.23
```

参与者访问窗口显示的同一地址，不要把 `127.0.0.1` 发给其他电脑。服务限定 Host/Origin，不能使用 `0.0.0.0` 作为访问地址；网页首次初始化仍仅允许回环来源，GUI直接在本机准备。包不会添加防火墙规则或映射公网端口；此HTTP服务用于可信局域网。若连接失败，检查设备间网络互通、访客Wi-Fi隔离及Windows防火墙所选端口。已在本机真实WLAN地址验证多账号和完整包页面；跨物理设备及实际防火墙环境尚未验收。

### 连接失败与疑似卡死

让朋友重新打开刚复制的完整地址，然后在启动窗口点击“检查连接 / 启动问题”。报告检查当前IP是否仍属于本机、本机游戏HTTP服务、宿主准备状态、所选存档的锁占用，以及Windows网络类别和防火墙启用状态。可以“复制诊断报告”，也可以“打开防火墙设置”自行检查；检查过程不会修改防火墙、结束其他进程或删除存档锁。

| 看到的现象 | 下一步 |
| --- | --- |
| 本机访问失败或IP已失效 | 核对启动错误；必要时停止房间、刷新网卡，选择当前Wi-Fi地址和端口，启动成功后重新复制链接 |
| 提示存档仍被使用 | 从原 `start.cmd` 或局域网窗口停止房间再重试；报告也会说明无法区分的访问权限问题。不要删除锁文件判断是否卡死，锁文件留在磁盘上是正常现象 |
| 本机响应正常，朋友超时，近期未出现朋友的来源IP | 请求可能尚未到达服务；检查地址／端口、Windows当前网络类别对应的游戏程序或TCP端口入站规则，以及路由器／校园／公司／访客Wi-Fi的设备隔离 |
| 能看到朋友打开页面，随后登录失败 | 请求已到达服务，核对账号和密码；玩家尚未成功登录并拉取游戏状态时，不计为在线玩家 |
| 已登录但显示“暂时失联” | 请玩家检查页面、设备休眠及网络；恢复页面轮询后会重新显示在线 |

本机能打开页面不能证明其他设备能访问；同一Wi-Fi名称也不能证明设备互通。防火墙显示“已开启”只表示当前配置启用，不能据此断言它拦截了端口。诊断窗口只读取本窗口管理服务的访问记录，无法读取其他启动器进程的内存记录；服务重启也会清空这些临时记录。更具体的宿主启动错误保存在该存档目录的 `host.log`。

### 房间管理与连线玩家

KP的独立“房间管理”页显示“房间信息与连线玩家”：版本、房间ID及状态、监听IP／端口、启动时间、玩家连接地址和复制按钮。列表按账号合并多个页面，展示身份、角色、在线页面数、来源IP及最后心跳。最近30秒有已登录页面心跳为“在线”，30–120秒为“暂时失联”，超过120秒为“离线”；关闭页面后有延迟，主动退出会立即清除该登录会话的连接记录。

展开“最近访问与连接排查”可看最近8条页面／登录／异常请求，服务内最多保留60条。该记录帮助确认请求是否到达，不等于人数；房间网络详情只向KP提供，玩家页面和KP玩家预览不会收到其他账号的IP列表。0.4.2需要停止原启动器后重新启动并刷新网页，无需重新创建存档。

## 备份与恢复

“场次→创建完整备份”先创建宿主房间备份，再保存包侧快照。返回两个配对对象：

- `runtime/host/backups/<backupId>/`：宿主房间/规则/素材。
- `runtime/package-backups/<行动ID>.json`：`hostBackup.backupId` 和配对的 `package` 快照。

网页备份不包含账号密码散列。恢复需要停止原服务并使用原来的 `runtime/host/identity/`。移动到其他电脑应另用宿主离线 `backup --include-identity`，同时保留对应包侧快照；不要仅拷贝单独的包 JSON。

恢复到一个全新目录，不覆盖原存档。以下路径用实际备份 ID 替换：

```powershell
engineering/.venv/Scripts/python.exe -B engineering/backend/scripts/run.py --data-dir rulepacks/stumpsville/runtime-restored/host restore --bundle rulepacks/stumpsville/runtime/host/backups/<backupId> --identity-dir rulepacks/stumpsville/runtime/host/identity
```

将配对 JSON 的 `package` 对象以 UTF-8 JSON 写入 `runtime-restored/package.json`，然后启动：

```powershell
engineering/.venv/Scripts/python.exe -B rulepacks/stumpsville/tools/launch.py --data-dir rulepacks/stumpsville/runtime-restored --port 8899
```

完整复现程序在 `tests/verify_package.py`，使用独立新目录验证恢复后的角色、手记和回顾。备份不是只导出配置；“资料→导出配置包”只导出可检查的规则/资料，不包含私人场次存档。
