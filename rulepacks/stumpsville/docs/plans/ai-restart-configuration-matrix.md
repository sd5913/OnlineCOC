## 目标与范围

复现重启后会话失效、配置创建和追加失败；验证当前作者契约允许的操作及明确拒绝边界。仅使用 `tests/output/` 隔离存档。真实模型调用使用现有服务商配置的隔离副本，保留正式配置原字节；不写正式房间。

已在工程依赖冻结后接线。下表是覆盖目标；实际通过范围、首次失败和未完成项以本页进度及结果 JSON 为准。

## 实施与证据

1. 包内替身复现恢复拦截；纯数据测试核对稳定编号、三方同步和作者材料。
2. 工程释放后运行公开 HTTP 和浏览器测试，记录首次失败及修复后的结果。
3. 每类支持操作至少安排一个隔离 DeepSeek 场景；负例验证模型反馈及服务端最终拒绝，不要求模型必须生成非法候选。
4. 保存逐例输入、输出类型、检查报告、审批、执行后状态和重启读取结果。原始请求资料只留隔离目录，精选报告不含凭据。

成功率分为：支持操作首次通过／总数、修复后最终通过／总数、负例正确拒绝／负例总数；模型澄清和人工追加提示另计，不能算作原始首轮成功。保留每轮调用次数、确认 Token、失败原因和处理过程，接口成功不等于已发布或实际生效。

## 已确认问题与处理

- 明确 HTTP 拒绝曾被包 transport／队列保留为未知命令，后续写操作被永久拦住。初验 5/11，修复分类及本机 HTTP 状态保留后 15/15；网络、408、5xx 仍查询原回执。见[恢复结果](../../tests/ai-recovery-results.json)。
- 网页固定模块清单漏了 `debug.js`。已补齐并加入依赖顺序检查；真实浏览器 6 组验证通过，含顶部弹窗、1440/390px、正文开关和导出组件。首次会话列表时序及窄屏未切换面板的测试失败均保留，见[浏览器结果](../../tests/ai-recovery-ui-results.json)。
- 原单房间矩阵首次支持 6/13、预期拒绝 5/6，未到达重启验证。物品修改、地图增改在代理 30 秒门限处超时；当时并行运行主模块全量套件，需独立批次串行复测，不能直接归因为产品错误。
- 随后真实出现存储容量问题：AI 目录 158 代快照共 527,106,299 字节，末代 7,019,617 字节；数据管理按“历史占用＋新代两倍”检查默认 536,870,912 字节上限，触发 `STORE_FULL`，公开 HTTP 仅报告 `STORAGE_UNAVAILABLE`。该房间不能继续创建会话。原始证据为 `tests/output/ai-config-matrix-dbe1cfea/`。协调方以 ISSUE-015 完成全历史无损压缩，在该失败目录的隔离副本验证 158 代原字节保留、压缩后续写 12 代及重开成功；见[归档与有效限制](../../../../docs/history/2026-11-20-issue-015-ai-store-growth.md)。原失败报告不回填为成功，完整历史仍会增长。
- 原房间重启历史复验的工程修复见[ISSUE-013归档](../../../../docs/history/2026-11-20-issue-013-ai-session-restart.md)。本包的同档发布与会话继续由分批矩阵分别验证；不将前端重新加载当作宿主重启。

每项支持操作须核对实际数据或规则结果；每项拒绝须说明理由且保持原状态。不宣称 53 类场景全部通过。

## 本轮离线结论

[去重汇总](../../tests/ai-config-matrix-summary.json)覆盖21个目标：支持13/14（92.86%）、预期拒绝7/7（100%），合计20/21。初轮仅到达19个目标，支持6/13、预期拒绝5/6；新增的源删除负例与补完的重启不能算作初轮通过。物品业务7/7、地图批次5/6、规则6/6；重复前置和重启按case ID去重，不相加冒充更多覆盖。

独立重启专项2/2：先发布并实际发放物品，随后两轮回环固定回答，立即关闭／重启原目录，回答仍可读且第三轮继续成功。共3次本机替身调用，0次外部模型调用。第一次物品批次重启断言误比较配置列表排序；已按configurationId比较，地图／规则／独立重启均记录顺序变化而定义一致。

未支持项仍为场景玩家文案修改：A/B通过、C缺覆盖。当前C声明只能将一个实际实体绑定到Lua参数；`sv.scene.resolve`另需scene/world实际ID，而玩家安全措辞由Python知识投影消费。未用无关探针虚构coversData；后续先设计能验证真实包投影及多实体依赖的包侧探针，若公开接口不能承载再提工程ISSUE，并补披露／撤回实测。累计 STORE_FULL 的本次复现已另经无损压缩与失败样本复制验证解决；完整历史的长期容量治理仍有上限，以上配置成功率不包含无限期运行保证。

## 分批复测与真实模型交接

离线入口为 `tests/verify_ai_config_matrix.py --batch npc|items|map|rules|restart`，每批创建独立房间，记录创建／校验／批准耗时并重启原存档；`restart` 在物品发布消费完成后生成两轮回环固定回答，立即同档重启并继续第三轮。`--batch all` 保留原单房间累计压力复现场景，不作为规避存储问题的手段。

真实入口为 `tests/verify_ai_config_live.py`。从项目根目录按顺序执行：

```powershell
engineering/.venv/Scripts/python.exe -B rulepacks/stumpsville/tests/verify_ai_config_live.py --live --batch npc --call-limit 24 --output-root rulepacks/stumpsville/tests/output/ai-live-current
engineering/.venv/Scripts/python.exe -B rulepacks/stumpsville/tests/verify_ai_config_live.py --live --batch items --call-limit 24 --output-root rulepacks/stumpsville/tests/output/ai-live-current
engineering/.venv/Scripts/python.exe -B rulepacks/stumpsville/tests/verify_ai_config_live.py --live --batch map-rules --call-limit 24 --output-root rulepacks/stumpsville/tests/output/ai-live-current
```

前置条件：工程／包依赖稳定占用，已有可运行 Python 环境与启用的 `deepseek-main`，原授权聊天确认真实调用。首次 NPC 试运行在权限设置缺少必填 `allowPlayerChat` 时停止，0 次外部调用；脚本已补齐。随后包会话自动审批未接受跨聊天授权，真实执行交回原授权聊天。主会话已完成真实失败修复与复验；总结果以[统一报告](../../../../engineering/acceptance/ai-runtime/repair-20261120.md)和各批 JSON 为准，不能把包会话当时的 0 次外部调用作为最终次数。

每批最多 24 次真实请求；每例至多两轮人工提示，内部修复至多5次、传输重试0次，均受总调用上限约束。单次外部 HTTP 180秒、任务300秒、轮询320秒。发送类别为包作者指南、公开操作Schema、按授权读取的配置／Lua／游戏定义，以及隔离房间的角色、场景和本次测试对话；不读取正式存档。隔离副本允许 public/KP/private 外发，自动批准关闭，候选经检查后由测试脚本明确批准并验证实际消费。

已准备的真实场景共9项：NPC新增／默认值修改／未使用模板删除；普通物品／武器／普通容器新增并实际发放；地图新增并移动、计算规则新增并预览、稳定物品编号删除请求的拒绝。其余修改／删除由离线矩阵覆盖；真实模型扩展场景仍需后续补测，不混入这9项成功率。

以上交接命令输出到 `tests/output/ai-live-current/ai-config-live-<batch>-<随机值>/` 和 `tests/ai-config-live-<batch>-results.json`；未指定 `--output-root` 时原始目录直接位于 `tests/output/`。前者保留原始工具请求／模型回复、进度及逐例输入、候选、决定与消费；后者保留首次／最终通过、调用、确认Token、失败和历史运行定位。脚本结束校验持久服务商配置原字节未变；发放、移动等仅在隔离房间执行。
