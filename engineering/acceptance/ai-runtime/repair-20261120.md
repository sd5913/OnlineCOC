## 改动与结论

同房间重启后的历史使用只读复验，忽略旧进程标识，继续检查账号、授权、scope、基线和来源；旧批准与待执行批次不因此获得新授权。KP 与 PL 历史、撤权后隐藏和旧批次拒绝均已验证。

对话顶部“引用与调试”打开独立窗口，支持整个会话/单条请求；默认不含正文，关闭、换会话或身份后清理旧结果。1100px 与 390px 真 Edge 验证导出和焦点恢复。A/B/C 失败明确未发布；重试仅恢复原需求，已完成动作保留回执并禁止盲目重放。

真实配置首轮暴露模型调用不存在的配置命令及引用包侧咨询资料的问题。新增宿主权威模板分页读取、枚举操作名、参数错误的有界反馈和明确的来源发布限制；仍保留 A/B/C 与权限检查。连续配置实验触发累计存储配额，已按 ISSUE-015 增加保留每代原字节的压缩，并验证原失败样本的副本可继续写入。

旧首测操作台的裁决查询接线缺失经 ISSUE-014 交引擎侧补齐。真实浏览器重新走通审核、拒绝、导入、修订、风险批准、加载、重连和退出清理。

真实支持操作按每个 case ID 最早尝试计 **4/8（50%）**，最终 **8/8（100%）**；最新各批自身首轮也是 8/8。负例单列 1/1。不是用重试扩大分母，也不表示任意自然语言请求有100%成功率。

全部 6 次真实实验共 **64 次 DeepSeek API 调用、834750 个已确认 Token、21 次需求尝试**；每批上限24次，无注入服务商故障。最新三批为24次调用、313078 Token。首次NPC达到本地实验上限的429是测试限额，不是服务商限流；前置权限字段夹具失败为0次外部调用，另保留在历史运行定位中。费用以账单为准，不作费用估算。

每轮保留输入、候选、A/B/C、决定、消费、错误、调用和原始工具证据。三批精选结果：[NPC](../../../rulepacks/stumpsville/tests/ai-config-live-npc-results.json)、[物品](../../../rulepacks/stumpsville/tests/ai-config-live-items-results.json)、[地图与规则](../../../rulepacks/stumpsville/tests/ai-config-live-map-rules-results.json)；所有历史运行定位及首次/最终计算见[机器汇总](repair-20261120-results.json)。持久服务商配置逐轮字节相同，正式存档未改动。

场景玩家文案修改仍在 C 层被 `LIVE_SCENARIO_COVERAGE_MISSING` 阻止，未发布。当前探针不能证明真实 Python 知识投影和多个实体依赖，后续见[包侧计划](../../../rulepacks/stumpsville/docs/plans/ai-restart-configuration-matrix.md)。规则源删除、物品/地点数组删除与重排、嵌套容量机制不作为已支持能力。危险删除回答提及的“空位”替代建议未经验证，也不计入成功范围；若继续设计须另过作者契约与实际消费检查。

## 失败处理记录

| 失败 | 分类与处理 | 最终状态 |
| --- | --- | --- |
| 同档重启第二轮历史 SOURCE_STALE | 产品缺陷；历史与执行校验分离，保留权限和来源检查 | 已通过 |
| 旧操作台审核提示缺 aiRulings | 产品接线缺陷；补只读查询、引用解析和订阅，保留高危审核 | 已通过 |
| 静态 UI 动态模块加载失败 | 测试夹具 MIME；显式 JS/CSS 类型 | 已通过 |
| 无资料旧文案／宽泛按钮和 details 选择器 | 旧测试失效；按当前具体可见控件断言 | 已通过 |
| 富文本重试值断言错误 | 新测试夹具；按 contenteditable 正文检查，并断言未发命令 | 已通过 |
| 模型虚构配置命令 | 产品工具反馈不足；枚举操作名称，错误在原额度内反馈，模板改用宿主权威读取 | NPC 增改删复验通过 |
| 混入包资料后 CONSULTATION_ONLY | 保留原来源限制，新增模型可见来源提示；新需求使用宿主模板／活动工件 | 配置实际发布通过 |
| 规则请求只返回方案并重复询问 | 模型行为；反馈后成功，进一步明确“生成候选≠批准发布” | 新批次首轮通过 |
| 明确 4xx 拒绝永久挂起包队列 | 包适配错误；保留 HTTP 状态并清理已明确拒绝的标记，未知结果仍查原回执 | 15/15；浏览器 6/6 |
| 累计全量快照 STORE_FULL | 产品存储问题；保留全部历史原字节的压缩，未执行截断历史方案 | 15 项专项和原失败副本续写通过 |
| 场景玩家文案 C 覆盖缺失 | 包探针未覆盖真实 Python 投影及多个实体依赖；保持阻塞，不降低检查 | 未支持，未发布，见包侧后续计划 |

原单房间矩阵在并行测试时出现代理超时，随后串行分批通过；初始超时和累计存储失败均保留，分批通过不替代存储修复证明。

旧回答只有在当前依据仍有效时保留；真实撤权、数据变化和新 scope 仍可能隐藏旧内容。模板删除须无实例引用且经高危审批；规则源文件删除未提供公开操作。模板发布与实际实例创建/发放是不同步骤，不能把“候选生成”记为玩法已生效。

## 使用更新

重启正在运行的房间宿主和本机管理器，再刷新页面。树桩镇网页导出需重建以包含同版通用组件和包适配器。所有验证使用隔离测试存档；未迁移正式房间或开启自动批准。
