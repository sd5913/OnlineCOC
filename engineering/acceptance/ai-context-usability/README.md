本轮检查简单需求反复补充的具体原因，并验证有限改进。原机制仅保留最近 4 个请求，没有语义压缩；应用初始输入上限 96 KiB、累计请求上限 256 KiB，均非 token 数。默认 deepseek-flash 的服务商公布窗口与应用限额不同，检查值及官方来源见 context-before.json；未修改实际 Profile 或模型。

## 已完成

管理员保留最近 0—4 轮完整历史，另从更早的本人手动请求抽取最多 32 条、12 KiB 原文需求，优先原始目标和最近补充，明确遗漏数。取消请求、删会话、权限变化持续复验；历史为 0 时两种携带同时关闭。它不总结模型建议，不证明当前游戏事实，不授予执行权；严格 PL 保持原个人知识规则。

明确配置编辑预读前 5 个模板，单页最多 8 KiB，并附真实分页信息。管理员输入附完整操作名称索引，具体 Schema 仍须查询。默认查询的 roomMode 由服务端控制，防止模型错误地把它附在实体搜索上。当前用户明确选择后，再问同组选项会进入最多两次的既有纠正额度；改变主意仍可重新选择。已复现的错误能力声明有窄范围技术反馈，不能保证任意自然语言均正确。

../ai-chat-isolation/context-first、context-fixed/context-second 保留初次夹具失败；修复使用精确命令参数、当前会话修订和新的调度器实例，未放宽生产校验。context-corrected 为 39/39；technical-feedback-verified 为 53/53，含真实回环 HTTP 与 Edge；inheritance-and-choice 为 23/23，覆盖旧聊天依赖不继承及用户改选。核心初跑为 664/669；5 个失败中两个属于同一 batchId/rulingId 缺陷，三个属于新来源／当前读取规则下的旧夹具假设。修复后精确复验 5/5。原核心使用独立源码快照，最终版本追加定向组合，不宣称单轮全量 669/669；明细见 results.json，以上分母不可相加。

## 真实 DeepSeek 对照

使用独立合成房间，生成不得修改业务数据；可用模板候选再经实际人工审批接口发布并核对完整配置。来源配置保持不变。预算为 20 次、250000 token，账本已封存：实际 **18 次、140825 已确认 token、0 次未知用量**。单次本地测试输出上限为 2200 token，工具最多 4 轮、技术修复最多 2 次、无运输自动重试。

| 指标 | 改前 | 初始改后 |
| --- | --- | --- |
| 严格首轮可用（3 个配对场景） | 2/3 | 2/3 |
| 确定需求的不必要澄清 | 0 | 0 |
| 两项模板候选实际批准并核对 | 2/2 | 2/2 |
| 单次明确模板修改的调用数 | 2 | 1 |
| 同一模板修改的 token | 14084 | 7082 |

原始宽松 oracle 将“加 1 点”只按 clarification 格式判为成功，但原文分别包含未读取归属却作判断、把 entity.patch 子集当成全部数值能力的错误。独立复核将两例降为失败；原结果与输出原样保留，修正见 independent-audit.json。随后增加完整操作名称索引、窄范围纠正和确定性回归，**没有重新调用真实模型验证这两条歧义回复的最终质量**。

最初长轮样例的 bonus=15 同时出现在包指南，不能作为参数保留效果的可靠对照。补充使用未出现在指南的 bonus=13：跨过 4 轮后，1 次调用、7401 token 得到正确候选并实际批准成功（1/1）。没有对应的改前 bonus13 实模试验，不混入配对提升率。样本量很小，不表示全量场景成功率。

## 失败处理与复现

failure-register.json 逐项记录原因、修复、首次证据、复验与剩余限制。技术问题使用原有限修复额度，未知执行按原回执核对；候选审批仍由宿主权限、当前来源和 A/B/C 校验决定。失败或不确定用量不得记为零。

运行 `run_tests.py --label <新名称> --engine engineering/acceptance/engine-chat-interface-snapshot/v2 --core` 可生成隔离树与 JUnit。live_trials.py 和 bounded_provider.py 记录合成模型输入、输出、耗时和 usage；已封存账本拒绝追加调用，不复用旧轮预算。work/ 是忽略入库的隔离宿主和缓存，精选结果及源码摘要在本目录。
