## 真实发布与边界

- 实际 `sv.character` 默认值候选 A/B pass、C `EXTENSION_FORBIDDEN` unknown，经 Edge 卡片“采纳评估并发布”调用真实 Application 和 Host.command，创建的新角色实际 hp/maxHp=5。
- 实际短休规则候选 C `LIVE_SCENARIO_COVERAGE_MISSING` unknown，采纳后发布；固定低骰验证恢复值，并执行宿主规则确认消费。补充 `randomSides:6` 的真实场景后，另一候选 C pass。
- 缺少／伪造采纳证明拒绝；批准后改依据返回 C_BASIS_STALE。C 原始报告没有改成 pass，A/B、作者权限和执行失败仍为硬边界。
- 服务关闭后已批准候选仍可发布；关闭期间依据变化拒绝，仓库锁占用返回明确错误。重新读取持久化依据和访问策略，未缓存或省略核验。

actual-c-publication-* 保留引擎 v2 首次失败和 v3 成功；actual-c-review-before/after.png 是真实网页点击前后。replay-1795194105655650000.json 记录原输出摘要、原调用 ID、实际差异和幂等性。

## 自动回归与失败处理

最终核心 648/648 通过，Edge 组件 4/4 通过；结果见 results.json 和 XML。首轮核心（引擎 v2）635 通过、8 失败，均保留；lifecycle-evidence 首次 36 通过、2 失败，修复后 lifecycle-evidence-fixed 38/38（34 核心、4 Edge），不与最终核心重复相加。最终核心在引擎 v3 与冻结 AI v2 上运行，source manifest 绑定全部实际源码。唯一警告为已有 Starlette/httpx 弃用提示，无测试失败或跳过。

failure-register.json 逐项保留首次现象、处理和状态，包括知识夹具、骰面声明、引擎重复 Approval Schema、短休 oracle、未取证回答、关闭回调、表达匹配、测试路径、预算阻断及额外来源文字。失败处理遵循：保留原请求和回执 → 区分模型／夹具／工程／预算 → 在固定技术次数内修复 → 原候选重放 → 检查真实状态和未触及字段 → 分开报告首次与修复后结果。结果 unknown 不自动换命令 ID 或重放业务。

## 复现与文件

使用工程虚拟环境运行 run_tests.py，传 `--engine ../engine-accounts-interface-snapshot/v3`（按当前工作目录调整路径）；`--core` 运行核心回归。replay_saved.py 不发 API；repair_evidence.py 是明确标注的缩短提示反馈实验，不代表完整生产提示。coordinator_live.py 只有 `--run` 才调用 API，重复执行会继续同一预算台账，封账后不再运行。

work/ 为 Git 忽略的隔离宿主、原始运行状态及源码镜像；文件摘要、XML、JSON 和精选截图入库。new-files.json 交主协调会话同步实际目录清单；document-check.json 核对十一份修改的当前文档链接和冻结代码摘要。其余 AI 主题及开发者参考已检查相关描述，未受影响的不作形式化修改。最终运行 finalize.py 生成统一统计，不改写任何首次实验记录。
