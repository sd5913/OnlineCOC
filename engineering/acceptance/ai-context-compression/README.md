## 长会话与可追溯压缩

助手自行提出 HP=3，用户同意；加入 25 个长背景轮次后，用户更正“建议值 +1”，再加入 5 个轮次。最后按旧方案发布 NPC 模板，随后明确要求按已发布模板创建实例。

- 发布任务输入 446,592→54,224 字节；两个摘要分组各自动修复一次。模型实际回读摘要原文和当前模板，发布 HP/maxHp=4、isNpc=1 的完整定义。
- 创建实例前两次压缩因格式／来源锚点失败而终止，没有执行。修正摘要结构示例、逐字锚点和非逐字引句处理后，输入 448,206→56,534 字节，最终创建一个 HP=4 的实例，没有重新定义或发布模板。
- 确认参数只能来自已核验用户原话；非逐字引句降为 record-locator 并要求回读，不能成为确认依据。摘要不授予执行权。确定性测试覆盖“尚未同意 HP=3”被模型改写成“已批准 HP=30”、跨任务读取拒绝、权限变化和并发缓存落盘。
- 历史保留、摘要分组、回读与应用窗口均有边界；并非无限记忆。归档对象当前没有自动保留期清理。

## 失败、反馈和处置

| 失败 | 影响与处理 | 当前状态 |
| --- | --- | --- |
| 摘要输出字符串数组／错误来源锚点 | 每个分组最多一次自动修复，耗尽后明确失败、保留原文和调用账本；补充 JSON 样例、确认参数逐字锚点、引用降级规则 | 后续真实创建成功；此前失败仍计数 |
| 独立来源未读却声称参考 | [首轮](consultation-1795248177952401900.json) 只读取宿主配置，仍实际发布了测试护盾，且描述多一个句号；不能计作符合指令的成功 | 强化读取前置条件和精确字符串提示，补测实际来源链通过 |
| 物品删除提供“高危例外接受校验失败” | 未生成可执行候选，无业务变化；建议本身错误 | 已加强系统提示，但不以未补测的提示修改宣称消除 |
| 地图 index=99 | [测试输入本身不合法](map-1795248371462053900.json)，稳定编号检查阻断；回复仍说“已追加” | 不计支持场景失败／成功，计质量失败；合法 index=11 补测增改成功 |
| 地图删除仍说“候选待审批” | 校验 blocked，无实际执行；更新提示后仍复现，不能靠 KP 来源接受执行 | 仍有模型措辞问题，交协调会话纳入指令可靠性计划 |
| NPC 说明不准确 | 基准默认字段实际 12；长会话计划写 13、正确候选文字写 11；另一新增回复提出可去掉强制 isNpc 标记 | 实际配置正确，3 条回复仍各计质量失败 |
| 发布结果核验遗漏 isNpc | 原测试预期漏掉作者强制字段，误报配置不同 | 修正 oracle；只读核验完整模板，原报告保留 |
| 创建结果读取 diagnostics 竞态 | 业务已完成且幂等；测试在 finally 持久诊断前读取，误报 KeyError | 测试等待诊断落盘，只读核验原回执与压缩记录 |
| PL needs_input 被测试误判 | strict-known 输入没有未知暗号，输出也没有暗号、候选或名字变更 | 修正合法终态判定；[离线核验](offline-review.json) 通过 |

失败处理顺序：查看任务状态、具体校验错误与原回执→区分技术限制、真实未决问题、模型输出错误和测试 oracle→仅对可修复的技术问题执行有界修复→需要新方案时另建请求→KP 单独批准→核对实际状态和幂等。未知执行不能按未执行盲目重放；不通过高危接受跳过硬限制。

## 复现

在项目根目录、现有 `engineering/.venv` 运行：

```powershell
& engineering/.venv/Scripts/python.exe -X utf8 -B engineering/acceptance/ai-context-compression/run_tests.py --label reproduce-core --engine engineering/acceptance/engine-kp-policy-interface-snapshot/v1 --ai-source engineering/acceptance/ai-compression-interface-snapshot/v3 --core
& engineering/.venv/Scripts/python.exe -X utf8 -B engineering/acceptance/ai-context-compression/review_results.py
```

第一条仅使用冻结代码创建新的 work 树与结果；第二条不调用 API、不修改房间，复核已有报告及本机合成存档（`work/` 不入库；新检出仍可阅读已保存的哈希核验结果）。`--write` 只重写派生统计，不覆盖原报告。

实模入口为 `live_scenarios.py --tree <隔离树> --group <compression|consultation|pl|items|npc|map> --run`。只有需要复现实模且另开实验目录／账本时才运行；本账本已封存。需本机有效的服务凭据，脚本不写出密钥。不存在旧绝对路径时会从当前作者包重建快照，并与记录哈希比较；不一致则停止，避免把变更后的包混入旧实验。

公开配置已迁移 deepseek-main revision 6→7：窗口 1,048,576、输出 8,192、工具回合 12、任务期限 600,000 ms，凭据引用／地址／启用状态和每日配额不变；[迁移记录](profile-migration.json) 不含密钥。其他机器的已有配置须在管理器单独更新；主任务技术修复有效上限仍是两次，摘要每分组最多另修复一次。
