## 本轮范围

宿主变更限于 `publication.py`、`contracts/operations.json`、`contracts/models.json` 及发布文档。KP 咨询来源风险可明确接受；完整上下文摘要、风险理由、原技术检查及当前执行权限继续复验。配置图之外的任意包文件写入没有新增执行能力。

| 条件 | 处理 |
| --- | --- |
| 当前 KP 的咨询来源，已映射为可执行配置候选 | 提供 consultationReview.sourceDigest 和 consultation-source 风险理由后可审批；保留咨询标记 |
| 严格玩家或玩家会话上下文 | 拒绝直接升级为管理员执行上下文；PL 可见信息仍由原知识/来源校验限制 |
| A/B 技术检查失败、Lua 执行错误、结构不合法 | 仍拒绝，须修正后重新验证 |
| 当前权限、来源证明、世界/配置/规则基线失效 | 仍拒绝，不能用风险接受覆盖 |
| 删除被引用配置、悬空规则绑定或规则依赖环 | 仍拒绝，保护最终配置图 |
| 高危配置或可采纳 C 风险 | 继续使用原高危摘要和 C 采纳流程；咨询确认可以同时存在 |
| 不支持的包存储、未知操作或跨仓库原子组合 | 不生成成功回执；需使用已经实现的真实目标端口 |

宿主已支持配置 add/replace/remove、Lua/数据工件发布；运行时实例、关系、进度等通过现有 Host 操作或受支持原子批次处理。配置发布不会自动迁移旧实例，包文件同步不属于该宿主原子提交。

## 证据和复现

正式契约最终检查 41/41 通过：17 项咨询风险专项，24 项既有发布回归。包含 KP 接受后发布和幂等、确认缺失/过短/过期、发布时确认与权限/世界基线复验、严格玩家拒绝、技术失败拒绝、未知存储目标拒绝，以及宿主/AI 风险评估的一致性。

`prepare.py` 从已有 engine-chat v2、ai-chat v2 只读快照构造隔离镜像，并覆盖当前已登记的宿主代码及两份宿主契约。开发首轮曾为冻结 AI 契约增加可选审批字段；最终使用 AI 方正式 `ai-compression-interface-snapshot/contracts-v1/` 契约和咨询评估函数，单独验证宿主与 AI 的摘要、去重计数及评估结果一致。

`first-field-error.xml` 保留首次来源字段误写造成的 14 个失败及 1 个通过；对应源码摘要在 `first-source.json`。该问题已经按真实 ContextSnapshot 修正，随后协议统一为完整 context 摘要。`parameter-expectation.xml` 和 `fixed.xml` 是同一次中间运行的两份记录：39 项通过，短理由在前置 Schema 校验被拒绝，测试误以为返回拒绝回执。最终 `official.xml` 使用正式 AI 契约，记录 17 项专项及 24 项现有发布回归；`results.json` 汇总最终结果与来源，`new-files.json` 供协调线程维护目录索引。

全部测试使用合成房间、实际宿主事务与真实 Lua A/B/C 夹具；未修改正式房间、账号或 API 配置。本模块外部 API 调用为 0；上下文压缩与实模测试由 AI 模块单独记录。本轮不进行 Git 操作。
