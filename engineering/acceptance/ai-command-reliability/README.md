## 完整流程、注入与历史响应重放

以下实验不能合并为一个“成功率”：

- **自然完整流程**：实际Coordinator、真实DeepSeek、作者严格包、隔离Host。修复前slot5失败；加入作者声明的库存引用投影后，slot5和移到slot7的目标相同变体最终 **2/2** 正确生成、独立批准、扣减一格、通知正确玩家且幂等。slot7中间一次预算阻断保留，最终另建任务完成。证据见[slot5与阻断](coordinator-1795183647247512600.json)、[slot7完成](coordinator-1795184194107020600.json)。最终正文也与执行参数一致。
- **首轮完整配置流程**：替换、删除均经过A/B/C、批准、发布和幂等。物品追加实际发布成功，严格断言因描述多一个中文句号失败；独立全文复核确认仅该标点差异，所有旧物品、顺序和无关字段均保留。真正缺少属性选择的请求正确返回needs_input，首轮验收脚本误要求review_ready；这两项复核均保留原失败。见[原始7场景](coordinator-1795183044989840600.json)和[独立复核](followup-verification.json)。
- **显式故障注入**：在真实模型响应之后注入错槽位3或工具额外字段，原始HTTP响应与注入内容分别保存。工具错参被自动纠正；移槽候选也修为slot7/value1，但正文仍误称该槽不是口粮，因此该轮整体保留失败，不能用动作正确掩盖说明错误。
- **历史失败首响应重放→生产校验→真实模型修复**：复用原始失败输出，不额外花一次API重造错误，不向模型提供测试预期答案。NPC固定标记缺失经真实B/C精确反馈，1次真实调用修正后发布；裁定mode错误经真实预检及当前规则/依赖源码，1次真实调用修正后整批提交。Lua在补充DSL语法反馈后1次修到正确构造器，A/B通过；原夹具含作者场景未覆盖的bag-one，C保持unknown。独立正确最小初态中零API重放同一修正候选，A/B/C、发布、实际调用及幂等通过。见各[saved-repair记录](saved-repair-1795183760607024700.json)、[Lua作者检查](lua-author-check.json)与[实际消费复验](followup-verification.json)。

实际消费复验5/5通过：新增／替换模板创建出的实例数值正确；删除后不能再据该模板创建；Lua发布后可实际调用；严格包新增物品定义可实际授予、消耗且不重复扣减。新增物品第一次消费夹具漏建角色到会话的source关系，拒绝记录保留，独立补齐正确初态后通过。它们是零API的模型输出执行复验，不计入自然首轮正确率。

最终[Lua语法修复记录](saved-repair-1795184015563359400.json)与[裁定参数修复记录](saved-repair-1795184146769813400.json)单独保存；前者保留作者场景覆盖阻塞，后续最小初态发布证据在消费复验中。

## 首轮失败与处理

初始71次探索探测缺少部分真实对象、流程、引用、规则前置状态和指南注入，其原始40/71语义通过率仅供排错。随后9次输入尚未补齐原子范围的调用单列为valid-v2；完整71例为valid-v3。它们不是同输入A/B对照。源输入、判定器纠错、错误夹具以及修复后结果均保留，详见[setup-attempts.json](setup-attempts.json)、[baseline-reassessment.json](baseline-reassessment.json)。

生产处理流程：保存原始任务与诊断；按权限、业务歧义、技术参数、来源变化、执行未知分类；技术问题共用最多2次修复，使用真实Schema、预检和已授权发送快照；无法修复保留阻塞及原因。权限不提升，业务目标/代价/效果不代选；正常游戏失败不当成技术错误。来源变化按当前依赖校验处理，批准绑定不可变候选；未知执行只查原命令回执，不另发新命令。

剩余边界：单个样例不能证明任意提示100%正确。短休首轮仍出现不必要反问；成员停用额外附带了不合法来源通知，已被校验阻止，本轮未消耗更多API复测该类。模型说明可能与动作矛盾，必须保留逐项参数、预检、实际结果及原始文本供审核。作者场景不足不会被自动补造或绕过；混合存储、flow.*和member.add不在当前原子执行范围内。

## 用量、回归与复现

API已停止。累计登记 **199次**，有明确响应 **198次**；已知用量 **1,556,280 tokens**。第194次因Windows账本文件占用留下started且无usage，保留 **44,218 tokens** 的全额预留，保守总计 **1,600,498 tokens**，低于批准硬限200次／1,750,000 tokens。账本写入增加了有界文件占用重试；不将该次当成成功或零费用。全部输入为合成隔离数据，正式房间／凭据配置未修改。

当前收集到的 **626个唯一核心用例**均有最近一次通过证据，另有批次详情桌面／窄屏2/2。全量首轮602/608，剩余6项是漏复制CLI脚本与旧历史可读策略断言，修正后相关46/46；后续变更按影响范围回归，重复运行不增加分母。最后Coordinator／裁决／数据编辑51/51、投影输入边界15/15。并非在最后一个源码版本重新运行了一遍全部626项，详见[regression-coverage.json](regression-coverage.json)与原始XML。

`valid_cases.py`生成独立初态；`valid_live.py --run`是直接生成；`coordinator_live.py --run`是完整流程；`repair_saved.py`复用历史首响应；`replay_outputs.py`和`verify_followups.py`不调用模型。真实调用均经`bounded_provider.py`同一累计账本、单并发、最多2次技术修复与2次传输重试。再次运行真实脚本仍受现有累计预算限制，不能靠新建账本重置额度。
