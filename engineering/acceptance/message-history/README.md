## 真实 DeepSeek 实验

运行 [live_experiments.py](live_experiments.py) 前需明确授权。本轮已获授权，配置只读取副本，调用上限 16 次、总 token 上限 200,000、每任务最多 4 次。使用隔离 fixture 宿主，凭据仅经既有 Vault 在调用时读取，不写入报告。

| 场景 | 结果 |
| --- | --- |
| 玩家原回复→模拟旧仓库→撤回引用→新查询 | 通过：旧原文留存，缺失时间仍为空；后续任务不引用撤回证据 |
| 同改名需求显式补充→批准运行批次→独立新需求 | 通过：完整实际回执触发前驱归档；独立请求保持不同关联 |

场景 **2/2（100%）**，4 个模型任务，共 **10 次 provider calls、51,510 tokens**，请求及返回模型均为 `deepseek-flash`。本轮无真实模型失败；原配置文件内容保持不变。逐调用计量、任务状态、断言结果见 [live-results.json](live-results.json)。此小样本不代表任意剧情或全部配置操作的模型成功率；配置增删改既有记录继续保留在此前验收中。

每次真实模型网络等待期间并发请求公共 ASGI HTTP 的 tasks、rulings、view，**30/30 HTTP 200**，最大 **0.0894 秒**，未观察到等待模型时长持锁。该实验覆盖应用/宿主锁等待，不包含正式本机代理与 TCP 路径，不能据此宣称已经确认旧 OSError 的底层根因。

## 复验与边界

使用工程既有 Python 环境，pytest 加 `-B -p no:cacheprovider`，`--basetemp` 指向新的 `work/` 子目录；XML 输出使用新文件名。`work/` 是忽略的隔离宿主、浏览器及日志目录，禁止改用正式存档。更新实验结果后运行 `record_results.py` 重建摘要，新增轮次需显式加入其 ORDER。

新消息凭证、旧最终回复迁移只支持历史展示，不能授权详情查询或执行。完成凭证当前覆盖 AI 运行批次；包业务成功、配置发布及 accepted 不被猜测为目的达成。未知或部分成功必须核对原命令，不更换 ID 重做。用户截图中的本机连接问题由包/工程会话联合追查，包侧联合结果不冒充本模块独立测试。
