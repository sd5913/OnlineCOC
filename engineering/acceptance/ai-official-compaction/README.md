# 官方压缩机制适配与长对话对照（ISSUE-024）

2026-11-21。当前行为见[会话权限与语义压缩](../../../docs/current/engineering/ai-session-access.md#语义压缩与原文定位)。本轮是在 ISSUE-023 基础上的增量，配置增删改、审批、重启和权限的既有证据仍见[前轮验收](../ai-context-compression/README.md)，不能把这里的三个长对话情景当成所有操作的成功率。

## 实现和来源

参照 DeepSeek 官方 Harness 的固定提交 `2e39e70496aa02986ca6a820c5d497e816b69d7e`，在现有 Python 编排中实现压力阈值、旧工具文本裁剪、完整交换保留、单任务滚动检查点和明确输入窗口超限时的一次恢复。[来源与查阅日期](official-sources.json)区分官方说明和社区复现。没有安装 Harness 插件，没有新增服务端 `/compact` 接口，也没有迁移 Responses 协议。

本项目仍以完整 messages/tools 的 UTF-8 字节保守计量，受 768 KiB 应用上限约束；未把字节当成精确 token。模型窗口较小时缩小余量。裁剪只作用于安全文本叶子，保留数字、引用、结构；editRef、Schema、校验错误、最新及不完整工具交换不裁剪或摘要。早期短用户原文优先于大段背景保留，原顺序不变，不把短句确认升级成执行批准。

滚动检查点仅覆盖同一生成任务；跨用户轮次仍受原有历史捕获上限约束，只复用相同且重新授权的摘要分组缓存。原始记录、来源核验、PL 边界、调用预算、未知用量预留及人工审批继续适用。

## 真实 DeepSeek 配对条件

两版使用相同模型、工具、公开测试包和合成房间。为在有限输入中触发压缩，**仅实验内**将声明窗口设为 131,072 token，生产 Profile 未改。摘要与业务调用都经过实际服务商，计入同一独立预算；助手先前“建议 HP3”的文本是通过离线 provider 建立有效历史的**种子夹具**，不是一次真实生成成功，外部种子调用为零。

同一长对话依次验证：

1. 助手建议 HP3，用户同意，插入大量无新增参数的背景，用户更正为已同意数值加1；生成 HP4 草稿，经实际三检、显式测试批准和发布。
2. 用户撤回旧新增目标，改成新目标 HP7；发布新模板，原模板、其他配置、规则、数据及实体保持不变。
3. 用户撤回继续新增；仅确认停止，不产出候选、不写业务状态。

每项生成阶段先验证业务状态未变；前两项再通过真实批准路径验证发布及幂等回执。语义断言在测试批准后核对，所以 v1 的错误 HP5 曾发布到其**隔离合成房间**；没有写入正式游戏存档。统计绑定 fixture 与包文件摘要，旧版和新版不共享运行目录。

v1 把“HP3 同意后加1”生成成 HP5：旧短确认进入摘要，助手方案仍在原文，模型误取当前模板默认值4作为起点。保留初跑证据后修正短用户原文的保留优先级，再以同一夹具从头复测。v2 首项摘要发生一次 `COMPRESSION_INVALID`，在既定一次修复内恢复；后两项命中相同授权摘要分组，无新摘要 HTTP 调用。原始账本包括被拒摘要，没有隐去该次调用。

包侧随后发现确定性变体：末条历史背景超出预算时，v2 仍强留该行。v3 要求所有早期历史行都能放入剩余预算，放不下的原文进入摘要；当前请求仍单独保留。该变更不改变上述实模样本的选择：三项最后历史行分别仅 167／161／161 字节，而对应剩余预算为 17,157／16,308／15,350 字节。[分支证据](tail-selection-proof.json)依据封存输入和诊断计算，无新增 API 调用；不将这项离线证明冒充 v3 重新实模运行。

v2 首项请求由 280,796 字节降至 61,860 字节，保留近期原文 13,387 字节。该组实模没有触发工具文本裁剪，也没有收到真实服务商输入窗口超限；这两种机制仅由确定性注入测试验证。v1 的 afterPruneBytes 错误标记了抽取后大小，不用于推断裁剪收益；v2 区分两项。

本组 v2 比基线总 token 少 13.68%，摘要 token 少 31.86%；业务 token 反而略高，因为保留更多原文。端到端仅少 1.96%，首项还因摘要修复而更慢。每版只有一组对照，不能据此推断一般准确率、所有长对话的性能或真实异常恢复成功率。

[封存账本](live-ledger.json) 共 **23 次、413,419 token**，均有服务商 usage，无未知用量；未突破 [30 次／500,000 token 的实验自限](budget.json)。保留全部实模尝试共 6/7 通过（85.71%）；这包含两个实现版本与旧版对照，不是最终版本可靠性的统计估计。实模复测 v2 单次三情景为 3/3。机器统计及证据 SHA256 见 [comparison.json](comparison.json)，可用 `summarize.py` 重算。

## 失败反馈与恢复

用户任务失败保留错误码和诊断，原文档案不删除；只在服务商明确输入窗口超限时自动压缩并尝试一次，必须实际缩小。再次超限、受保护材料无法缩小、摘要修复失败或期限／额度不足时结束并反馈，不无限重试。普通请求无效和输出截断沿用独立错误处理。未知用量保留全额预留，未知执行先查原回执，不能换 ID 重做。

生成成功、校验通过和执行成功分别记录。语义不符的候选不能凭格式正确当成任务成功；应检查完整候选差异，修正后重新生成、三检和批准。本轮的“先批准再断言”只为验证隔离环境的完整链路，不适合作为正式房间的自动验收操作。
