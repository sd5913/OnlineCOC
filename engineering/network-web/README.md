# 网页联机

玩家使用浏览器，房主运行本机游戏宿主。平台分为创建房间、房间管理、加入房间三页；加入页展示公开且在线的房间，也支持 8 位代号和“最近加入”快捷返回。点击“进入游戏”才打开独立游戏页、连接房主并获取资源。

## 玩家

1. 打开房主提供的 HTTPS 网址，注册或登录；密码只要求至少 6 位，不要求字符组合。注册时保存一次性显示的恢复码。
2. 在“加入房间”选择公开房间，或输入私密房间的代号；按要求提供密码/邀请，或等待审批。
3. 查看包信息、规则和人员，点击“进入游戏”。关闭大厅或房间页不会关闭游戏。
4. 点击“连接房主”，用房主提供的**宿主游戏账号**登录。平台账号与游戏账号目前分开。

平台登录和游戏登录均可选“记住账密”，默认不勾选。成功验证后在访问者当前浏览器本地保存，下次自动填入；退出账号仍保留记忆，取消勾选或点击“清除已记账密”即可删除。游戏账密按平台账号和房间分别保存。模块不上传或跨设备同步这份记忆；本机保存的是可回填的明文账密，不包含恢复码。

当前测试入口使用原测试 CA；玩家须先通过可信渠道取得并信任 `network-p2p/local/test-ca.pem` 公钥证书。没有可信证书时不属于“干净电脑直接打开即可游玩”。无需安装 Python 或下载游戏客户端；不需要任何私钥、发布令牌或 SSH 信息。

## 房主

树桩镇可使用包内 [start-web.cmd](../../rulepacks/stumpsville/start-web.cmd)，包侧启动见[说明](../../rulepacks/stumpsville/docs/current/web.md)。平台 0.3.0 新增开房串导入；旧版房主页面仍可使用创建页中的“兼容旧版房主入口”。下列通用命令默认导出首测规则桌面。

先启动现有宿主、准备玩家游戏账号。以下命令在项目根目录执行：

```powershell
$py = 'engineering/network-p2p/.venv/Scripts/python.exe'
& $py -m pip install --no-deps -e engineering/network-p2p -e engineering/network-web
& $py engineering/network-web/scripts/configure_host.py --upstream http://127.0.0.1:8765
& engineering/network-web/start.ps1
```

生成器复用本机已有的目录/CA/发布凭据，默认导出配套“首测规则桌面”；省略 `--upstream` 时要求恰好发现一个本机已注册宿主。`--source` 可选其他已适配包，`--approval` 开启首次审批。已有配置不会覆盖；之后直接运行 `start.ps1`，或用 `-Config` 指定配置。

打开 `local/room/web-entry.json`，复制 `creationString`，或在配置包管理页点击其提供的复制按钮。在平台 **“创建房间”** 粘贴，选择是否公开、是否设置密码，点击创建；“解析开房信息”可预览包名和版本。默认不公开、无密码。开房串仅供房主认领，十分钟有效、一次使用；过期可由包重新生成或重启适配器。

创建后进入 **“房间管理”**，可调整公开/密码、审批、移除、黑名单及资源授权。把普通 `roomCode` 发给玩家，勿分享开房串。公开且在线的房间进入 **“加入房间”** 列表；私密房间仍可凭代号进入。密码变更针对首次加入，已有成员保留快捷重入。旧房间升级后默认保持私密。

配置包调用方法与独立联网管理页建议见[接入契约](../../docs/current/engineering/network-web.md#32-开房串与配置包管理页)。

临时关闭适配器保留代号、成员和快捷入口；永久解散后此身份不能再次发布，新房间须使用新 `statePath`。同一身份的资源版本固定，更新游戏包须开新房。停止本模块不停止宿主或 LAN/AI 等其他模块。

## 接入限制

- 版本1样例为 `examples/core-table/`；树桩镇0.8.0另有版本2玩家发行包，支持完整场景、行动、线索与聊天，已通过本地双浏览器联测，新桥已部署云端。网页AI未接入。
- 包用 `web.json` 明确声明资源组、玩家 HTML、所需模块和 API 白名单。启动组为 `startup`；其他组由包通过桥接口按需加载。
- 首期桌面 Chromium/Chrome/Edge；一个平台账号在同一房间只允许一个游戏席位。异常关闭后最多约 35 秒回收。
- 新网页入口与旧 P2P 客户端是不同房间身份；不要把两种远程入口发布到同一游戏宿主并期待自动合并人数和准入。
- 版本2必须声明包服务与存储白名单，显式绑定本机服务及包版本，远程只接受玩家游戏角色；原始宿主白名单保持不变。`host --stop-file <路径>` 提供本机优雅停止，保留借用宿主。

协议、部署文件、端口、备份及测试见[工程说明](../../docs/current/engineering/network-web.md)。
