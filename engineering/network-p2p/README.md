# 公网联机快速使用

完整项目部署到 Windows x64 设备，可先用[联机依赖安装 EXE](../network-web/dist/OnlineCOC-Network-Setup.exe)离线安装运行时，详见[安装说明](../network-web/installer/README.md)。仅用浏览器加入网页房间无需安装。

云端负责房间发现与中转，房主运行游戏并保存存档。当前 0.2.3 保留短房间码、本机宿主识别和双击启动；[验证范围](../../docs/current/engineering/network-p2p.md#6-验收及实用边界)。需要玩家仅使用浏览器时，选择独立的 [network-web 网页入口](../network-web/README.md)。

## 安装与首次准备

完整项目的 Windows x64 房主先运行 `engineering/network-web/dist/OnlineCOC-Network-Setup.exe`，选择 **OnlineCOC 项目根目录**，完成安装与验证后再运行本目录 `play.cmd`。EXE 不随 Git 跟踪，新检出须另行取得发布产物或按说明构建。安装器只准备联机依赖；游戏宿主、目录服务器和房主发布凭据仍需准备。离线安装、正在运行导致安装失败及重新安装的步骤以[安装器说明](../network-web/installer/README.md)为准。

使用旧 P2P 玩家 ZIP 时，先安装 Python 3.14 x64（含 `py` 启动器），将 ZIP 完整解压，双击 `play.cmd` 自动安装依赖。首次需要联网。完整项目离线安装器与这个源码 ZIP 是两种安装路径，不能把 ZIP 描述为免 Python 客户端。

从源码新检出、尚无私有配置时，按[配置示例](config/client.example.json)准备 `local/client-config.json`，填写维护者提供的目录地址、CA 和房主发布凭据。不要使用示例中的占位值开房；玩家使用生成的 ZIP，不需要发布凭据。服务器部署和玩家内容导出见[工程说明](../../docs/current/engineering/network-p2p.md#2-配置与分发)。

## 房主开房

1. 用原启动器启动游戏宿主，再双击本目录的 [play.cmd](play.cmd)。
2. 打开“我的房间”，从“本机已运行房间”选择宿主；刚启动的房间可点“刷新本机房间”。未识别到时，在“连接设置”填写宿主地址。
3. 设置房间名称、公开/私有、密码和审批，点击“发布房间”。自动生成 **8 位房间码**，例如 `ABCD-EFGH`。
4. 点击“复制加入信息”发给玩家，并提供[玩家 ZIP](dist/onlinecoc-player.zip)、游戏账号及所设的房间密码。

公开房间可直接凭短码加入；私有房间的完整加入信息已包含邀请，玩家粘贴一次即可。短码不区分大小写，允许省略连字符；原完整房间 ID 仍可用。短码只定位房间，密码、邀请、审批及游戏登录仍按设置执行。

联测时保持游戏宿主和联机进程运行。停止联机只撤下分享，原宿主继续运行。同一联网入口一次分享一个宿主，识别列表不会启动未运行的存档或自动发布房间。

## 玩家快速加入

准备 **Windows x64、Python 3.14、Chrome/Edge**，取得房主提供的 ZIP、加入信息和游戏账号。客户端已带服务器地址及测试 CA，无需腾讯云账号、SSH 密钥或自行配置服务器。

1. 将 ZIP 完整解压到独立目录，双击 `play.cmd`。首次自动安装依赖，需要联网；以后直接打开页面。
2. 在“房间码 / 加入信息”粘贴房主发来的内容，按需填写房间密码，点“连接房主”，等待审批（如启用）。
3. 登录游戏账号，点“下载并进入”。
4. 看见“已进入房间”后，在基础聊天的 `general` 频道发送一条测试消息，确认显示 `status: committed`；让房主或另一玩家在支持聊天历史的游戏界面确认收到。房主提供的游戏页面可能有自己的交互入口。

房间密码用于房间准入，游戏账号密码由原游戏宿主管理；两者分别填写。缺少对应玩家内容时，“下载并进入”从房主获取并校验当前清单；已校验的相同内容可复用缓存。房主更新内容须重新导出、配置并发布，玩家重新登录检查后下载，不支持正在运行的房间自动换包。

本文的旧 P2P 方式需要本机客户端，不能用浏览器直接访问房主回环网址；可选的 [network-web](../network-web/README.md) 使用云端网页且要求包显式兼容。更新到新版后请重开联网进程；旧入口玩家使用新 ZIP。

## 常见问题

- **没有识别到本机房间**：只读取当前 Windows 用户的宿主注册记录及已配置地址；先启动宿主再刷新，旧版/自定义入口可手填地址。
- **安装失败后重试**：离线运行时用同一个安装器重试。源码/旧 ZIP 安装需先确认 `py -3.14 --version` 正常，再在客户端目录执行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1`，成功后双击 `play.cmd`。首次 pip 中断可能留下 `.venv`，此时 `play.cmd` 不会自动补装缺失依赖，必须显式重跑 `setup.ps1`。不要把该源码修复命令用于离线安装器管理的嵌入式运行时。
- **缺少本机配置**：依赖安装不生成有效的服务器凭据；按上文准备配置，或使用房主生成的完整玩家 ZIP。不要把房主的 `local/` 整目录交给玩家。
- **房间不可加入 / `ROOM_UNAVAILABLE`**：确认房主在线；私房须粘贴完整加入信息，再核对房间密码。修改后再次点“连接房主”；反复失败可能触发限流，应稍后再试。
- **`AUTH_FAILED` 或游戏账号密码错误**：已经连到房主，但游戏登录被拒绝；向房主确认游戏账号，在当前登录框重新输入后点击“登录并检查内容”。当前真实宿主错误码尚未映射成中文提示。
- **连接超时或断线**：确认目录与中继服务可用，可勾选“仅使用中继连接”重试。旧 P2P 入口断线后需重新加入，不承诺自动恢复未确认的操作。
- **下载失败或 `CONTENT_CHANGED`**：保持房主在线、修复网络后重试“下载并进入”；若主机内容变化，先离开再重新加入、登录检查。系统只提交完整校验通过的内容。不要手动把下载文件覆盖到房主存档。
- **只有状态和基础聊天**：未配置玩家内容时，这是内置入口。树桩镇旧 P2P 入口仅基础状态/聊天；完整地图、行动和专用页面使用已适配的 [network-web](../network-web/README.md)。

## 本轮验证与部署前提

2026-11-26 本机回归 46 项通过、8 项云端专项跳过；新增真实宿主验收分别通过 P2P 浏览器首次加入和 LAN 首次交互。P2P 验证了私房隐藏、两类密码失败后重试、玩家包下载显示、第二账号读取聊天、缓存命中零重复下载，以及停止分享不停止宿主。复测脚本及摘要见[本轮记录](acceptance/2026-11-26-firstplay.json)。本轮使用现有开发运行时，没有重装共享运行时；离线 EXE 由[网页模块专项](../network-web/installer/README.md)单独验收。

本轮目录、房主和玩家都在同一电脑，未访问云端。历史记录中有 [Windows 房主 ↔ Ubuntu CVM 玩家](acceptance/2026-11-13.json)的自动直连及强制 TURN 证据，但没有两名真人分别处于家庭/移动网络的验收。公网使用还需已部署的 HTTPS/WSS 目录、STUN/TURN、有效发布凭据、客户端可验证的 CA/证书及相应端口放行；本地安装成功不等于这些条件已满足。

配置、玩家包生成、内容导出、运维和复测见[工程说明](../../docs/current/engineering/network-p2p.md)。本机私密资料见[local 说明](local/README.md)，只向玩家分发生成的 ZIP。
